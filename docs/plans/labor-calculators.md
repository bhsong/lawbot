## 적용 범위와 근거

두 세금 계산기와 같은 웹앱 진입점을 사용한다. 지원 계산기는 순수 함수로 두고 입력·출처, 계산 단계·근거 조문, 결과를 기존 SSE와 계산 카드로 반환한다. 결과나 적용 여부가 바뀌는 필수 입력을 먼저 확인한다. 합산할 부가 금액·시간 등 생략이 0을 뜻하는 선택 입력만 0과 `미입력(0)`을 표시한다. 질문에 해당 값이 있는데 추출되지 않았거나 조건이 모호하면 안내한다. 금액, 날짜, 기간, 근로시간, 출근율, 적용 사실은 질문의 원문 구간으로 받고 코드에서 검증한다. 연차 결과에는 일 단위를 명시하고, 주휴·가산의 시간 단계에는 시간 단위를 표시한다. 기존 세금 계산의 원 단위 계약과 결론 검사는 유지한다.

## PR1 회귀와 지연

1. 라우터 프롬프트는 사용자가 준 값으로 산출하는 질문과 법정 값·기한을 그대로 찾는 질문을 구분한다. 새 계산기와 유사한 범위 밖 질문의 경계를 짧게 명시한다. CR077을 포함한 기존 조회 6건을 보호한다. 문항 ID, 원문 문장, 금액의 존재만으로 조회를 재분류하는 규칙은 사용하지 않는다.
2. PR1의 고정 val 100문항과 판정 기준을 보존한다. **승인된 판정 방식**은 평가 전용 PR1 계산기 목록에서 CR041·043·048·050·052·057 모두 `none/unsupported_question`을 요구하고, 전체 목록을 쓰는 실제 PR2 경로에서는 CR041(퇴직금 월급 가정)과 CR043(표준 최저임금 월 환산)을 계산, CR050(연차)을 필수 입력 안내로 판정하는 것이다. CR048·052·057은 전체 목록에서도 미지원이다. 기존 CR042·045는 전체 목록에서 각 노동 계산기의 필수 입력 안내를 확인한다. 평가 도구에서 두 목록을 요청별로 사용하고 앱의 기본 목록은 일곱 계산기로 둔다.
3. 모든 금액 필드의 원문 후보를 완전한 구간의 시작·끝으로 만든다. 필드마다 서로 겹치지 않는 후보를 배정할 수 있을 때 계산한다. 첫 등장만 고르는 방식으로 배정할 수 있는 질문을 거부하지 않도록 한다. CR092의 `700만원`/`700만`, 위치가 다른 같은 금액, 다른 금액의 내부 구간, 조합에 따라 배정이 가능한 사례를 시험한다. 구간이 부족하면 `guidance/ambiguous_input`이다.
4. CR023·030·088의 보존된 1차 원출력을 재생한다. 세금 귀속연도는 원문과 고정 평가일에서 코드가 결정한다. 모델이 덧붙인 귀속연도는 계산 입력에 사용하지 않는다. 실제 원문의 지원 밖·복수 귀속연도와 나머지 금액 구간 검증은 유지한다. CR023·030의 결과는 0원, CR088은 총급여 확인 안내다. 같은 세 판정을 실제 모델 평가에서도 확인한다.
5. CR092의 보존 원출력과 겹치는 변형을 먼저 재생한다. 실제 모델 평가에서 모호한 입력 10/10, CR092 안내, 독립 검산과 불일치한 금액·일수 0건을 확인한다.
6. 지연은 요청 시작→라우터 호출·완료, 원문 검증·계산→계산 카드, 검색·리랭킹, 생성 호출→첫 토큰, 요청 시작→첫 모델 글자, 전체 시간으로 나눠 측정한다. 라우터 입력 길이·응답 사용 토큰을 기존 API가 제공하는 범위에서 기록하고, API에 내부 대기·생성 시간이 없으면 라우터 왕복으로 기록한다. 라우터 카탈로그와 중복 설명을 줄이고 코드가 찾을 수 있는 세금 귀속연도 필드를 줄인다. 출력 상한은 가장 긴 합성 원출력이 들어가는지 확인한 뒤 줄일 수 있으며 상한 단축 자체를 지연 개선으로 집계하지 않는다. 게이트 밖 비계산의 호출 수와 프롬프트 바이트는 PR1과 동일해야 한다. 라우터 요청을 더하지 않고 검색 후보·임계값·토큰 상한과 공유 서버 설정을 유지한다.

## PR #120 재리뷰 회귀

- 퇴직금 월급 추정에서 계속근로기간이 명확히 1년 미만이면 기존 자격 미충족 0원 경로를 사용한다. 6개월·11개월·364일과 12개월 경계를 시험한다. [근로자퇴직급여 보장법 제4조](https://law.go.kr/LSW/lsLawLinkInfo.do?chrClsCd=010202&lsJoLnkSeq=1015967243)

## 승인 후 실제 모델 평가

PR 검증 표의 실제 라우터 평가·실제 E2E·모델 스모크는 최초 `실행 안 함`으로 적는다. PR과 CI 확인 후 사용자에게 명령·시간·메모리 영향·요청 상한을 다시 제시하고 별도 승인받는다. 아래는 구현할 평가 명령이다. 개발 CSV만 사용하고 요청 로그·캐시·DB 쓰기를 끈다. 시작·종료 때 설정·조문·프롬프트 해시, 모델 식별자와 revision, 공유 서버 준비와 상주 상태를 기록한다. Pro·임베딩·리랭커가 모두 상주하고 서버 동시 생성 상한이 1일 때만 실행한다. 06:20–06:50 KST를 피해 동시 요청 1개, 재시도 0회로 진행한다. 운영 중단이나 추가 모델 적재는 필요 없다.

```sh
LAWBOT_ENV_FILE="$dev_env" uv run --locked python -m lawbot_tools.eval_calc_router --suite labor-pr2 --live --output /private/tmp/lawbot-labor-pr2-eval.json
```

라우터 직접 238회(100 + 18 + 120), 답변 비교 13쌍의 라우터 13·생성 26·임베딩 최대 52·리랭킹 최대 52회, 인덱스 준비 최대 2회를 합쳐 추론 POST 최대 **383회**다. 준비·모델 목록 조회는 별도다. PR1 190회 약 23분을 바탕으로 **40–60분**을 예상한다. 13쌍은 PR1 표본 8건과 노동 계산기별 대표 1건(CR041 포함)이며 적용·기존 RAG 순서를 번갈아 사용한다. 실제 모델 평가가 통과해야 CR092·원문 누락·지연의 실측 완료를 보고한다. 이 상한은 품질 평가에 해당한다. 실제 모델 E2E와 모델 스모크를 실행하게 될 때는 별도로 범위·명령·상한을 산정하고 승인받는다.

2026-11-12에 사용자 승인으로 1회 실행했다. 383회 요청으로 종료했고, 사전 문항군 및 지연 기준에 미달했다. [실행 기록과 원문](../evals/2026-11-12-labor-calculators-live.md)

## 캐시와 v5.6.0 반영 절차
