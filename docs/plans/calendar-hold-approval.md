# 관리자 캘린더 보류 승인과 정기 가져오기

2026-11-10 KST · `feat/calendar-hold-approval` · 기준 `91e5c0d` (초기 `cda1b33`)

## 보류 검토

- 관리 화면에 시행일 보류와 국회 입법예고의 검토 양식을 연다. 시행일 양식은 기존 `review_template`의 현재 스냅숏, 공식 근거, 조문 전후 원문을 제공한다. 시행일·공포일·근거·요약과 확인 표시를 제출하면 CLI의 `review`로 처리한다. 입법예고는 공식 상세와 수집 날짜를 확인하고 CLI의 `review_assembly`로 승인·반려·철회한다.
- 캘린더 서버와 웹앱의 각 `.env`에 `LAWBOT_CALENDAR_ADMIN_TOKEN`을 설정한다. 캘린더는 비공개 관리자 경로에서 Bearer 토큰을 상수 시간 비교로 확인한다. 미설정 시 관리자 검토 쓰기를 비활성화한다. 기존 공개 GET 응답은 유지한다.
- 웹앱 프록시는 허용 경로만 호출하며 POST에는 관리자 세션, 같은 Origin, JSON 본문과 멱등 키를 요구한다. 로그인한 관리자 식별자를 reviewer로 채우고 성공 결과와 식별자 위주의 감사 기록을 저장한다. 캘린더는 같은 관리자·스냅숏·검토 내용의 재전송을 기존 이력으로 확인한다. 이후 새 결정이 저장됐다면 재전송이 그 결정을 덮어쓰지 않는다.
- 저장 후 보류 목록과 캘린더를 갱신한다. 검증 실패 시 항목과 이유를 표시하고 입력은 유지한다.

## 정기 가져오기

- monitor 등록의 event_id가 법령 등록 또는 국회 스냅숏에 있으면 JSON 경로를 열기 전에 건너뛰고 소스의 기존 `unchanged` 집계에 포함한다. 미등록·실패 입력을 재시도하고 #106의 동일 revision 비교와 #107의 수집 범위 제한을 보존한다.
- 기존 캘린더 가져오기 실행 기록에 국회 실패의 소스·이벤트 ID·예외 종류·비밀값을 제외한 메시지를 저장한다. 관리 화면에서 최근 실패를 페이지별로 읽는다.

## 검증과 반영

1. 토큰과 프록시 제한, 오래된 스냅숏 거부, 정상 저장과 재요청, 기존 JSON의 삭제·모델 변경 및 실패 재시도를 먼저 테스트로 재현한다.
2. 합성 데이터와 임시 DB로 Chromium 390px·1280px에서 관리자 로그인부터 오류 확인, 승인, 목록과 캘린더 반영까지 검증한다.
3. 기본 테스트 전체와 린트·포맷·타입·스키마·두 프런트엔드 빌드를 확인한 뒤 PR을 연다. 실제 모델 E2E, 모델 스모크, 품질 평가는 실행 안 함으로 기록한다.
4. 운영 트리와 DB에 접속하지 않는다. 저장소의 운영 태그를 기준으로 적용 차이를 확인해 PR에 토큰 입력, 재시작, 빌드, DB 마이그레이션 유무를 기록한다. 기능 추가이므로 운영 반영 후 버전의 Y를 올린다.
