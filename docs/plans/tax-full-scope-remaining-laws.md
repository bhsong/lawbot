## 지금 레포와 다른 안내 (2026-11-11 확인)

사용자 안내문은 예전 레포 기준이다. 지금 레포 기준으로 다음처럼 처리한다.

- **형식 맞추기:** CSV 본문을 기존 CSV에 합치지 않는다. 생성기(`lawbot-build-articles`)가 legalize-kr에서 다시 만들므로 article_id·chapter·본문 표기·열은 기존 조문과 같다. 사용자 CSV는 조문 ID 대조에만 쓴다. `<개정 …>`·`<신설 …>` 제거도 기존 생성기·프롬프트 규칙을 그대로 쓴다.
- **기존 데이터의 삭제 조문 6개**(소득세법 제13조·제23조·제49조·제148조의3·제159조, 지방세법 제102조의8): 6개 모두 활성 코퍼스에 없다. 소득세법 5개는 조문 CSV에 `deleted=1`로 있고, 지방세법 제102조의8은 범위에 없었다. `qa_tax_v5`에서 이 조문이 정답인 질문과 `confusable_with`로 가리키는 질문은 0건이다. 뺄 데이터가 없다.
- **긴 조문:** v5의 임베딩 최대 토큰은 법률 4,352, 하위법령 5,120(emb-v5b 학습값)이고 리랭커는 2,560에서 자른다(안내문의 3,072는 v4 값). 규칙은 #111과 같이 잘림 허용이다. `lawbot-max-seq --training-max-seq 5120`으로 잘리는 조문 목록을 기록한다. 항 단위 분할 색인은 v6 재학습 때 검토한다.
- **제목 없는 조문 5개:** 본문도 없는 조문이며 생성기가 뺀다(위 범위 참고).
- **삭제 조문:** 생성기는 삭제 조문을 `deleted=1`로 두고 검색 문서에서 뺀다. 질문 생성도 비삭제 조문만 쓴다.

## 방법

1. **범위 바꾸기 (모델 호출 없음):** 7개 법령의 행을 `data/v5/scope_tax.csv`에서 뺀다. #108 이후 생성기는 `scope_tax.csv`에 없는 등록 법령을 `law_scope.json`의 `decrees`대로 전체 조문으로 만든다. 법령별 예외 목록을 넣지 않는다.
2. **대조:** 생성된 7개 법령 비삭제 조문 ID = 기존 118행 ∪ 사용자 B CSV 비삭제(본문 빈 4개 제외)인지 확인한다. 차이는 조문별로 원인(원문 버전 차이, 생성기 규칙 등)을 적어 보고한다. 한도를 넘는 조문 목록과 서식 이름만 나열한 조문 목록도 낸다.
3. **기존 val 검색 평가 (별도 승인 후).** 신규 B만 실행하고 신규 A 평가의 변경 수치를 기준으로 쓴다. [실행 계획](#3단계-신규-b-검색-평가)
4. **배포 판단:** 하락이 11-11 신규A 수준(리랭킹 R@3 1%p 이내)이면 재학습 없이 v5.y로 배포를 제안한다. 크면 v6 재학습까지 배포하지 않는다. 사용자가 정한다.
5. **질문 생성 (다른 세션):** 신규A+B 비삭제·본문 있는 조문으로 기존 방식대로 질문·정답을 만든다. 서식 이름만 나열한 조문(소득세법 시행규칙 제100~103조 등)은 질문 수를 줄이고 검색 문서로만 둘 수 있다. 분할은 `lawbot-qa-split`(random_state 42)이고 test는 학습·설정 선택에 쓰지 않는다.
6. **v6 재학습과 평가:** 기존 val과 새 조문 질문의 Recall@1/3/10을 나눠서, 법령별로 보고한다. 3단계에서 신규 B 조문이 정답보다 앞선 문항을 하드 네거티브 후보로 검토한다. 5,120토큰을 넘는 긴 조문의 항 단위 분할도 이때 검토한다.

## 3단계 신규 B 검색 평가

기준 코퍼스는 1,859조문이다. `0eac5af`의 법률 CSV SHA-256 `d1ca15fd0debb2ea546baf2bfc94665afb65eb6a096fe3522091d486b7e763b1`과 통합 CSV SHA-256 `ca0f258c8091f222c1cd7e2e1945eeefcdc409ddcd2dff05fc2687a41c60f299`는 11-11 신규 A 평가의 변경 코퍼스와 같다. 해당 기록의 문항군별 변경 수치를 기준값으로 쓰고 기준 코퍼스 추론은 생략한다. [11-11 신규 A 평가](../evals/2026-11-11-v5-income-tax-eval.md)

신규 B 코퍼스 3,795조문으로만 같은 고정 val 3,606문항을 실행한다. 법률 정답 1,977개(노동 1,110 · 세금·보험 867)와 하위법령 정답 1,629개(노동 444 · 세금·보험 1,185)를 각각 검색한다. 시작 전에 고정 val의 질문 ID와 정답이 새 코퍼스에 있는지 확인한다. Recall@1/3/10, MRR@10, 리랭킹 R@3과 하위법령 첨부율·평균 첨부 수를 문항군별·법령별로 낸다. 신규 A 문항군 표에 있는 지표만 기준 대비 차이를 계산한다.

시작과 종료 때 각 구간에서 다음 값이 11-11 기록과 같은지 확인하고 기록한다. 하나라도 다르면 기준 비교는 무효로 표시한다.

3단계 실행 코드는 `798ccea1427e80ac1ce85d96d4fdf8f16c2f0d9f`으로 고정한다. 해당 커밋을 체크아웃한 개발 환경에서 실행한다. `retrieval`은 `rank_all`의 상위 10개 ID를 `emb_top10`에, 실제 리랭킹 상위 10개 ID를 `rr_top10`에 기록한다. 첨부는 기존 `dec_attached` 열에 남는다. `decree-retrieval`은 `decree_candidates` 열에 `article_id`·`emb_rank`·`rr_rank`를 담은 JSON 배열을 리랭킹 순서로 기록하고 기존 `attached` 열에 첨부 ID를 남긴다. 새 형식으로 처음 실행할 때는 새 tag를 사용한다. 가짜 검색 결과로 기록을 검증했고, 후보 기록에 추가 추론은 없다.

문항별 기준 순위가 없으므로 신규 B의 비삭제 ID 중 `0eac5af`에 없던 ID를 사용해 ‘신규 B 조문이 정답보다 앞선 문항’을 뽑는다. 임베딩과 리랭킹 단계에는 정답 앞에 선 신규 B ID와 순위를 적는다. 리랭킹 후보에 정답이 없으면 정답의 리랭킹 순위를 추정하지 않는다. 하위법령 첨부 단계에서는 정답보다 먼저 첨부된 신규 B ID와 정답 미첨부 상태에서 첨부된 신규 B ID를 기록한다. 문항 ID, 정답 조문 ID, 신규 B 조문 ID와 단계별 순위를 v6 재학습용 하드 네거티브 후보로 남긴다.

아래 명령은 별도 사용자 승인 후 실행한다. 평가 구간은 두 검색 단계의 경계에서 나눈다. 06:20 KST 전에 진행 중인 구간을 종료하고 06:50 이후 이어간다. 중단했다면 같은 tag의 완료 문항 기록을 사용하고 구간별 실제 요청 수를 기록한다.
