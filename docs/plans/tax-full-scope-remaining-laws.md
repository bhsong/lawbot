## 지금 레포와 다른 안내 (2026-11-11 확인)

사용자 안내문은 예전 레포 기준이다. 지금 레포 기준으로 다음처럼 처리한다.

- **형식 맞추기:** CSV 본문을 기존 CSV에 합치지 않는다. 생성기(`lawbot-build-articles`)가 legalize-kr에서 다시 만들므로 article_id·chapter·본문 표기·열은 기존 조문과 같다. 사용자 CSV는 조문 ID 대조에만 쓴다. `<개정 …>`·`<신설 …>` 제거도 기존 생성기·프롬프트 규칙을 그대로 쓴다.
- **기존 데이터의 삭제 조문 6개**(소득세법 제13조·제23조·제49조·제148조의3·제159조, 지방세법 제102조의8): 6개 모두 활성 코퍼스에 없다. 소득세법 5개는 조문 CSV에 `deleted=1`로 있고, 지방세법 제102조의8은 범위에 없었다. `qa_tax_v5`에서 이 조문이 정답인 질문과 `confusable_with`로 가리키는 질문은 0건이다. 뺄 데이터가 없다.
- **긴 조문:** v5의 임베딩 최대 토큰은 법률 4,352, 하위법령 5,120(emb-v5b 학습값)이고 리랭커는 2,560에서 자른다(안내문의 3,072는 v4 값). 규칙은 #111과 같이 잘림 허용이다. `lawbot-max-seq --training-max-seq 5120`으로 잘리는 조문 목록을 기록한다. 항 단위 분할 색인은 v6 재학습 때 검토한다.
- **제목 없는 조문 5개:** 본문도 없는 조문이며 생성기가 뺀다(위 범위 참고).
- **삭제 조문:** 생성기는 삭제 조문을 `deleted=1`로 두고 검색 문서에서 뺀다. 질문 생성도 비삭제 조문만 쓴다.

## 방법

1. **범위 바꾸기 (모델 호출 없음):** 7개 법령의 행을 `data/v5/scope_tax.csv`에서 뺀다. #108 이후 생성기는 `scope_tax.csv`에 없는 등록 법령을 `law_scope.json`의 `decrees`대로 전체 조문으로 만든다. 법령별 예외 목록을 넣지 않는다.
2. **대조:** 생성된 7개 법령 비삭제 조문 ID = 기존 118행 ∪ 사용자 B CSV 비삭제(본문 빈 4개 제외)인지 확인한다. 차이는 조문별로 원인(원문 버전 차이, 생성기 규칙 등)을 적어 보고한다. 한도를 넘는 조문 목록과 서식 이름만 나열한 조문 목록도 낸다.
3. **기존 val 검색 평가 (승인 후, 계산기 평가와 겹치지 않게):** emb-v5b로 기존 val의 Recall@1/3/10·MRR@10, 리랭킹 R@3, 하위법령 첨부를 기준 코퍼스와 비교한다. 노동·세금 문항군별, 법령별로 낸다. 요청 수와 예상 시간은 실행 전에 알린다. 06:20–06:50을 피한다.
4. **배포 판단:** 하락이 11-11 신규A 수준(리랭킹 R@3 1%p 이내)이면 재학습 없이 v5.y로 배포를 제안한다. 크면 v6 재학습까지 배포하지 않는다. 사용자가 정한다.
5. **질문 생성 (다른 세션):** 신규A+B 비삭제·본문 있는 조문으로 기존 방식대로 질문·정답을 만든다. 서식 이름만 나열한 조문(소득세법 시행규칙 제100~103조 등)은 질문 수를 줄이고 검색 문서로만 둘 수 있다. 분할은 `lawbot-qa-split`(random_state 42)이고 test는 학습·설정 선택에 쓰지 않는다.
6. **v6 재학습과 평가:** 기존 val과 새 조문 질문의 Recall@1/3/10을 나눠서, 법령별로 보고한다. 11-11 평가에서 신규 조문 때문에 순위가 떨어진 val 54문항(노동 법률 1·세금 법률 18·노동 하위법령 6·세금 하위법령 29, [기록](../evals/2026-11-11-v5-income-tax-eval.md))을 하드 네거티브 후보로 검토한다. 5,120토큰을 넘는 긴 조문의 항 단위 분할도 이때 검토한다.

## 버전과 영향

- 재학습 없이 넣으면 y, 재학습하면 v6.0.0.
- 정확 일치 캐시: 7개 법령에 기대는 승인 답변은 반영 시 승인 대기·꺼짐으로 바뀐다. 계산기(소득세법 조문 해시)는 영향이 없다.
- 시맨틱 캐시(계획 4)는 이 작업 뒤의 조문 release·임베딩에 맞춰 만든다.
- 운영 반영은 06:30 자동 갱신과 같은 경로(`lawbot-articles-update --restart`)로 하며, 새 조문 약 1,939개의 임베딩 계산이 공유 모델 서버에 부하를 준다. 시간을 정해 실행한다.
