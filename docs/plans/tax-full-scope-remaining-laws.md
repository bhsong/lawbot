## 방법 (요약)

1. **범위 바꾸기:** #108 이후 생성기는 `scope_tax.csv`에 없는 등록 법령을 `law_scope.json`의 `decrees`대로 전체 조문으로 만든다. 그래서 해당 법령의 행을 `scope_tax.csv`에서 빼면 전체 조문이 된다. 사용자 CSV의 본문·커밋 열은 쓰지 않는다(본문은 생성기가 legalize-kr에서 조문별로 만든다).
2. **대조:** 전체 생성 결과의 조문 ID가 `scope_tax.csv` 기존 행 ∪ 사용자 CSV(삭제 제외)와 같은지 확인한다. 다르면 원인을 보고한다.
3. **질문 데이터:** 새 조문에 대한 val·학습 질문이 없다. 질문 생성과 검수를 먼저 한다(test 셋은 설정 선택에 쓰지 않는다).
4. **평가:** 기존 val 질문의 검색 Recall이 얼마나 떨어지는지 emb-v5b로 먼저 잰다(실제 모델 평가는 요청 수를 알리고 승인 후). 떨어지면 임베딩 재학습을 우선한다(리랭크 후보 수 늘리기보다 지연이 적다).
5. **버전:** 재학습하면 v6.0.0, 재학습 없이 넣으면 y.
6. **영향:** 정확 일치 캐시는 해당 법령에 기대는 답변이 승인 대기·꺼짐으로 바뀐다. 계산기는 근거 조문 해시가 바뀌면 꺼진다. 시맨틱 캐시(계획 4)는 이 작업 뒤의 조문 release·임베딩에 맞춰 만든다.
7. **운영:** 새 조문의 임베딩 계산이 공유 모델 서버에 부하를 준다. 06:20–06:50을 피하고 시간을 정해 실행한다.
