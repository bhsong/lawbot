## 2. 범위와 하지 않는 것

- 노동 7개 법률과 그 하위법령은 지금처럼 문서 전체를 넣는다. 세금·보험 25개 문서는 **범위 목록에 있는 조문만** 넣는다.
- 모델 서버, 모델(임베딩·리랭커·답변), 화면은 바꾸지 않는다. 임베딩 재학습은 이번 범위가 아니다(4단계 평가 결과를 보고 따로 정한다).
- 별표·서식(간이세액표 등)은 지금처럼 넣지 않는다. 근로소득 간이세액표는 소득세법 시행령 별표라 데이터에 없다.
- 긴 조문 나누기(청크)는 하지 않는다. 목록 중앙값 548자, 3,000자 넘는 조문 43개(v4는 1개). 리랭커 입력 상한(2,560토큰)에서 잘리는 영향은 4단계에서 잰다.

## 3. 단계

### 1단계 (PR 1): 생성기 일반화 — 데이터는 바꾸지 않음

진행 (2026-11-03): 구현 완료, 결과는 [evals/2026-11-03-v5-generator.md](../evals/2026-11-03-v5-generator.md). 계획과 달라진 점:
- 규칙 3(날짜 없는 시행일) 두 건은 날짜가 없는 게 아니라 생성기가 '1년 6개월'과 다른 개정법률의 조문을 못 읽은 것이라 규칙으로 고쳤다. 타법개정 부칙·'개정규정' 없는 호 형식도 같이 고쳤다
- 시행 전 개정과 뒤 개정이 한 조문에서 겹치는 경우(11개 조문, 범위 안 6개)는 최신 본문에 주의 표시를 붙인다 (사용자 결정)
- 노동 결과는 바이트 동일이 아니라 1칸 다르다: 근로자퇴직급여 보장법 제1조 `effective_date`가 전부개정 시행일(2012-07-26)로
- 부칙 특례 규칙은 모든 문서에 켰다 (PR #54 검토 뒤 사용자 결정). 노동 데이터에 근로자퇴직급여 보장법 부칙<제21475호>제2조 1행이 늘었다
- 조문 끝 `[주의: …]` 문구와 `부칙<제N호>제M조` 표기는 사용자가 이대로 쓰기로 했다. 인용 판정이 `법령명 제N조`만 세는 문제는 3단계에서 본다

목표: 25개 문서가 모두 같은 규칙으로 조합되고, 노동 21개 문서 결과는 바이트 단위로 그대로.

규칙 추가 (모든 문서에 똑같이 적용, 조문별 예외 목록 없음):

1. **마지막 전부개정(또는 제정)부터 조합한다** (실패 A). 커밋 제목이 `(전부개정)`·`(제정)`·`(폐지제정)`인 버전 중 공포일 ≤ 기준일인 마지막 버전을 시작점으로 삼는다. 전부개정은 본문 전체를 새로 쓰므로 그 앞 버전의 조문은 이어지지 않는다. 소득세법은 1994-12-22, 지방세법은 2010-03-31부터가 된다. 노동 문서에서 시작점이 바뀌어도 결과가 같은지 확인한다.
2. **'다만' 번호 목록을 읽는다** (실패 B). `N. <대상>의 개정규정: <날짜>` 형식의 각 호를 조문·장별 시행일로 읽는다. 대상 중 별표·서식은 데이터에 없으므로 무시한다.
3. **날짜 없는 시행일** (실패 C): 두 건의 부칙 원문을 먼저 보고 규칙을 정한다. 원문만으로 날짜를 정할 수 없으면 규칙을 만들지 않고 데이터 변경(사용자 확인 항목)으로 보고한다.
4. **부칙 특례 조문을 넣는다.** 다음을 모두 만족하는 부칙 조문을 행으로 넣는다.
   - 본문에 `제N조…의 개정규정에도 불구하고` 또는 `제N조…에도 불구하고`로 같은 문서의 본칙 조문을 가리킨다.
   - 본문의 기한(`YYYY년까지`, `YYYY년 M월 D일까지`) 중 가장 늦은 날 ≥ 기준일이다.
   - 그 부칙의 개정이 기준일에 시행 중이다.
   - 범위 목록이 있는 문서에서는 가리키는 본칙 조문이 범위 안에 있다.
   - 행: `article_id` = `<문서명> 부칙<제N호> 제M조`, `related_ids`에 가리키는 본칙 조문.
   - 2026-11-03 시험 결과 3건이다: 국민연금법 <제20903호> 제4조(2026~2032 연금보험료율), 소득세법 <제21548호> 제2조(자녀세액공제 연령 기준 2026~2029), 국민연금법 <제11143호> 제7조(농어업인 보험료 지원). 같은 규칙의 다른 후보 6건은 범위 밖 본칙을 가리키거나 부칙이 시행 전이라 빠진다.
   - 노동 21개 문서에서 걸리는 부칙이 있으면 v4 결과가 바뀌므로, 몇 건인지 보고하고 노동 문서에 이 규칙을 켤지 사용자에게 확인한다.
5. **대상 문서를 설정으로.** `LAWS` 상수 대신 문서 목록 파일(법령명, 종류, 범위 목록 경로 또는 '전체')을 읽는다. 기본값은 지금 7개 법률이라 v4 명령과 자동 갱신(`lawbot-articles-update`)은 그대로 돈다.

테스트 (TDD, 원문 조각으로 만든 작은 가짜 저장소):
- 단위: 전부개정 시작점, 번호 목록 시행일, 부칙 특례 포함·제외(기한 지남, 부칙 시행 전, 범위 밖 본칙), 범위 목록 필터, 삭제 조문 제외
- 회귀: 같은 HEAD·기준일로 노동 21개 문서를 바꾸기 전·후 생성기로 만들어 바이트 비교 (`--check`)
- 확인(테스트 아님, 기록만): 25개 문서가 실패 없이 조합되고 1절 표의 차이가 조합 본문 쪽으로 나오는지

완료 기준: 기본 테스트 전체 Green·린트 통과, 노동 결과 바이트 동일, 25개 문서 조합 성공(또는 C의 남은 건을 사용자 확인 항목으로 보고).

- `data/v5/scope_tax.csv`: 사용자 목록에서 삭제 조문 6개를 빼고 `law`(머리말 문서명), `kind`, `article_no`, `priority`, `선택근거`만 둔다. 커밋·글자 수 열은 생성기가 정하므로 두지 않는다.

- 행 순서: v4 문서 순서를 그대로 두고 세금·보험 문서를 뒤에 붙인다(노동 조문 임베딩·`data/decree_exp` 후보 번호 유지).

- 테스트: 범위 목록의 조문이 모두 들어가고, 목록 밖 조문은 없고, 노동 행은 v4 생성 결과와 같다.

### 3단계 (PR 3): 웹앱 구성과 평가셋

- 개발 `.env`만 v5 CSV를 가리키게 한다. 운영 `.env`·`data/live`는 건드리지 않는다.
- system 프롬프트: 지금 "대한민국 노동법 상담 도우미"라서 세금 질문을 거절할 수 있다. 범위를 "노동법과 근로소득 원천징수·4대보험"으로 넓힌 후보를 만들고 val로만 고른다.
- 평가셋: 세금·보험 질문 평가셋이 없다. **만드는 방법은 이 단계 시작 전에 사용자와 정한다**(아래 확인할 것 1).
- 범위 밖 평가: `oos_eval.csv`의 소득세법 2문항(OOS073 월세 세액공제, OOS074 3.3% 환급)과 고용보험법 4문항은 범위가 일부만 들어오므로, 정답 조문이 범위 목록에 있는 문항만 범위 안으로 옮긴다(지금 `eval_v4`의 출처 법령 기준 재분류는 문서 일부만 들어온 법에 맞지 않음).

### 4단계: 실제 모델 평가 (승인 후)

- val로 검색 Recall(임베딩·리랭킹), 하위법령 첨부, 인용 정확도, 범위 밖 거절률을 v4 기준선과 비교한다. 노동 질문 지표가 떨어지는지 반드시 본다(세금 조문이 노동 질문 후보를 밀어낼 수 있음).
- 요청 수·예상 시간·운영 영향을 먼저 알리고 승인받는다. 결과는 `docs/evals/`에 기록한다.

### 5단계: 운영 반영 (별도 요청 시)
