# ERP 기관 소식 게시판별 최신 10개

## 목표

캘린더 ERP 자료의 기관 소식(고용노동부·재정경제부·국세청)은 지금 기관 전체에서 최신 10개만 보여 준다. 매일 올라오는 공지·보도자료가 10칸을 차지해 고시·공고, 입법·행정예고, 법령·세무 자료가 보이지 않는다. 게시판마다 최신 10개를 보여 준다.

수집은 이미 게시판별로 되고 자동 승인되어 있으므로 수집기는 바꾸지 않는다.

## 사용자 결정 (2026-11-17)

- 게시판마다 최신 10개. 공지·보도자료 개수 축소는 화면을 써 본 뒤 따로 요청한다.
- 게시판 순서: 고시·공고, 입법·행정예고, 법령·세무 자료를 위에, 공지·보도자료를 아래에 둔다.
- 게시일이 없는 글은 원래 게시판 목록 순서를 그대로 쓴다.
- 에이전트(Claude)가 브랜치·PR을 만들고, 사용자 승인 후 병합과 운영 반영까지 한다.

## 규칙

1. 게시판 순서는 `sources.yaml`의 `category_tags`에서 정한다. 하나의 규칙을 모든 게시판에 적용한다.
   - 1순위: `고시`·`법령`·`행정규칙` 중 하나가 있는 게시판
   - 3순위: 그 밖에 `공지`·`보도자료` 중 하나가 있는 게시판
   - 2순위: 나머지
   - 같은 순위 안에서는 `sources.yaml` 순서
2. 게시판 안의 글 순서
   - 게시일이 있으면 게시일 최신순, 게시일이 없는 글은 뒤
   - 같은 게시일이거나 게시일이 없으면 원래 게시판 목록 순서: 처음 본 수집 실행이 최근인 글이 먼저, 같은 실행 안에서는 목록에 나온 순서
3. 공개 스냅샷은 기관당 10개 상한을 게시판당 10개로 바꾼다. API `limit`(1~10, 기본 10)도 게시판당 개수로 해석한다.
4. 화면은 게시판별 묶음으로 보여 준다(스냅샷의 게시판 순서).

## 변경

- `packages/lawbot-common/.../erp_news.py`: `latest()` 안정 정렬·게시판별 상한, 스냅샷 검증을 게시판당 10개로
- `services/source-hub/.../news.py`: 승인 자료를 목록 순서로 반환, 게시판 순위 정렬
- `services/law-calendar/.../news.py`: 게시판당 `limit`
- `services/law-calendar/frontend/src/erp/AgencyNews.tsx`: 게시판별 묶음 표시

## 완료 기준

- 단위: 게시판별 상한, 게시일 없는 글의 목록 순서 유지, 게시판 순위, API `limit` 게시판당 적용
- 대역 E2E: 캘린더 ERP 화면에서 게시판 제목과 게시판별 글 표시
- 기본 pytest 전체, ruff, pyright, 프론트 빌드 통과

## 운영 반영

웹앱·모델 서버는 바꾸지 않는다. 운영 트리 checkout 후 캘린더 프론트 빌드와 캘린더 재시작, source-hub `daily --republish`(수집 없이 공개 스냅샷만 재발행)로 새 규칙을 적용한다.
