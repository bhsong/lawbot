# 정확 일치 캐시 릴리스 판정과 관리자 검토 계획

2026-11-09 · 개발 기준 `c87dbff` · `feat/exact-cache-carry-forward`

## 범위와 완료 기준

P07 승인 질문만 유지한다. DB 코퍼스의 활성화와 롤백에서 이전 승인 범위와 새 스냅샷을 대조한다. 유지 답변은 모델 호출 없이 반환하고, 검토 대기·끔·철회는 RAG로 보낸다. 기존 관리자 탭과 접근 제어를 확장해 판정 조회·재승인·철회·모드 전환을 지원한다. 시맨틱 캐시, 답변 생성 및 정정 편집, 운영 반영, 실제 모델 검증은 이번 작업의 범위 밖이다. [이전 구현 계획](../archives/exact-cache-p07.md)

## 구현 결정

- 판정은 코퍼스 DB의 조문 원본 행과 승인 시점의 릴리스를 사용한다. 표시·검토 의존 조문의 법령명·조문 번호·제목·종류·본문·삭제 값을 모두 비교한다. 직접 변경이 있으면 끔, 같은 법령의 다른 조문 변경은 검토 대기다. 정책·보호 지문이 달라졌거나 번들이 없으면 승인 답변을 모두 검토 대기로 두고, 조문 차이는 비교 화면에 남긴다.
- 기존 DB는 최종 표시본과 원문 해시만 보관한다. P07 원본은 고정 해시의 ZIP에서 복원하고 답변 원문 해시를 재검증한다. 앞으로 검증된 원문을 별도 저장해 CLI 정정 리비전도 재렌더링할 수 있게 한다. 원문을 확인할 수 없는 이전 리비전은 검토 대기로 두고 화면에 표시한다. 새 표시본이 이전 표시본과 바이트 단위로 같아야 자동 유지한다.
- 캐시 전용 스키마를 추가 마이그레이션한다. 판정은 활성화 이벤트와 답변별로 남기고, 새 리비전에는 원본 출처·직전 리비전을 보존한다. 현재 카탈로그의 상태를 기준으로 질문 연결을 한 트랜잭션으로 바꾼다. 롤백에서 예전 namespace를 다시 사용해도 철회나 미승인 상태를 과거 승인으로 덮어쓰지 않는다. 이전 전환에서 검토 대기 또는 끔 상태였던 항목은 명시적 재승인까지 미적중으로 유지한다. 모드와 유효기간을 유지한다.
- DB 조문 갱신기가 활성화·복구를 기록한 직후, 웹앱 재시작 전에 판정한다. 캐시 미설정 시 건너뛰고, 캐시만 실패하면 기존 제어 행을 보존한다. 보고서와 표준 출력에 판정 건수를 넣고 monitor가 읽는 마지막 줄 및 종료 코드를 유지한다.
- 관리자 API는 기존 인증·Origin·요청 제한·멱등 키 계약을 적용한다. 캐시 쓰기와 멱등 응답을 같은 트랜잭션에 넣고 `generation`을 검사한다. 승인할 표시본과 보호 지문·활성 릴리스를 다시 확인하고 철회한 질문은 제외한다. 번들이 없으면 재승인과 캐시 활성화 변경을 막고 조회·철회·`off`를 허용한다. CLI의 추가 보호셋과 일치 여부를 확인할 수 없으면 CLI에서 재승인하도록 안내한다.
- 표시 정책에는 `DISPLAY_VERSION`을 명시적으로 포함한다. 고정 입력 렌더 스냅샷을 버전에 연결해 표시 결과 변경 시 갱신한다. 기존 지문에서 전환하는 첫 릴리스는 새 정책으로 취급하며, 운영 문서에 기존 캐시의 재판정 순서를 적는다.

## 순서와 검증

1. 비교 규칙·렌더 스냅샷·캐시 DB 트랜잭션을 TDD로 구현한다. 직접·간접 변경과 지문·원문 실패, 재시도·철회 보존을 합성 데이터에서 확인한다.
2. 가짜 Git과 모델 대역으로 새 릴리스, 자동 복구 및 수동 롤백의 호출 순서를 검증한다. 캐시 오류 시 조문 릴리스와 마지막 줄 계약을 확인한다.
3. 기존 관리자 라우터와 프런트엔드에 목록·상세·변경 비교·감사·상태 변경을 연결한다. 미인증·일반 계정·Origin·세대·사유·멱등·보호 분할을 API 테스트로 검증한다.
4. Chromium 390px·1280px에서 검토 대기, 조문 비교, 재승인, 캐시 적중 및 `off` 후 RAG를 검증한다. 전체 기본 테스트, 린트·타입 검사·두 프런트엔드 빌드를 실행한다.
5. 운영 문서·설정 예시·평가 기록을 갱신하고 `main` 대상 PR을 만든다. 운영 전환과 병합은 별도다.

## PR #101 리뷰 반영

- 릴리스 판정에서는 마지막 승인 보호 지문을 유지한다. 관리 화면의 보호 지문이 이 값과 다르면 활성 질문 수와 무관하게 재승인을 막는다. 기존 지문만으로 추가 CSV 사용 여부를 구별하기 어려우므로, 원래 보호 범위를 검증할 수 있는 CLI에서 명시적으로 승인 묶음을 갱신한다.
- 신규 초안은 `off`에서 승인하고 `shadow`를 거친다. 검토 대기 답변을 `shadow`나 `on`에서 재승인할 때는 이전에 승인된 질문만 활성화한다. `on`에서 재승인 버튼과 함께 즉시 사용자에게 반환된다는 안내를 표시한다.
- 캐시 설정이 있을 때 번들 미설정·파일 부재를 배포 점검과 시작 로그에 표시한다. 릴리스 이동에 포함되지 않는 미승인 초안은 운영 문서에 `seed` 재실행으로 안내한다.
