## 목표

모바일에서 날짜를 탭하면 스크롤하지 않고 그날 시행 조문과 세무일정을 바로 볼 수 있다.

## 범위

- 대상: `services/law-calendar/frontend`의 법령 캘린더 탭.
- `packages/lawbot-ui`는 바꾸지 않는다. 챗봇 관리자 화면도 이 패키지를 쓰고 챗봇 화면 지문(`fingerprint.ts`)에 포함된다. 그래서 이 패키지를 바꾸면 챗봇 재빌드와 재시작이 필요해진다.
- 범위 밖:
  - 달력 칸 크기·색·오늘 표시, 상단 안내 이동, 검색, 공지, 목록 항목 표기
  - `viewport-fit` 변경, 보류 목록 창, ERP 탭, PC 동작
  - 데이터, 수집기, 내보내기, 게시기

## 요구사항·수용 기준

모바일 판정 기준은 `(max-width: 700px)`이다. 기존 반응형 기준과 같고, 탭하는 시점의 `matchMedia`로 판정한다.

### R1. 날짜 탭 → 시트
- 모바일에서 달력 날짜를 **클릭(탭)** 하면 그 날짜를 선택한다. 그날 시행 조문 또는 세무일정이 1건 이상이면 하단 시트를 연다.
- 0건이면 지금처럼 선택만 하고 시트는 열지 않는다. 세무일정만 있는 날에는 시트를 연다.
- 방향키, Home·End, Page Up·Down, `이전 달`, `다음 달`, `오늘` 버튼으로 선택이 바뀔 때는 시트를 열지 않는다.
  - 공용 `MonthCalendar`는 클릭과 키보드 모두 `onSelect`를 부른다. 공용 패키지를 바꾸지 않으므로, 클릭 여부는 캘린더 쪽에서 판별한다. 예: 달력 영역의 `click` 이벤트에서 날짜 버튼을 찾는다.
- 현재 불러온 달이 아닌 날짜(앞뒤 달 칸)를 탭하면 선택만 한다. 달 데이터를 다시 불러와야 하므로 시트를 열지 않는다. 데이터를 불러오는 중이거나 오류가 난 상태에서도 열지 않는다.
- PC(701px 이상)는 지금과 똑같다.

### R2. 시트 내용
- 제목은 선택 날짜(`dateLabel`)이고, 시트는 이 제목으로 라벨링한다.
- 시행 조문 목록에는 항목마다 법령명, 조문, 요약, 상태를 보여 준다. 처음 8건을 보여 주고 `더 보기`로 8건씩 늘린다.
- 세무일정 목록은 달력 아래와 같은 정보와 `국세청 원문 ↗` 링크(새 탭, `noopener noreferrer`)를 보여 준다.
- 같은 문서 안에서 `id`가 겹치지 않는다. 달력 아래 목록의 `lc-effective-title` 등과 충돌하면 안 된다. 그래서 시트 목록은 공용 `EventList`를 재사용하지 않고 캘린더 쪽의 작은 컴포넌트로 만든다.
- 예시(데모) 데이터일 때는 시트에도 `예시 / 실제 법령 아님`을 표시한다.

### R3. 시트에서 상세 열기
- 시트의 조문을 누르면 지금과 같은 상세 로딩(`loadChange`), 오류 안내, 전체 화면 `ChangeDialog`를 쓴다. 시트는 뒤에 열린 채로 남는다.
- 상세를 닫으면 시트로 돌아가고, 시트의 스크롤 위치와 방금 누른 항목의 포커스를 유지한다.
- 상세를 불러오지 못하면 시트 안에 오류 안내를 보여 준다.

### R4. 닫기와 뒤로 가기
- 닫기 버튼, 배경(시트 바깥) 탭, Esc, 브라우저 뒤로 가기(iOS 스와이프 포함)는 모두 **한 단계 뒤로** 간다: 상세 → 시트 → 닫힘.
- 시트를 열 때와 시트에서 상세를 열 때 `history.pushState`로 이력 항목을 하나씩 추가하고, `popstate`로 한 단계 닫는다.
- 버튼, 배경, Esc로 닫을 때는 `history.back()`으로 닫아서 이력 항목이 남지 않게 한다.
- 모바일에서 달력 아래 목록으로 연 상세도 같은 방식으로 뒤로 가기에 닫힌다.
- 뒤로 가기·앞으로 가기를 했는데 화면이 그대로인 이력 단계가 없어야 한다. 새로고침 뒤 남은 시트 이력이나 데이터에 없는 날짜·조문을 가리키는 이력은 건너뛰거나 정리한다.
- 시트를 닫으면 포커스를 원래 날짜 버튼으로 돌려준다.
- URL의 경로·쿼리·해시는 바꾸지 않는다. ERP 탭 해시(`#erp`)와 충돌하지 않아야 한다.

### R5. 모양·접근성
- 시트는 `<dialog>`(`showModal`) 기반이다.
  - 아래에 붙고, 최대 높이 약 85dvh, 위쪽 모서리를 둥글게 하고, 아래쪽에 `env(safe-area-inset-bottom)` 여백을 둔다.
  - 시트 안은 스크롤되고, 열려 있는 동안 뒤 페이지는 스크롤되지 않는다.
- 포커스 가두기, Tab 순환, 닫기 버튼 접근 이름(`날짜 내역 닫기`)을 갖춘다.
- 애니메이션은 `prefers-reduced-motion: no-preference`일 때만 쓴다(약 180ms 위로 올라옴).
- 가로 넘침은 0px이다. 기존 다크 모드 토큰(`--bg`, `--line` 등)만 쓰고 새 색은 만들지 않는다.

### R6. 콘텐츠 점검 (사용자 요청)
- 화면 문구와 테스트 데이터에 개인정보, 비밀값, 운영 주소·포트, 실제 사용자 대화가 없다.
- 테스트는 기존 합성 픽스처(`demo.ts`, `[예시]`)와 테스트 전용 데이터만 쓴다.
- 새 외부 의존성, 폰트, 이미지를 추가하지 않는다. 그래서 `licenses.txt`는 변하지 않는다.
- 출처 문구, `공식 출처` 링크, 라이선스 링크는 그대로다.
- 참고 프로젝트의 문구·데이터·이미지를 들여오지 않는다.
- PR 전에 diff에서 이메일·전화번호·토큰 형식·개인 경로·포트 번호를 검색하고 결과를 기록한다.
