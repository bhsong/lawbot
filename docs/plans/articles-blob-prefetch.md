# 조문 생성기의 부분 클론 blob 사전 수신

## 원인과 범위

2026-11-08 정기 점검에서 v5 조문 생성기가 부분 클론의 과거 원문을 처음 읽었다. `git cat-file --batch`에 여러 파일을 넘겨도 Git이 없는 blob마다 fetch를 시작해 monitor 제한 900초를 넘겼다. 변경 범위는 조문 생성기의 Git 읽기와 그 테스트다.

## 설계

- 부분 클론에서 읽을 `커밋:경로`를 blob OID로 해석한다. 지연 수신을 끈 상태로 로컬 존재 여부를 검사하고, 없는 OID만 중복 제거해 `fetch --stdin`으로 받는다. 이후 본문 읽기에서도 지연 수신을 끈다. 사전 수신에 실패하면 Git 오류를 포함해 실패한다.
- 파일 제목 확인과 변경 커밋 보고는 후보를 모아 읽는다. 전부개정 판정은 문서별로 최신 후보부터 확인하고, 시행 중인 전부개정 이전의 본문은 기존처럼 생략한다. 남은 이력을 문서 전체에서 모아 사전 수신하고 본문은 문서별로 읽는다.
- 일반·전체 클론은 원격 요청 없이 처리한다. 지연 수신을 확실히 끌 수 있도록 부분 클론에만 Git 2.44 이상을 요구한다. 행 순서, 조문 판정, CSV·매니페스트 및 비교 결과는 유지한다.

## 테스트와 완료 기준

- [x] Red에서 `file://` 부분 클론의 파일별 fetch를 Trace2로 센다. Green에서 같은 읽기가 묶음 한 번이고 일반·전체 클론은 0회임을 확인했다.
- [x] 로컬에 이미 있는 blob, 중복 OID, 끊어진 원격과 미수신 객체의 오류 경로를 확인했다.
- [x] 합성 저장소의 여러 문서·개정으로 부분/전체 클론의 `build()` 바이트, 버전 기록, 변경 보고가 같고 불필요한 옛 본문이 수신되지 않음을 확인했다.
- [x] 전체 Green을 확인하고 결과를 기록했다. 실제 legalize-kr 다운로드 검증은 미실행이다. [검증 기록](../evals/2026-11-08-articles-blob-prefetch.md)
