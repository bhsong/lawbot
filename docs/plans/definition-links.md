# 정의 조문 연결

작성 2026-11-19 KST. [근거 평가](../evals/2026-11-19-reasoning-format-definitions.md#정의-조문-연결)

## 목표

검색된 법률 조문이 다른 법에서 정의한 용어(예: 퇴직급여법의 "평균임금" → 근로기준법 제2조 제1항 제6호)를 쓰면, 그 정의 항목만 조문 뒤에 붙여 모델에 준다. v6 임베딩은 긴 정의 조문을 찾지 못하고(근로기준법 제2조 216~1,397위), 후보·최종 조문 수를 늘려도 회수가 늘지 않았다. 연결은 조문 원문에서 나온 하나의 규칙으로 만들고 문항별 예외 목록을 두지 않는다.

## 규칙

1. 각 조문의 `N. "용어"란 …` 항목을 정의 항목으로 읽는다. 같은 조에서 `제1항제N호`를 언급하는 항을 그 항목에 붙인다.
2. 정의가 `「법령」 제A조제1항제B호에 따른`으로 다른 법의 항목을 가리키면 그 항목까지 따라간다(최대 3단계).
3. 모델에 들어가는 상위 3개 법률 조문마다, 그 법이 정의한 용어가 본문에 쓰였고 정의가 다른 법의 항목으로 이어지면 그 항목을 조문 바로 뒤에 붙인다. 이미 제공된 조문과 중복이면 붙이지 않는다.
4. 전체 법률 조문의 5%를 넘게 등장하는 용어는 제외한다. 이 기준값은 val로만 정한다.

val 30문항에서 기준 조문 회수 21 → 24, 발동 5문항, 발동당 약 190자였다.

## 결정 (2026-11-19)

- **연결은 웹앱이 시작할 때 만든다.** 이미 읽은 조문 본문으로 연결 표를 만들고, 생성기·CSV·DB 형식은 바꾸지 않는다. 06:30 갱신된 코퍼스를 그대로 따라간다. 나중에 연결을 생성기나 그래프 DB로 옮길 때 재사용할 수 있도록 파서·연결 표·빈도 계산은 `packages/lawbot-common`의 `lawbot_common.definition_links`에 둔다.
- **화면에는 따로 보이지 않는다.** 정의 항목은 모델 입력에만 넣고 조문 카드로 표시하지 않는다. 답변이 정의 조문을 인용하면 간결형의 `근거:` 줄에는 그대로 나온다.

## 구현 범위

- 정의 항목·다른 법 참조 파서와 빈도 계산(단위 테스트: 정의 항목, 관련 항, 다른 법 해석, 최대 단계, 빈도 제외).
- 검색 결과 조립에서 상위 3개 조문 뒤에 정의 항목을 붙이는 단계와 요청 로그의 발동 기록(붙인 항목 수).
- 인용 검사: 붙인 정의 조문의 인용을 제공된 조문으로 인정한다.
- 조문 카드 목록에서 정의 항목을 빼는 처리와 대역 E2E(카드 3개 유지, 정의를 인용한 답변의 근거 줄).

## 검증 (각각 사용자 승인 후)

1. 일반 val 발동 빈도: 일반 val 질문으로 현재 검색을 실행하고 규칙의 발동 수, 기준 조문이 이미 제공된 문항에서의 발동 수, 붙인 분량을 잰다. 질문 임베딩·리랭킹 호출이 문항 수만큼 필요하므로 요청 수와 시간을 먼저 보고한다. 생성 호출은 없다.
2. 추론 val 32문항 전체 생성: 기준선(A, 2026-11-19 24.5점)과 문항별로 비교하고 하락 문항을 확인한다.
3. 일반 val 표본 생성: 발동한 문항에서 기존 답변이 나빠지지 않는지 확인한다. 표본 수는 1번 결과를 보고 정한다.
4. 지연: 발동 문항의 완료 시간 증가를 보고한다. 평가 기준 발동당 약 0~9초였다.
