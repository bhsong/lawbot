# 외부 접속: Cloudflare Tunnel + Access

## 목표

회사 등 Tailscale을 설치할 수 없는 브라우저에서 운영 챗봇과 법령 캘린더를 사용한다. 접속자는 사용자 본인 하나다. 관리자 기능은 지금처럼 Tailscale(또는 맥 미니 로컬)에서만 사용한다.

```text
외부 브라우저 → Cloudflare Access(허용 이메일 1개, OTP) → Cloudflare Tunnel(맥 미니에서 나가는 연결)
                                                           ├ 챗봇 호스트   → 127.0.0.1:<운영 웹앱 포트>
                                                           └ 캘린더 호스트 → 127.0.0.1:<캘린더 포트>
tailnet 기기 → tailscale serve → 같은 두 포트 (관리자 기능 포함)
```

- 공유기 포트는 열지 않는다. 모델 서버·생성 서버·Source Hub는 터널에 연결하지 않는다.
- 챗봇의 앱 로그인은 유지한다(Access와 이중 확인).
- 출처 이용 조건은 [재확인 기록](../evals/2026-11-19-external-access-copyright-check.md)을 따른다.

## 변경 범위

### 1. Cloudflare 경유 요청의 관리자 기능 차단 (코드)

Cloudflare가 프록시한 요청에는 항상 `CF-Connecting-IP` 헤더가 붙고, 클라이언트는 이 헤더를 지울 수 없다. `tailscale serve`와 로컬 접속에는 이 헤더가 없다. 이 헤더가 있는 요청을 외부 요청으로 보고 다음을 거부한다. 헤더를 위조하는 tailnet 기기는 자기 자신의 관리자 접근만 막으므로 문제가 없다.

- 챗봇 웹앱
  - `/api/admin` 아래 모든 경로: 404
  - 관리자 사용자명 로그인: 없는 사용자명과 똑같이 처리한다(가짜 해시 검증으로 같은 응답 시간, 5회 실패 후 429, 감사 기록 없음). 로그인 실패 횟수는 터널 경유와 Tailscale·로컬을 따로 세어 외부 시도가 tailnet 로그인을 잠그지 않게 한다.
  - 일반 사용자 로그인과 질문은 그대로 허용한다.
- 캘린더 서버: `/api/admin` 아래 모든 경로 404(서비스 토큰이 맞아도). 챗봇이 루프백으로 호출하는 관리자 프록시는 헤더가 없으므로 영향이 없다.
- 터널 설정에서도 두 호스트의 `^/api/admin` 경로를 404로 보낸다(이중 차단, 아래 3).

### 2. 출처 표시 (캘린더 화면)

- 기관 소식 드로어(고용노동부·재정경제부·국세청): 기관명과 누리집 URL 출처 표시, 해당 기관 저작권 정책 링크.
- 캘린더 하단 공식 출처: legalize-kr 링크와 "메타데이터 MIT" 표시.

### 3. 운영 문서 (operations.md)

- `cloudflared` 설치, 이름 있는 터널 생성, launchd 등록, 설정 파일은 레포 밖 사용자 폴더(권한 600)에 둔다.
- ingress: 두 호스트 → 각 루프백 포트, `^/api/admin` → `http_status:404`, 마지막 규칙 `http_status:404`.
- Access: 두 호스트를 덮는 self-hosted 앱, 허용 정책은 본인 이메일 하나, 세션 시간.
- 확인 절차와 끄는 방법(터널 서비스 중지).
- 포트·호스트명·이메일·터널 ID는 문서에 적지 않는다.

## 완료 기준

- 단위·계약·통합·대역 E2E 기본 테스트 전체와 Ruff·Pyright·프런트 typecheck·테스트·빌드 통과.
- 새 테스트
  - 챗봇: 외부 헤더가 있는 `/api/admin` 요청 404, 외부 관리자 로그인이 없는 사용자명과 같은 상태 코드 순서·가짜 해시 검증·감사 없음, 외부 잠금이 tailnet 로그인을 잠그지 않음, 외부 일반 로그인 정상, 헤더 없는 관리자 로그인 정상. 통합 테스트(실제 서버 프로세스)로 외부 헤더 차단 1건.
  - 캘린더: 외부 헤더 + 올바른 토큰도 404, 헤더 없으면 기존과 동일.
  - 화면: 기관 소식 드로어의 출처·저작권 정책 링크, 하단 legalize-kr 링크(단위 + 기존 ERP UI E2E).
- 실제 모델 E2E·모델 스모크·품질 평가: 검색·생성 경로를 바꾸지 않으므로 실행 안 함.

## 운영 반영 (별도 승인)

1. 코드 반영: 웹앱·캘린더 재시작(모델 서버·생성 서버는 재시작하지 않음).
2. 사용자가 Cloudflare 계정·도메인을 준비하면 operations.md 절차로 터널·Access 설정.
3. 확인: 외부 브라우저에서 Access 인증 → 챗봇 로그인·질문 1건, 캘린더 조회, 두 호스트의 `/api/admin` 404, 관리자 로그인 거부. tailnet에서는 관리자 기능 정상. 로그인 쿠키 `Secure` 확인.
4. 결과를 `docs/evals/`에 기록한다.
