## PR-A · 기준선, 등록부, 관리자

1. 기존 fixture를 재사용해 `daily`의 수집→점검→요약 순서·종료 상태, 정상/부분/실패/정상 0건의 캘린더 sync와 기존 공개 API, 6종 피드·이력·첨부 해시의 호환 계약을 먼저 고정한다. 호환성 테스트는 현재 동작에서 통과해야 한다. 새 동작은 관찰 가능한 실패를 확인한 뒤 구현한다.
2. `services/source-hub/`를 독립 uv 프로젝트로 두고 기존 모노레포 CI의 설치·lock·타입·pytest 대상에 추가한다. YAML 초기값 + SQLite 런타임 설정으로 소스·기관·법령 선택과 스케줄, 검증 상태, 수집 이력 및 설정 감사를 저장한다. 등록부 스키마에 고정 ID, 그룹·기관·게시판, 공식 홈·대상 URL, 모드·어댑터·파서 버전, 간격·대조·백필·초기 기준, 분류·검토·권리 정책과 마지막 시도/성공·오류·다음 실행을 둔다. 자격증명과 수신자는 독립 비공개 설정을 사용한다.
3. 그룹·기관·소스 및 지원되는 개별 법령의 활성 설정을 AND로 합성한다. 설정 저장 때 고정 ID·중복·등록된 어댑터·공식 도메인·모드·간격을 검증한다. 실행 계획은 설정 버전을 고정하고 변경자·시각·이전/새 값·사유를 감사에 남긴다. OFF는 다음 실행부터 신규 수집과 기본 알림 대상에서 제외하고 과거 자료·승인을 보존한다. 과거 요약 포함은 명시적 설정으로 제공한다.
4. 공개 캘린더와 분리된 관리자 UI/API와 fish CLI는 같은 검증·쓰기 경로를 쓴다. UI에서 기관/업무 필터, 모드·검증 상태, 최신 시도·성공·실패, 신규·수정 수, 다음 실행·감사와 OFF 영향 확인을 제공한다. 수동 실행·재시도는 등록된 소스만 대상으로 하고 PR-B에서 실제 실행에 연결한다. 수동 등록은 공식 링크·출처·검토 증적을 요구하며 게시 권한을 별도 확인한다. 인증 누락·권한 부족·브라우저 교차 출처 쓰기·중복 요청을 시험한다. 공개 앱은 관리자 라우트·수신자 정보를 제공하지 않는다.
5. 아래 범위를 모두 등록한다. 실측 전 기관 소스는 미검증·비활성으로 둔다. 정식 엔드포인트와 게시판 ID가 없는 후보는 조사 대상 경로와 사유를 가진 미검증 항목으로 남기고 실행을 막는다. 검증된 어댑터 유형 안에서 운영자가 배포 없이 게시판을 추가할 수 있게 한다.
6. 수집 설정 SQLite에 별도 응용프로그램 식별자를 부여한다. 캘린더·조문 코퍼스 등 다른 DB를 읽기·쓰기 대상으로 지정하면 거부하는 회귀 시험을 둔다.

## PR-B · 수집 실행, 원천 이력, 기관 스냅샷

[고용노동부 공식 RSS 세 채널 수동 수집](../archives/source-hub-moel-rss.md)을 먼저 병합했다. [고용노동부 게시판 목록 대조](../archives/source-hub-moel-reconcile.md)와 [재정경제부 수집](../archives/source-hub-mofe.md)은 PR #132로 병합했다. [국세청·홈택스](../archives/source-hub-nts-hometax.md)는 PR #133으로 병합했다. [기관별 최신 소식](erp-agency-news.md)은 별도 PR로 구현한다.

1. **기존 실행 어댑터.** 한 실행 계획을 기존 수집기에 CLI로 넘기는 호환 옵션을 제안한다. `daily`의 기본 동작과 기존 점검·요약을 유지한다. 명시적 선택 실행에는 소스별 `disabled/ok/failed`와 실행 ID를 기록하고 캘린더 sync가 해당 실행 결과를 읽게 한다. 구버전 실행 행도 읽는다. ERP는 monitor 내부 모듈을 import하지 않고 커밋에 고정된 읽기 전용 사본과 공개된 실행/이벤트 계약을 소비한다. monitor 및 sync 변경 파일과 검증 범위는 PR-B 착수 전에 승인받는다.
2. **OFF와 다시 켜기.** 저장소 전체가 OFF면 해당 수집기 호출과 그 수집기의 fetch·상세 조회를 0건으로 검증한다. 일부 법령만 OFF면 활성 형제의 공유 저장소 fetch는 유지하고, 비활성 법령의 blob·원문 보강 요청은 건너뛴다. 저장소 커서 전진 시 비활성 개별 범위의 마지막 처리 위치를 보존하고, 재활성화 때 누락 구간을 재대조한다. 이력이 다시 쓰였을 때 기존 비교와 명시적 기준점 정책으로 복구한다. 캘린더의 OFF 시각은 정상 최신 시각으로 승격하지 않는다. 기존 조문 자동 갱신이 같은 Git 사본의 최신 HEAD를 입력으로 쓰므로, 전환 전에 챗봇 원천 새로고침과 캘린더·ERP 수집 실행의 소유권을 분리한다. 챗봇은 현재와 같은 입력 경로·최신 HEAD·실행 순서·재생성 조건을 보장한다. 전체 OFF, 일부 OFF, 기관 수집 실패, 알림 실패 중에도 조문 갱신 명령이 동일한 최신 커밋을 받는지 임시 Git 사본과 대역 명령으로 검증한다. 이 계약을 충족한 후에 통합 스케줄 전환을 제안한다.
3. **기관 어댑터.** 자료 유형을 실제 제공하는 공식 API 우선, 다음으로 공식 RSS/Atom과 게시판 정기 대조, 공개 HTML 목록·상세·첨부, 허용이 확인된 공개 브라우저 접근, 공식 메타데이터 순으로 적용한다. 각 게시판별 URL·ID·피드 ID·목록 범위·페이징·공식 원문 연결·파서 버전·대조 주기를 기록한다. RSS의 URL·GUID·제목·발행일·설명·공식 링크와 게시글 ID를 대응시킨다. 홈택스는 공식 홈 링크와 자료실 메뉴를 안내한다. 국세청 공식 공지가 홈택스의 신규 게시 사실을 직접 확인해 주면 이후 알림에서 해당 공지를 근거로 사용할 수 있다. 접근·이용 조건이 불명확한 소스는 `blocked/manual_review`로 남긴다.
4. **관측과 버전.** 독립 ERP 패키지 `services/erp-materials/`의 SQLite에 실행, 문서, 판, 첨부, 검토 및 이벤트를 저장한다. ERP 관련성은 수집 뒤 판정하고 비관련·불확실 판정도 보관한다. 게시판 ID를 우선 식별자로 쓰고, 없으면 기관·게시판+정규 URL을 쓴다. RSS·HTML 관측을 연결해 중복을 막는다. 본문·첨부 바이트·URL 변경·정오표·삭제 확인을 각각 기록한다. 일시적 목록 누락을 삭제로 확정하지 않는다. 같은 관측의 재실행은 확인 시각만 갱신한다. 초기 백필 기준점과 알림 범위를 독립 관리한다.
5. **실패와 파일.** 게시판별 간격, 타임아웃, 제한 횟수 및 지수 백오프, 짧은 겹침 대조와 긴 주기 재대조를 둔다. 정상 빈 목록은 문서화된 빈 응답 조건을 검증한다. 파서 이상·403·429·타임아웃·점검·권리 확인 대기와 기존 마지막 정상 데이터를 구별한다. 다운로드는 허용 도메인과 각 리다이렉트, 크기·확장자·MIME·시그니처를 검사하고 해시·바이트·공식 링크·상태를 보관한다. PDF/HWP/HWPX/XLS(X)/ZIP은 형식별 추출기를 사용한다. 압축 해제·처리는 격리하고 파일 수·풀린 크기·시간을 제한한다. 본문 또는 첨부 실패 시 공식 링크와 확인 상태를 남긴다. 출처별 권리·개인정보 검토를 공개 전에 적용한다.
6. **기관별 최신 10건.** 공개 가능한 게시물로 스냅샷을 만들어 `GET /api/erp-news/latest`에 공급한다. 기본은 기관의 활성 등록 게시판 전체에서 게시일 내림차순, 날짜 미상은 뒤에 두고 안정 ID로 동률을 정렬한다. 적용일·발견일·갱신일은 별도 필드다. 마지막 성공 시각·범위·지연·실패·비활성·자료 한계를 응답에 넣는다. 일부 OFF면 활성 최신 목록에서 제외하고, 필요할 때 별도 과거 스냅샷에 OFF와 기준 시각을 표시한다. 법령정보센터 기본 범위는 추적 ERP 법령의 공포·개정 이력으로 제안한다. 공포·개정일과 시행일을 구분한다. 기관별 접근·첨부 검증은 별도 승인된 샌드박스 실행에서 측정하고, 대역 결과와 분리해 기록한다.

## PR-C · 공개 피드, 적용 기준, ERP 화면

1. **공개 경계.** 수집→분류→발췌→검토→공개를 분리한다. 공식 출처·권리·개인정보 확인을 거친 metadata-only는 소스별 자동 공개 승인에 따라 제목·게시일·링크만 노출한다. 확인된 발췌, 공식 첨부 링크, 형식·해시 검증 완료, 수동 검토 완료를 구분한다. 발췌는 순수 규칙 기반을 기본으로 한다. 본문·적용일·효력·신고 규격 추정 없이 카드에 확인 상태를 남긴다. 원본 재배포 권한이 없으면 공식 링크를 제공한다.
2. **하위 호환.** v1 파일과 `GET /api/erp-updates` 계약을 그대로 읽을 수 있게 두고, ERP v2 공개 파일과 조회 경로를 추가한다. v2에 기존 공개 ERP 자료, 기관 카드·상태, 업무 기준 판·출처·이력·스냅샷 식별자를 제공한다. v2가 미구성일 때 v1으로 표시한다. 유효한 v2에서 철회된 판을 v1 폴백으로 복원하지 않게 하고, 법령 일정 및 기관 최신 뉴스가 ERP 규칙의 로딩/실패와 별도로 동작하게 한다. 기존 Pydantic→TypeScript 스키마 검사와 `no-store`를 적용한다.
3. **효력 모델.** `ErpRule`의 고정 `rule_id`는 업무 주제·원천 키로 명시적으로 연결한다. `ErpRuleVersion`은 승인된 원천 revision, 버전 상태, 효력 기간, 적용 기준·범위, 값·근거 URL, 검토 시각을 갖는다. `ErpRuleTransition`과 검증된 필드별 근거로 현재와 예정 판을 연결한다. 제목 유사성 또는 캘린더 `comparable`만으로 연결하거나 차이를 생성하지 않는다. 공포·발령·게시·수정·수집·법령 시행일과 업무 적용일, 귀속연도, 기한을 분리한다. 기존 승인 자료는 그 승인과 자료 시점 그대로 이관하고 효력 범위를 검증하지 못한 경우 ‘현행 기준 확인 필요’로 표시한다.
4. **판정과 재검증.** KST 기준일과 명시적 업무 적용 컨텍스트(지급일, 근로제공기간, 귀속연도, 보험료 적용월, 신고분 등)에서 승인 유효 판을 고른다. 대상이 다른 부분 시행은 분리한다. 공식 확정 근거·새 내용·시작일·대상 범위를 모두 검증한 판만 예정으로 공개한다. 초안·예고는 검토 링크로 제공한다. 상충·철회·연기·최근 재검증 실패 시 예정 판은 재확인 상태로 전환하고 이전 승인과 이력을 보존한다. 예정 판의 현행 전환은 효력 조건과 재검증을 통과할 때만 수행한다. 과거 기준일 조회와 정정/철회 이력을 보존하고 적용일 미상의 자료는 별도 표기한다.
5. **카드와 목록.** `/#erp`의 현재·예정 섹션, 관련 법령 일정, 수집 이력과 기존 6종을 유지한다. 같은 업무 기준은 한 카드로 렌더링해 현행 및 가장 이른 확정 예정판, 각 적용 대상·기간·확인 시각·공식 링크와 검토 상태를 보여 준다. 이후 확정판은 접힌 타임라인에 표시한다. 검증되지 않은 표·레이아웃 차이는 원문 링크로 연결한다. 예정 근거가 없을 때 출처 최신성에 따라 ‘예정 변경 미확인’으로 표시한다. 기관 카드의 제목·게시일·수집/확인 시각·새 글/수정/정오표/첨부 상태·본문 확인 수준·검토·공식 링크와 검색, 기간 및 다중 필터, 페이지네이션을 검증한다.
6. **기관 드로어.** 기존 ERP 화면 우측에 버튼 다섯 개를 둔다. 이미 저장된 공개 스냅샷을 읽어 화면 폭과 스크롤 위치를 유지하는 하나의 오버레이를 연다. 데스크톱 폭 360–440px, 내부 스크롤, 트리거와 패널 간 포인터 이동, Escape·닫기·바깥 클릭, 키보드 초점 복귀, 터치·작은 화면, 애니메이션 감소 설정을 시험한다. 데이터 갱신은 활성 기관 선택을 바꾸지 않는다. 게시일 미상·0건·지연·비활성·오류·공식 개별 링크 미확인·다른 기관만 정상인 상태를 포함한다. 기관 소식과 확정 ERP 적용판은 별도 데이터로 유지한다.

## PR-D · 정기 실행, 동일 공개 스냅샷, 알림

1. 하루 실행 ID·설정 버전·KST 기준 시각을 고정한다. 단일 실행 제어가 소스별 주기와 ON/OFF, 기존 법령 실행 및 후속 점검, ERP 수집·공개, 설정된 시각의 일일 알림을 관리한다. 같은 home에서 수동/정기 실행이 겹치지 않게 한다. 수집 지연 시 확정된 마지막 스냅샷과 지연 표시를 사용한다. 활성 소스가 실패하면 정상 0건과 구분해 집계한다. 합성 시계로 중복 스케줄, 잠금, 중단 후 재실행을 검증한다.
2. 공개 ERP 파일과 알림이 같은 불변 공개 스냅샷의 ID·해시를 읽도록 한다. 날짜·cutoff·성공 실행 ID·공개판 ID와 출처 상태를 고정한다. 공개 파일을 원자적으로 교체하고, 당일 발송 기준 스냅샷은 재실행 시 그대로 사용한다. 전일 기준 스냅샷과 비교해 발견·정정·첨부 변경과 신규/정정된 확정 미래 판을 구한다. 기관 최신 10건은 운영자가 전체 목록 요약을 선택할 때 포함한다. 승인 철회와 재확인 상태도 이력과 공개 화면에 반영한다. 발송 전에 스냅샷이 철회되면 남은 전송을 중지하고 대체 발송 여부를 관리자에게 표시한다.
3. 알림은 제목, KST 날짜, 정상/지연/실패/비활성 집계, 신규·수정 강조, ERP 공개 요약 및 링크를 담는다. 새로운 예정 변경에는 적용 시작과 대상, 검증된 차이, 양쪽 공식 원문을 넣는다. UTF-8 SMTP 텍스트·HTML과 Telegram 분할·이스케이프를 채널별로 렌더링한다. 발송 시각·채널·수신자 별칭·항목 상한·무변경일 발송 여부를 비공개 설정으로 관리한다.
4. 아웃박스의 고유 키는 `(day_kst, snapshot_hash, channel, recipient)`로 한다. 동시 처리의 선점을 원자적으로 기록하고 Telegram은 성공한 조각을 재전송하지 않게 저장한다. 확실한 재시도 가능 실패와 응답 유실처럼 수락 여부가 불명확한 실패를 구분한다. 수락 여부 불명은 자동 재전송 없이 대조 대상으로 보낸다. 공급자 수락과 확인 가능한 전달 상태는 별도 기록한다. 실패는 수신자·채널 단위로 격리한다. SMTP와 Telegram 모두 로컬 대역으로 한글·링크·길이·스냅샷/델타 일치·재시도·동시성·비밀정보 노출을 검증한다.

## PR-E · 분리 리허설과 운영 전환

1. 법령 실행기·캘린더 DB 없이 ERP 패키지·DB·공개 파일·알림을 독립 실행한다. 기존 법령은 별도로 실행한다. 합성 DB에서 기존 승인/해시 보존, 백업·복원, 읽기 전용 피드와 정정 철회, 권한 경계, 보존 기간·용량 상한을 검증한다.
2. 새 실행 가이드를 작성해 확인된 운영 경로와 현재/대상 커밋, 실제 등록 작업과 겹침 여부, 백업·복원 명령, 수집 종료/발송 시각을 기록한다. 운영 승인 뒤에만 등록된 기존 작업의 상태와 완료 여부를 확인해 기존 작업 해제와 새 작업 활성화를 순서대로 수행한다. 기존 조문 갱신·요약의 실행 순서와 책임을 인계한다.
3. 전환 전 운영 DB·설정·피드·스케줄을 독립 백업하고 무결성을 확인한다. 실패 시 새 실행과 발송을 멈추고, 검증된 구 실행과 공개 피드를 복원한다. 승인 이력과 수락 불명 아웃박스를 보존해 롤백 뒤 중복 발송을 방지한다. 실제 SMTP/Telegram은 승인된 시험 주소·비공개 채팅에서 검증하고 그 결과를 확인한 뒤 실제 수신자를 별도 설정한다.
