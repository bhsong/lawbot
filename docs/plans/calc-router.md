# 계산 질문 라우터와 결정적 계산기

`feat/calc-router`는 원격 `main`의 `9b3c60f`에서 시작했다. #112 병합 후 기준을 `1458e62`로 갱신했다. 앱 버전 구분은 `y`이며 배포 순서상 v5.5.0 예정이다.

기존 계획을 대조했다. #112에서 검색 평가와 운영 반영을 확인해 [소득세법 전체 조문 계획](../archives/v5-income-tax-full.md)을 보관했다. `tax-full-scope-remaining-laws.md`는 후속 범위, `LAW_CALENDAR_PLAN.md`는 실데이터 검증, 모니터 수집기 계획과 원 계획서는 입법예고 수집·리마인드 작업이 남아 현 위치에 둔다. 기존 개발 트리의 미커밋 평가 기록은 별도 복제본으로 격리했다.

1. 의료비 세액공제와 기본 공제 범위의 중도정산 근로소득세를 순수 함수로 계산한다. 적용 연도별 법정 수치와 조문 해시는 v5 기준 데이터에 넣고 활성 CSV 또는 DB 릴리스와 대조한다. 결과가 바뀌는 누락·모호한 입력은 필요한 값과 조문을 안내한다.
2. 합성 val에서 고른 결정적 게이트를 웹앱과 캐시에서 공유한다. 후보만 기존 Pro API에 JSON을 한 번 요청하고 입력의 원문 구간을 검증한다. 캐시 조회·seed·승인에서 후보를 제외하고 기존 항목은 조회 및 관리에서 끈다. 계산기 이름·상태·라우터 사유·지연·사후 검사만 계산 메타데이터로 기록한다.
3. 기존 답변 생성 프롬프트에 계산 또는 안내 지시를 추가한다. SSE로 모델 응답보다 먼저 입력과 단계 표를 보내고 결론의 금액이 다르면 화면에 경고를 표시한다. 비계산 질문의 기존 프롬프트 바이트와 호출 수를 시험에서 고정한다.
4. 손으로 검산한 계산기별 10건 이상, 원문 구간·숫자 파싱, 프롬프트와 서버 API 계약, 캐시와 코퍼스 전환, 390px·1280px 브라우저 경로를 TDD로 확인한다. 기본 테스트 전체, 린트, 타입 검사, 빌드가 통과한 후 PR을 연다. 실제 모델 E2E, 모델 스모크, 품질 평가는 실행 안 함으로 기록한다.

## 적용 범위

- 법정 수치 파일은 2026년 귀속을 지원한다. 귀속연도가 없으면 서울의 현재 연도를 적용하고 입력 표에 기본값을 표시한다. 지원 데이터에 없는 연도는 안내로 전환한다.
- 의료비는 제59조의4제2항 순서에 따라 총급여 3% 문턱을 적용한다. 일반 부양가족은 문턱 차감 후 700만 원을 한도로 한다. 대상 구분 또는 실손보험금 배분을 달리해도 결과가 같은 경우 계산한다.
- 중도정산에서 제52조의 건강·고용보험료 특별소득공제를 적용하는 경우 제59조의4제9항의 표준세액공제는 0원이다. 해당 공제를 신청하지 않는 경로의 표준세액공제는 13만 원이다. 표의 결정세액·지방소득세는 원 단위 계산이다. [소득세법 제59조의4제9항](https://www.law.go.kr/lsLinkCommonInfo.do?lsJoLnkSeq=1032011667)
- 활성 코퍼스와 웹앱이 로드한 조문의 본문을 대조한다. 조문이 누락되거나 해시가 다르면 관련 계산기만 끈다. CSV에서 의료비 시행령을 읽으려면 통합 CSV가 필요하다.

## 평가

합성 val 100문항을 고정했다. 계산 후보 80문항과 비계산 대조 20문항이며 test 분할은 만들지 않았다. 게이트만 확인하는 명령은 `uv run python -m lawbot_tools.eval_calc_router`이다.

별도 승인 후 개발 CSV v5 설정으로 아래 명령을 실행한다. 라우터 자체 진단은 비계산 대조군까지 포함한 100회다. 계산 질문 8건은 웹앱 경로에서 다시 실행하므로 라우터 8회, 답변 생성 8회, 검색 임베딩·리랭킹 최대 32회가 추가된다. 웹앱 인덱스 초기화 임베딩 최대 2회를 포함하면 추론 요청은 최대 150회다. 준비·모델 목록 조회는 별도다. 예상 시간은 25–55분이며, 동시 요청 1개로 06:20–06:50 KST를 피한다.

```sh
uv run python -m lawbot_tools.eval_calc_router --live --output /tmp/lawbot-calc-router-val.json
```

## 운영 반영

병합과 운영 반영 승인 후 챗봇 프런트엔드에서 `npm ci && npm run build`를 실행한다. [정확 일치 캐시 절차](../operations.md#p07-정확-일치-캐시)의 `exclude-calculations`로 초안·승인 개수와 ID를 기록하고, DB 백업 후 `--apply`로 기존 활성 플래그를 끈다. 웹앱을 재시작하고 `uv run python -m lawbot.check_deploy`에서 계산기별 조문 해시 상태와 캐시 집계를 확인한다.

개발의 합성 DB에서는 초안 1건과 승인 1건이 제외됐고 활성 플래그 1건을 껐다. 운영 개수는 운영 반영 시 읽기 전용 명령으로 확인한다. [검증 기록](../evals/2026-11-11-calc-router.md)
