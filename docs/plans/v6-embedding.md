## 1. 맥 미니 4단계 A (검색만, 생성 없음)

**목표:** 운영과 같은 MLX 4bit 리랭커로 v6 임베딩의 검색 지표를 잰다. 비교 대상은 [11-11 신규 B 평가](../evals/2026-11-11-new-b-eval.md)(v5b, 같은 3,795조문, 같은 val 3,606문항)다.

| 단계 | 내용 | 승인 |
| --- | --- | --- |
| 1-1 모델 배치 | 사용자가 Drive `labor_law/v6/emb_final_v6_fp16`을 운영 트리 `models/v6/emb_v6_fp16`(git 밖)에 둔다. `lawbot_model_server.check`와 파일 SHA-256으로 확인한다 | 사용자 작업 |
| 1-2 모델 서버에 추가 | 운영 `.env`의 `LAWBOT_SERVE_EMBEDDING`에 `lawbot-emb-v6=models/v6/emb_v6_fp16`을 더하고 모델 서버를 한 번 재시작한다. 운영 웹앱은 계속 `lawbot-emb-v5b`를 쓴다(11-05 v5 평가와 같은 방식) | 운영 설정·재시작 승인 |
| 1-3 평가 | 개발 `.env`의 `LAWBOT_EMB_MODEL=lawbot-emb-v6`. `lawbot-eval-v4 retrieval`과 `decree-retrieval`를 `--split val --dataset v5`로 실행한다. 동시 1, 재시도 0. 추론 요청 약 14,400회(질문 임베딩 약 7,200 · 리랭킹 약 7,200), 약 6시간. 06:15–06:50, 메모리 압박 단계 4, 운영 웹 3회 연속 실패에서 멈춘다 | 실제 모델 호출 승인 |

val에는 기존 문항만 있다. 레포의 검토 전 질문으로, 신규 조문 문항은 없다. 신규 조문의 효과는 Colab 수치로 본다.

## 2. 반영 판단

**반영 조건 (제안):**
- 세금·보험 법률 리랭킹 R@3과 두 하위법령 첨부율이 v5b 이상이다.
- 노동 법률 리랭킹 R@3 하락이 사용자가 정한 범위 안이다. Colab 표본에서는 −1.5p였다.

반영하면 임베딩 모델이 바뀌므로 X를 올린다(`v6.0.0`, [버전 규칙](../operations.md#운영-버전과-태그)). 반영은 별도 요청으로 진행한다.
- 운영 `.env`의 `LAWBOT_EMB_MODEL`을 바꾸고 웹앱을 재시작한다. 조문 임베딩 캐시는 새로 만들어진다.
- 정확 일치 캐시가 검색 결과에 기대는지 확인한다.

## 3. 레포 데이터 반영 (반영 결정 뒤, 별도 PR)

- 검토를 반영한 `qa_*` 3종과 정답 키, 신규 `qa_new_v6`·`split_new_v6`·`answer_key_new_v6`을 `data/`에 넣는다.
- 평가 도구 `--dataset`에 v6 세트를 더한다.
- 노동 법률 41문항(정답 조문 변경)의 새 정답 키를 만든다.

## 4. v6b (이번 달 말)

Colab 결과의 결정 A를 따른다. 같은 입력 CSV를 쓰고, 출력은 `v6b`로 따로 둔다. 규칙은 노동 train 2배, 노동 negative_2는 노동 계열 조문, 에폭 선택에 노동 법률 R@10 ≥ v5b 조건이다.
