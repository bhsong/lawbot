# 아침 Qwen 요약을 재사용하는 ERP 일일 이메일

2026-11-13 KST. 기준 `main` `bd6b110`, 작업 브랜치 `feat/erp-gmail-digest`. [통합 구현 계획](source-hub-erp-v1.1.md)

## 기존 흐름과 목표

- `law-monitor daily`는 수집과 캘린더·조문 점검 이후 `qwen3.8-27b-4bit`로 법령과 행정규칙의 변경을 요약한다. 결과는 `data/summaries/YYYY-MM-DD.md`에 쓰고 같은 날 다시 실행하면 별도 파일을 만든다. 현재 Markdown에는 내부 이벤트 경로, 운영 점검 결과, 공개 승인 전인 자료가 포함될 수 있다. [monitor 요약 계약](../../services/monitor/README.md#요약-2단계)
- `source-hub daily`는 KST 날짜와 실행 ID를 정하고 공개 승인된 ERP 카드·예정판·기관 소식과 당일 변경을 하나의 해시로 발행한다. 알림 입력은 해당 공개 스냅샷에 고정한다. [공개 스냅샷 계획](../archives/source-hub-daily.md)
- 메일 본문에서 공개 자료에 연결된 기존 아침 Qwen 요약을 재사용한다. 새로 수집한 자료는 확보하고 공개할 수 있는 근거의 범위에 맞춰 보강한다. 챗봇의 조문 갱신·재생성 조건과 순서, 기존 Markdown·상태·출력 및 모델 서버 설정을 보존한다.

## 구현 순서

1. 기존 모델 호출의 결과에 이벤트 ID와 원천 판 식별자를 붙여, 통합 실행 ID에 연결한 비공개 구조화 결과를 저장한다. 이메일 작성 단계는 이 결과를 읽는다. 날짜가 같은 파일을 골라 연결하는 방식은 재실행·밀린 이벤트를 구분할 수 없으므로 사용하지 않는다. 기존 Markdown이나 운영 점검 결과를 이메일 렌더러에 전달하지 않는다.
2. 법령 변경 목록은 캘린더에서 직전 스냅샷의 기준시각 이후 가져왔거나 공개 승인한 항목에서 구한다. 첫 스냅샷은 KST 당일 자정을 시작점으로 한다. 같은 날 재발행은 같은 비교 기준을 사용한다. 목록을 만든 뒤 요약의 이벤트·원천 판·공개 승인 범위를 대조한다. 요약 생성 실패·길이 초과, 보류 조문이나 별표가 섞인 요약, 원천 판 불일치에는 공식 링크와 공개 필드를 사용한다. 모델이 쓴 시행일·금액·요율·업무 영향은 그 주장까지 확인된 경우에만 실어 보낸다. 검증된 변경 예정판의 적용일·대상과 검증된 차이는 ERP의 승인 필드에서 가져온다. 확인할 수 있는 양쪽 공식 원문 링크를 함께 표시한다.
3. 새 자료의 제목과 링크만 확보한 경우 게시일과 `내용 미확인`을 표시한다. 홈택스는 현재 공식 자료실 링크 경로를 유지한다. 공개 승인을 받은 발췌나 확인된 근거가 있는 ERP 변경이 있을 때에만, 요약에 필요한 근거를 항목 ID와 함께 Qwen에 제공한다. 출처 텍스트는 자료로 전달하고, 모델 출력의 식별자와 인용 범위를 검사한다. 보강 호출은 하루 최대 한 번, 동시 요청 한 건, 자동 재시도 없이 실행한다. 실패·누락 시 메일은 승인된 공개 필드와 링크로 작성한다. 이메일 재시도에는 저장된 본문을 사용한다.
4. 같은 KST 공개 스냅샷에서 출처별 정상·지연·실패·비활성, 신규·정정·첨부 변경, 새 확정 예정 변경과 공개 ERP 링크를 담은 UTF-8 HTML·텍스트 메일을 만든다. 최신 소식 드로어의 기존 목록과 당일 변경을 구분한다. 발송은 기본 OFF로 두고 비공개 설정에서 수신자, KST 발송 시각과 무변경일 정책을 지정한다. 별도 시험 주소를 설정하기 전에는 로컬 대역으로 검증한다.
5. Gmail API의 `gmail.send` 권한을 사용한다. OAuth 자격증명과 수신자 설정은 비공개 실행 환경에 보관한다. 아웃박스는 날짜·공개 스냅샷 해시·채널·수신자 키로 전송을 선점한다. Gmail 수락, 재시도 가능 실패, 수락 여부 불명을 구분하고 불명은 자동 재전송하지 않는다. 정정·철회로 공개 해시가 바뀌면 기존 해시로 남아 있는 발송을 중단한다. 실제 발송과 운영 일정 등록은 별도 승인 후 진행한다. [Gmail 발송 API](https://developers.google.com/workspace/gmail/api/reference/rest/v1/users.messages/send) · [Google OAuth 서버 인증](https://developers.google.com/identity/protocols/oauth2/web-server#offline)

## 검증

- Red → Green → Refactor로 요약 재사용 시 모델 추가 호출 0건, 공개 승인·철회·부분 승인·원천 판 불일치, 파일명과 무관한 당일 재실행, 메타데이터만 있는 기관 글, 확정 변경과 공지의 분리, 모델 장애 폴백을 시험한다.
- 로컬 Gmail 대역에서 한글 HTML·텍스트, 공식 링크, 공개 파일과 메일의 스냅샷 해시 일치, 같은 날 중복 0건, 동시 선점, 확실한 실패 재시도, 응답 유실 시 자동 재전송 0건을 확인한다. 기존 monitor·캘린더·챗봇 대역 흐름과 기본 전체 검사를 실행한다.
- 이 세션의 이 PR에 한해 승인된 Qwen 실연동은 새 ERP 입력 계약을 사용하는 개발용 명령으로 합성 공개 자료 한 묶음을 최대 한 번 생성한다. 확인된 본문 근거와 제목·게시일·링크만 있는 항목을 사용하며, 후자에는 본문 해석을 생성하지 않는다. 기대값은 근거가 있는 항목 ID로 연결된 짧은 요약과, 내용 미확인 항목·공식 날짜의 보존이다. 호출 전 조문 갱신 시간대, 서버 준비, 기존 Qwen 모델 상주 및 서버 혼잡 여부를 읽기 전용으로 확인한다. 기존 서버와 상주 모델을 사용하며 서비스 재시작과 모델 교체 없이 1요청, 출력 최대 800토큰, 최대 대기 300초로 제한한다. 실패 시 재시도하지 않는다. 검증 결과와 요청 수는 `docs/evals/`에 기록한다.
- 이 PR에서는 Gmail 실발송과 운영 일정 전환을 다루지 않는다. Telegram은 보류한다.
