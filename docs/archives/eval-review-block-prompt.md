# 법률 추론 val: "핵심 검토" 블록 시스템 프롬프트 비교

작성 2026-11-19 KST.

## 목표

코드 변경 없이 시스템 프롬프트만 바꿨을 때 답변 품질이 달라지는지 확인한다. 현재 레포 구성의 기준선과, 현재 간결형 system 뒤에 "핵심 검토 → 상세 답변" 출력 규칙을 덧붙인 구성을 같은 val로 비교한다.

## 대상

- 법률 추론 val 32문항 [`data/v5/qa_reasoning_val.csv`](../../data/v5/qa_reasoning_val.csv) (ERR001–ERR030, CARD01–CARD02). test 평가셋은 사용하지 않는다.
- 평가기 `lawbot_tools.eval_reasoning`. 웹앱 질문 경로(임베딩 → 리랭크 → 하위법령 → 생성)를 개발 설정 예시(`.env.dev.example`, v5 프로필)로 문항당 한 번씩 순서대로 실행한다.

## 실행

| 실행 | system 파일 | 방법 |
| --- | --- | --- |
| A 기준선 | `data/v5/system_v5_concise.txt` | `uv run --no-sync python -m lawbot_tools.eval_reasoning --output <임시 경로>` |
| B 핵심 검토 | A 파일 뒤에 사용자 지정 `[답변 출력 규칙]` 블록을 그대로 덧붙인 레포 밖 임시 파일 | 레포 밖 임시 실행기가 같은 평가기를 호출하면서 `LAWBOT_PRO_SYSTEM`만 임시 파일로 바꾼다 |

- 저장소 코드·데이터·설정은 바꾸지 않는다. B의 system 파일 해시는 평가기의 실행 구성 기록에 남는다.
- 온도 0, 출력 최대 1,024토큰, 응답 대기 300초, 동시 1, 자동 재시도 없음(평가기 기본값). A 다음 B를 순서대로 실행한다.
- 실행 전 확인: 06:20–06:50이 아님, 두 모델 서버 준비, 필요한 모델 id 상주. 하나라도 실패하면 질문을 보내지 않는다. 실행 전후 구성이 다르면 그 실행은 무효로 표시한다.

## 판정

- 자동 집계: 기준 조문 전부 제공·전부 인용, 거절, 요청 성공, 출력 길이 제한 도달, 질문당 시간.
- 내용 판정: Claude가 문항별로 첨부 기준 답변과 대조한다. 핵심 판단과 결론에 영향을 주는 조건이 맞으면 1점(일치), 결론은 맞지만 중요한 조건·설명이 빠지거나 틀리면 0.5점(부분), 핵심 판단이 틀리거나 유보하면 0점(불일치). 이전 기록과 같은 기준이다.
- CARD01·CARD02는 근거가 조문이 아니라 국세청 안내라 조문 지표를 따로 해석한다.
- B 추가 확인: 핵심 검토 블록 출력 여부와 분량(3줄 이내·약 80자), `【결론】`·`【근거 조문】` 형식 유지, 1,024토큰 잘림.
- A와 B를 문항별로 대조해 개선·하락 문항과 이유를 적는다. 지연 시간 증가도 함께 보고한다.
