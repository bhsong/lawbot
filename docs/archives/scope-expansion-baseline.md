# 법령 감시 범위 확장과 개정 재생성

- 개발 기준은 `main` `a7786a4`, 작업 브랜치는 `fix/scope-expansion-baseline`이다.
- 2026-11-16 운영 확인에서 11-15 06:30 수집의 `daily-law-paths` 변경으로 기존 Legalize 파일 14개가 감시 범위에 들어왔다. 범위 재탐색이 이 파일들을 신규로 분류해 이전 조문 없이 전체 조문을 잡았다. 캘린더는 마지막 개정 부칙의 시행일로 이벤트 8개(204조문)를 자동 공개했고, 이벤트 3개(53조문)를 `complex`·`missing`으로 보류했다. 사용자 승인 후 운영의 이벤트 11개를 철회·거절했다. 남녀고용평등법 시행령과 임금채권보장법 시행령은 실제 개정 재생성 검증 대상이다.

## 구현과 완료 기준

1. 같은 관리형 수집 경로에서 범위를 확장하는 테스트를 먼저 작성한다. `cursor..HEAD`의 실제 추가·개정 커밋을 처리한 뒤, 범위 재탐색에서 처음 발견한 파일은 blob과 `items`만 저장한다. 실행 요약에 `기준점 추가 N개`를 남긴다. 이후 이 파일의 개정, 이력상 신규 파일, 강제 푸시 대체 비교, 비활성 경로 backfill을 검증한다.
2. 이전 원문이 없는 조문을 `new_document`로 보류하고 `RULE_VERSION`과 안내 문구를 갱신한다. 제정과 개정 중 조문 신설을 모두 재현한다. 수동 검토로 공개할 수 있는지, 철회·거절한 이벤트가 정정 원천을 다시 가져와도 비공개인지 확인한다.
3. `law-monitor replay-amendment`에 저장소 내 파일 경로와 개정 커밋을 명시한다. 해당 커밋의 부모와 비교해 기존 replay 형식의 `law_amended` 이벤트를 만들고, 캘린더는 기존 명시적 import 명령으로 가져온다. `--dry-run`은 로컬 Git 객체만 읽고 변경 조문과 부칙 시행일만 출력한다. 저장 경로는 기존 replay를 따른다.
4. 합성 자료로 Red → Green을 확인한다. 기본 pytest, Ruff, Pyright, 캘린더 프론트 타입 검사·테스트·빌드를 수행한다. 11-10 공포 개정 두 건은 개발 DB 사본과 기존 로컬 Legalize 객체로 dry-run하고 결과를 `docs/evals/`에 기록한다. 운영 반영과 운영 개정 재생성·import는 각각 사용자 승인 후 진행한다.

## 구현 결과

- `effective-date-v8` 및 `monitor-law-v8`을 적용했다. 명시적 import에서 자동 판정을 다시 평가할 수 있고, 기존 수동 검토 결정은 그대로 적용한다.
- 기존 `law_new`와 실제 개정의 새 blob이 같으면 별도 개정 ID로 저장한다. `data/replay/amendments/`에 만든 이벤트는 명시적 캘린더 import로 가져온다. [명령 사용법](../../services/monitor/README.md#감시-기준점과-단일-개정-재생성)
