# 정확 일치 캐시 관리자 승인 개선

기준은 `origin/main`의 `8bbd69b`, 작업 브랜치는 `feat/cache-approval-ux`다. 예시 질문 계획은 검증 기록과 병합을 확인해 보관했다. 캘린더, 수집기와 v5 범위 계획은 각각 후속 단계 또는 평가가 남아 있어 유지한다.

| 계약 | 구현 및 확인 |
| --- | --- |
| A 모드 전환 | `off`, `shadow`, `on`을 직접 전환한다. 활성화에 필요한 현재 승인 ID와 보호 분할 지문 검사를 유지한다. 대역과 단위 테스트에서 직접 전환과 shadow 관찰을 확인한다. |
| B 초안 승인 | 관리자는 모드와 관계없이 초안에 연결된 철회되지 않은 허용 질문을 승인한다. 검토 대기 답변을 `on`·`shadow`에서 재승인할 때는 이전에 검토된 질문만 복구한다. CLI의 `approve`는 namespace 전체의 활성 질문을 다시 지정하는 승인 묶음 교체이므로 `off` 요구를 유지한다. |
| C 승인 사유 | 단건·일괄 승인에서 공백 또는 미입력 시 `표시본 확인 승인`을 감사에 남긴다. 모드·철회 요청은 기존 400 `reason_required`를 유지한다. |
| D 일괄 승인 | 현재 generation에 상세를 열어 받은 표시본 해시를 보관하고 선택한 항목을 `POST /api/admin/cache/approvals`로 한 번 전송한다. 요청당 최대 50개를 받는다. 단건과 같은 검증을 재사용하고, 같은 트랜잭션에서 답변별 감사와 승인 ID·generation을 한 번 갱신한다. 항목 오류는 `answer_id`, `code`, `detail`로 반환하고 답변 변경을 모두 되돌린다. 동일 요청의 성공과 업무 오류 응답은 기존 멱등 영수증으로 재생한다. Origin, 관리자 권한과 속도 제한은 기존 가드를 사용한다. 스키마 변경은 없다. |
| E 관리자 화면 | 확인한 답변만 선택할 수 있으며 목록 필터를 바꿔도 현재 generation의 선택을 유지한다. 상세 하단의 승인·철회 영역에 상단과 연동된 사유 입력을 둔다. 모드·철회 옆의 사유 안내, 비활성 스타일, `on`의 즉시 반환 경고와 `role="alert"`를 확인한다. |

1. 모드·승인·롤백·가드 테스트와 390px·1280px Chromium 흐름을 추가해 변경 전 실패를 확인한다.
2. 서버와 화면을 구현하고 기존 carry-forward, 재승인과 철회 회귀를 확인한다. 테스트에는 임시 DB와 대역 모델 서버를 사용한다.
3. 기본 테스트 전체, CI의 정적 검사와 두 프런트엔드의 타입·단위 테스트·빌드를 실행한다. 실패한 대역 테스트만 `results/`에 스크린샷을 남긴다. `e2e_live`, `models`, 품질 평가는 실행 안 함으로 기록한다.
4. 운영 문서와 검증 기록을 갱신하고 계획을 보관한다. 전체 Green 뒤 계약별 검증과 프런트엔드 빌드 필요 사항을 담아 main 대상 PR을 만든다.
