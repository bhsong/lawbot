# 계산기 PR3: 2단계 라우터와 사실 판정 정리

작성: 2026-11-12. 브랜치 `feat/calc-two-stage-router`. 직전 상태: v5.6.1(`92e061f`), main `a3c62ba`.

## 문제

계산기 7종 전체를 다시 살펴보니 오류와 지연이 같은 구조에서 나온다.

1. **수량 누락을 막을 수 없다.** 라우터 LLM 한 번이 계산기 선택, 값 복사, 사실 판정을 한꺼번에 JSON으로 낸다. 질문에 있는 숫자를 LLM이 빠뜨려도 코드는 알 수 없다. 옛 held-out 012는 명세상 812일을 버리고 날짜로 계산해 잘못된 금액(8,833,496원)을 냈다. 사후 정규식 대조(`5a55bf3`)로 막아 보았지만 정상 질문 13건을 막아 되돌렸다.
2. **사실 판정을 정규식이 다시 한다.** LLM이 근거 구절만 복사하면 모듈 정규식이 그 구절의 긍정·부정을 다시 판정한다. 그래서 표현이 조금만 달라도 안내로 빠진다. 예: 014 "계속 회사에 다니고 있어요", 042 `applicability` 전체 일치, 051/052/056 `include_base`, 퇴직금 `service_qualifies`는 `1년 이상` 문구가 있어야 함.
3. **확인 문구가 없으면 거절한다.** `_MONTH_BASIS`, `_HOUR_EVIDENCE` 같은 검사는 모순이 있을 때가 아니라 정규식이 확인하지 못할 때도 거절한다(041).
4. **느리다.** 모든 계산형 질문이 약 1,200토큰 프롬프트를 쓴다. 출력 JSON이 길어 p50이 8.9초다. 조회·미지원 질문도 5.2초가 걸린다.

## 설계

언어 해석은 LLM이 하고, 코드는 계산·법령 규칙·기계적으로 확인할 수 있는 검사를 맡는다.

- **1단계 선택**(약 300토큰, 출력 최대 12토큰): 계산기 이름 7개, `unsupported`, `lookup` 중 하나를 고른다.
- **2단계 라벨링**(선택한 계산기만): 코드가 질문 속 숫자를 정해진 규칙으로 잘라 `[번호:값]`으로 표시한다. LLM은 번호마다 `번호=항목`, `x`(입력 아님), `?`(불확실) 중 하나를 쓴다. 이어서 언급된 사실만 `항목=예|아니오|불명|근거`로 쓴다. 숫자마다 반드시 라벨이 붙으므로 누락은 구조적으로 생기지 않는다. 라벨이 없는 숫자나 한 항목에 서로 다른 값이 붙으면 모호 안내로 보낸다.
- 출력은 기존 라우터 JSON(`calculator`, `inputs`, `ambiguity`)과 새 `facts`(`{항목: true|false|null}`)로 바꿔 `calc_router.route_calculation`에 넘긴다. 기존 검증 단계(구절 존재, 코퍼스 호환, 단위 복원, 금액 분해)와 계산 모듈은 그대로 쓴다.
- **사실 극성**: `facts`가 있으면 LLM 판정을 따른다. 정규식은 근거에서 반대 극성을 분명히 찾을 때만 거절한다. `불명`이면 그 사실을 확인해 달라고 안내한다. `facts`가 없는 기존 JSON은 지금처럼 정규식으로 판정한다.
- **단위 호환**: 숫자의 명시 단위가 항목 종류와 맞지 않으면(예: 시간 항목에 `4주`) 그 숫자를 `x`로 취급한다. 사실 항목 이름이 붙은 숫자도 `x`로 취급한다.
- **확인 문구 검사는 모순일 때만 거절**: `_MONTH_BASIS`, `_HOUR_EVIDENCE`, 퇴직금 `1년 이상` 같은 검사는 질문의 값과 다른 값을 찾았을 때만 거절한다. 날짜나 기간이 있으면 퇴직금 1년 요건은 그 값으로 판단한다.
- 세금 전용 프롬프트(`tax_only`)를 없애고 평가와 운영이 같은 경로를 쓴다.

- 지연: 조회·미지원 p50 2초 이하, 계산 질문 p50이 기존 8.9초보다 분명히 낮음.

## 단계

1. 새 held-out 커밋(이 계획서와 함께).
2. `calc_extract.py`: 숫자 토큰화, 1·2단계 프롬프트(모듈 항목 설명에서 생성), 파서, 라우터 JSON 조립. 단위 테스트를 먼저 작성한다.
3. `calc_router`: `facts` 극성 처리. 모듈의 사실 판정과 확인 문구 검사를 모순일 때만 거절하도록 바꾼다. 기존 테스트는 유지하고 새 동작은 테스트로 고정한다.
4. `LLM`·`service.py` 연결, 대역 모델 서버의 2단계 처리, 평가 도구 갱신(2단계 호출 수, 새 held-out 묶음).
5. val 재생과 실제 val 실행, 새 held-out 1회, `e2e_live` 3개 시나리오. 결과는 `docs/evals/`에 기록한다.
