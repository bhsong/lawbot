# 통합 일일 수집과 공개 ERP 스냅샷

2026-11-13 KST. 기준 `2f7094b`. PR #138에서 병합했다. [통합 구현 계획](../plans/source-hub-erp-v1.1.md)

1. 기존 monitor 실행 파일에 통합용 소스 선택과 실행 ID 계약을 추가한다. monitor는 단일 정상 실행 행을 남기고 기존 캘린더 import·조문 갱신 점검·요약 순서를 사용한다. 법령 소스가 실효 비활성이면 공용 Git 갱신과 챗봇 조문 점검을 함께 중지한다. 활성 상태에서 수집 주기만 미도래한 경우에는 기존 조문 갱신을 실행한다. ERP·캘린더 수집 범위와 코퍼스 범위 설정은 각각 보존한다.
2. Source Hub는 등록부 버전과 KST 날짜를 실행마다 고정한다. 기관 어댑터·ERP 읽기 전용 수집을 연결하고 OFF·주기 미도래·실패·정상 0건을 각각 기록한다. 같은 날 반복 실행과 단계 중단 후 재개를 시험한다.
3. 기존 v1·v2와 기관 소식을 공개 승인된 자료에서 읽어 하나의 원자적 스냅샷을 발행한다. 공개 캘린더와 후속 이메일은 같은 스냅샷을 읽는다. 실패 시 마지막 정상 자료와 실패 상태를 유지한다. 승인·철회에 따른 갱신은 별도 공개 파일 생성으로 반영할 수 있게 한다.
4. 운영 작업 전환은 별도 단계다. 검증은 합성 저장소, 대역 명령과 임시 DB로 실행한다. 발송 코드는 다음 PR에서 다룬다.
5. PR #138 리뷰에서 확인한 다섯 경로를 검증한다. 통합 기관 수집은 KST 일일 주기를 따르고, API는 저장된 소식의 조회 시점 신선도를 계산한다. 복구는 마지막 발행본을 사용하며, 선택된 국회 수집기와 재활성화된 법령의 개별 커밋 이력을 복원한다.

이메일의 Gmail 발신은 발송 전용 OAuth 범위인 `gmail.send`로 구현할 수 있다. 계정이 허용하면 2단계 인증과 앱 비밀번호를 사용하는 Gmail SMTP도 가능하다. 시험 발신 계정과 자격 증명은 이메일 PR에서 별도로 설정한다. Telegram은 보류한다.
