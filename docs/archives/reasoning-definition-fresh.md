1. 개발 캐시의 법률·하위법령 벡터를 로컬 검증한다. 본 실행에서 현재 모델로 각 캐시의 문서 1개를 확인한다. 불일치하거나 캐시를 읽을 수 없으면 중단한다.
2. 승인 후 개발 웹앱과 같은 검색 코드로 각 질문을 한 번씩 검색한다. 법률 상위 3개, 하위법령 최대 2개를 A에 제공한다. B는 규칙이 선택한 정의 1개를 첫 법률 뒤에 삽입한다. 문맥이 같은 경우 A와 B가 같은 입력을 사용하므로 1회만 생성한다. 문맥이 다르면 각 조건 1회씩 생성하며 짝수 ID는 B부터 실행한다.
3. 순차 1개, 출력 1,024토큰, 대기 상한 300초, 재시도 0회, 전체 10분 상한으로 실행한다. 호출 한도는 캐시 확인 2회, 검색 24회, 생성 6~12회로 총 38회다. 모델·조문·프롬프트·문항을 실행 전후 대조한다.
4. 질문별 1위, 정의 필요 여부, 기존 포함·추가·미발동, 기준 조문 전체 제공과 인용, 답변 원문, 시간·토큰을 기록한다. 내용 판정은 기준 답변의 결론과 핵심 적용을 충족하면 1점, 결론 일부 또는 핵심 조건 일부만 맞으면 0.5점, 핵심 결론이 틀리거나 답을 못 하면 0점이다. 본문 정답과 조문 인용은 별도 집계한다. 기존 근거에 이미 정의가 있으면 보강 효과 집계에서 구분하고, 대조군 발동은 불필요한 첨부로 센다.
