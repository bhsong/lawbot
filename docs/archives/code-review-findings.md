# 2026-11-12 코드 리뷰 수정 계획

첨부 리뷰 F001–F033을 검토한다. 리뷰 기준은 `193c8d9`이며, 작업 브랜치는 `0786d1c`에서 만들었다. 작업 중 문서 PR #121이 병합되어 `origin/main`의 `3b42ee9`로 fast-forward했다. 리뷰 이후 병합된 노동 계산기 변경을 반영해 각 항목을 현재 코드에서 다시 확인한다. 개발 저장소의 `fix/code-review-findings`에서 작업하고 `main` 대상 PR 하나에 변경을 담는다. 저장소의 merge commit 병합 방식으로 PR 전체를 한 번에 되돌릴 수 있게 한다.

기존 계획서는 남아 있는 항목을 확인했다. 계산기 계획에는 새 held-out으로 검증할 후속 작업과 운영 집계가 남아 있고, 캘린더·모니터·법령 범위 계획에도 미완료 항목이 있다.

F003·F019의 제한값은 기존 입력 크기, 현재 대기열 설정과 호출 경로를 대조해 정상 요청을 보존하는 값으로 정하고 PR에 근거를 남긴다. F021은 커서 경계와 기존 이벤트 파일을 유지하는 방식으로 설계하고 되돌림 시 데이터 재작성이 필요한지 확인한다. Vite의 8.3 계열 최소 수정 버전은 8.3.7이다. [공식 보안 권고](https://github.com/vitejs/vite/security/advisories/GHSA-p4f5-76q4-ffq7)

## 검증과 PR

1. 각 결함은 합성 입력과 가짜 모델로 실패하는 회귀부터 작성한다. 현재 기준에서 이미 수정된 항목은 기존 코드와 통과 근거를 기록한다. 날짜, 금액, 인용, UI, HTTP 오류, 수집 재시도에 정상 대조군도 둔다.
2. 조문 생성은 임시 원천과 출력만 사용하고 이전 데이터와의 비교는 읽기 전용으로 한다. 수집·피드백·캘린더 테스트는 임시 DB와 파일을 사용한다. 실제 공유 모델 호출 수는 0회다.
3. `docs/operations.md`와 CI의 기본 pytest 전체, Ruff 검사·포맷, Pyright, 캘린더 스키마, 두 앱의 타입 검사·Vitest·빌드를 실행한다. 브라우저 대역 E2E와 실제 서버 프로세스 통합은 가짜 모델로 실행한다. 결과를 `docs/evals/`에 기록하고 모든 완료 조건이 충족되면 이 계획을 보관 경로로 옮긴다.
4. 전체 기본 검증이 통과한 뒤 수정 파일과 기록만 커밋하고 PR 하나를 연다. 첨부 리뷰 원본은 현재 개발 트리에 미추적 파일로 있으며 보존한다. PR 검증 표에서 실제 모델 E2E·모델 스모크·품질 평가는 실행 안 함으로 표시한다. CI와 PR diff를 확인한 뒤 사용자에게 병합에 필요한 정보를 보고한다.
