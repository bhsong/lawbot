# v5.8.0 운영 반영 준비와 아침 요약 확인

2026-11-13 KST. 운영 기준은 `v5.7.1` (`60d1142`). 다음 버전은 `v5.8.0`이다. PR #139의 검토된 병합 커밋과 main CI를 확인한 뒤 배포 대상을 고정한다. [운영 버전 규칙](../operations.md#운영-버전과-태그)

## 준비 확인

- 현재 06:30 운영 등록은 `law-monitor daily`이며 마지막 종료 코드는 0이다. 2026-11-13 Markdown에는 국회 항목 28건, 모델 호출 0회, 요약 실패 절 없음이 기록되어 있다. 당일 기록으로 Qwen 요약 품질을 판정할 표본은 없다.
- 운영 monitor 상태 DB와 원천 Git 사본, 기존 ERP 자료 DB가 있다. 캘린더는 기존 단독 ERP 파일을 사용 중이다. 통합 공개 파일 연결, 등록부·기관 자료 DB 초기 준비, 새 작업 경로와 권한 대조는 배포 전환 단계에서 수행한다.
- 현재 운영 캘린더 DB는 v8, `quick_check=ok`이고 제거된 이미지 테이블은 0개다. 기존 ERP 승인 항목은 6개다.
- 배포 비교 범위에는 Source Hub, ERP 피드, monitor, 캘린더가 포함된다. 승인 시점의 diff에서 재확인한다. 현재 비교에서 챗봇·모델 서버 코드와 조문 데이터에는 변경이 없다.

## 승인 후 배포 순서

1. 운영 HEAD와 대상 커밋, CI, 운영 로컬 파일, 현행 등록 작업과 입력 경로를 확인한다. 기존 launchd 파일과 비밀 설정을 비공개 위치에 보관하고 monitor·ERP·캘린더 및 기존 공개 파일의 복구본을 확보한다. 캘린더 DB 백업은 현재 v8과 대비표 이미지 부재를 검증한다.
2. 승인된 커밋으로 운영 worktree를 갱신하고 루트·캘린더·ERP·Source Hub의 잠긴 의존성을 준비한다. 캘린더 화면을 빌드한다. 등록부 dry-run으로 기존 법령·조문 점검의 실효 상태를 대조하고, 기관 소스는 확인된 운영 설정을 적용한다.
3. 먼저 기존 피드를 사용한 캘린더의 API와 화면을 확인한다. 같은 작업 라벨에서 기존 06:30 작업을 해제한 뒤 새 통합 작업을 한 개만 등록한다. 다음 06:30 정기 실행에서 공개 파일을 생성하고 확인한 뒤 캘린더에 연결한다. 기존 캘린더 일정·ERP 항목·첨부 링크와 v1·v2·기관 소식의 `X-ERP-Snapshot`을 대조한다. 운영 모델 서버의 설정과 실행 프로세스를 보존한다.
4. 아침 Markdown의 실행 시각, 소스 점검 상태, 법령·행정규칙 이벤트 수, 모델 호출 수, 실패·길이 초과를 확인한다. 모델이 요약한 항목이 있으면 제목·변경점·공포일·시행일·적용 대상을 공식 원문과 대조한다. 국회 목록과 메타데이터 전용 공지는 모델 생성 품질 표본에서 제외한다. 생성 대상 0건이면 다음 적격 실행에서 품질을 확인한다.
5. Gmail 발송 설정은 비활성 상태를 유지한다. 메일 발송을 검토할 때는 공개 스냅샷과 같은 실행의 저장된 Qwen 결과를 사용해 `email-digest --preview`를 먼저 확인한다. 이 명령은 네트워크 요청과 새 추론 없이 본문을 보여 준다. 운영 검증이 끝난 커밋에 annotated `v5.8.0` 태그를 붙인다.

## 복구

새 06:30 작업과 통합 공개 파일 연결을 해제하고 보관한 기존 06:30 등록과 단독 피드 경로를 복원한다. 필요하면 이전 운영 커밋으로 되돌리고 해당 캘린더 자산을 복구한다. 수집 커서와 검토 이력을 보존하고 변경된 운영 데이터의 복원 범위는 실제 장애에 맞춰 확인한다. [통합 실행과 전환](../../services/source-hub/README.md#통합-일일-실행)
