# v5 조문·v5b 임베딩 전환 계획

작성일 2026-11-07. 개발 구현과 검증을 마쳤으며 운영 확인은 별도 반영 승인 뒤 진행한다. [검증 기록](../evals/2026-11-07-v5-transition.md) 기준은 PR #78이 병합된 main `fe90569`다. 기존 개발 트리의 캘린더 문서 변경과 Colab CSV 원본을 보존하기 위해 개발용 worktree를 분리했다. [기존 평가](../evals/2026-11-07-v5b-evaluation.md)

## 개발 설정과 답변 형식

1. `LAWBOT_PROFILE=v5`에서 v5 법률·하위법령 CSV와 매니페스트, `lawbot-emb-v5b`, 인코딩 길이 4,352·5,120을 함께 선택한다. 기존 설정의 v4와 기존 환경 변수는 계속 동작하게 한다.
2. v5의 답변 모델은 기존 `qwen3.8-27b-4bit`를 사용한다. 기본 간결형은 `system_v5_concise.txt`를 쓰고, 전체 형식에는 같은 범위와 인용 규칙을 쓰는 별도 4항목 프롬프트를 둔다. 기존 리랭커와 검색 후보 수, 하위법령 설정은 PR #78의 검증 구성과 맞춘다.
3. 새 설정에서 법률·하위법령 CSV 선택, 매니페스트 검증, 간결형·전체 형식과 조문 표시를 단위·계약·대역 E2E로 확인한다. 기존 v4 경로도 기본 회귀로 확인한다.

## 06:30 조문 갱신과 복구

1. 기존 `law-monitor daily`의 갱신 명령이 웹앱과 같은 프로필을 읽는다. v5는 `scope_tax.csv`와 동일 생성기로 두 CSV를 만들고 v5 매니페스트 이름을 사용한다. v5 live 경로를 `data/live/v5/`로 분리해 v4 데이터와 보관본을 보존한다.
2. 웹앱과 같은 모델·인코딩 설정으로 임베딩 캐시를 만든다. 데이터 구조와 검색 검증을 마친 후보만 보관·전환한다. 같은 live 경로의 갱신·초기화·복구가 서로 겹치지 않게 하고, 실패 뒤 데이터와 매니페스트를 함께 보존하거나 복구한다.
3. 개발 데이터 사본과 별도 캐시에서 범위 내 변경·범위 밖 제외, 캐시 생성과 재사용, 검증 실패 시 바이트 보존, 보관본 복구를 재현한다. 조문 원천은 개발 클론에서 읽고, 운영 launchd와 운영 데이터는 배포 승인 뒤 다룬다.

## 실제 모델 검증과 CSV

- 공유 서버의 상태 조회에서 v5b, 기존 리랭커와 27B가 상주 중임을 확인했다. 승인 전에 실제 요청 명령, 요청 수 상한, 예상 시간·메모리와 운영 영향을 제시한다. 정기 갱신 시간대를 피하고 입력과 동시 실행을 제한한다.
- 실제 모델 E2E는 고정 시나리오 3개를 순서대로 실행한다. 품질 확인은 고정 val에서 노동·세금/보험의 법률·하위법령 각 3건을 골라 기본 간결형을 검증하고, 그중 3건은 전체 형식으로도 확인한다. 표본은 구성 전환 확인용으로 집계한다. PR #78의 3,606문항 검색 결과와 잠정 답변 결과는 기존 기록으로 인용한다.
- 실행 전후의 커밋·모델 revision·조문과 프롬프트 해시·설정을 기록하고 대조한다. 추론은 순차 실행, 최대 출력 1,024토큰, 응답 대기 300초, 자동 재시도 없이 진행한다.
- Colab CSV 원본 5개와 새 실행에서 생성한 문항별 검색·답변·집계 CSV를 `results/v5/`에 보존해 PR과 평가 기록에서 연결한다. 임시 실행 스크립트와 로그는 정리한다.

## 완료 기준

- 기본 테스트 전체와 CI 정적 검사·프런트엔드 검사·빌드 통과. 승인받은 개발 실제 모델 확인 결과와 한계를 기록하고 main 대상 PR을 만든다.
- 병합 확인과 별도 운영 반영 승인 후 운영 HEAD 차이, 캘린더 DB 등 선행 변경의 반영 범위, 기존 서비스 설정을 확인한다. 기존 v4 복구 경로를 남기고 웹앱을 v5로 전환해 상태를 점검한다. 다음 06:30 실행의 종료 상태, v5 데이터 범위와 웹앱 상태를 확인한다.
