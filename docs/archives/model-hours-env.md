# 모델 서버 운영 시간을 .env 한 곳에서 관리

## 목표

운영 시간은 앞으로 자주 바뀐다. 운영 `.env`의 `LAWBOT_MODEL_HOURS` 한 줄만 고치면 모델 서버 시작·정지 시각과 웹앱 안내가 함께 바뀌게 한다. plist 수정, 웹앱 재시작, 스크립트 인자 변경은 필요 없게 한다. v6.8.0([계획](model-hours.md))의 후속이다.

## 요구사항

- R1. 예약 스크립트 `deploy/model-hours/lawbot-model-hours apply`는 운영 시간을 운영 트리 `.env`의 `LAWBOT_MODEL_HOURS`에서 읽는다(`--hours`가 주어지면 그 값이 우선). 이 키 하나만 읽고, 다른 키나 값을 출력·기록하지 않는다. 키가 없거나 비어 있으면 시간 제한 없음(항상 운영)으로 보고 두 서버를 올린다. 형식이 틀리면 아무것도 바꾸지 않고 실패를 기록한다.
- R2. launchd 템플릿은 매시 정각과 30분(`StartCalendarInterval`의 `Minute` 0과 30, 시각 지정 없음)과 `RunAtLoad`로 `apply`를 실행한다. 운영 시간은 보통 정각이나 30분 단위로 정하므로 그 시각에 바로 반영된다. 다른 분 단위 시각을 쓰면 다음 정각·30분에 반영된다.
- R3. `apply`는 현재 상태가 목표와 같으면 아무것도 하지 않고 로그도 남기지 않는다. 운영 시간 안이고 두 서버가 모두 등록돼 있으면 그대로 두고, 밖이고 둘 다 해제돼 있으면 그대로 둔다. 상태가 바뀔 때만 `start`·`stop`을 실행하고 결과를 한 줄 남긴다. 30분마다 `check_deploy`가 돌거나 로그가 쌓이면 안 된다.
- R4. 준비 마감은 운영 시작 시각 + 25분이다(`--deadline`이 주어지면 우선). 시작 직후가 아닌 때(로그인, 수동 시작, 시간을 바꿔 바로 시작)는 기존처럼 한 번만 짧게 확인한다.
- R5. 웹앱은 질문을 받을 때 `.env`가 바뀌었는지(수정 시각) 확인하고, 바뀌었으면 `LAWBOT_MODEL_HOURS`만 다시 읽어 안내 판정과 문구에 쓴다. 재시작이 필요 없다. 새 값의 형식이 틀리면 직전 값을 유지하고 경고를 한 번 기록한다. 다른 설정은 지금처럼 시작 때만 읽는다. 기존 `lawbot.envfile` 파서를 사용한다.
- R6. 문서: `docs/operations.md`의 운영 시간 절을 "`.env` 한 줄 수정 → 다음 정각·30분에 서버, 웹앱 안내는 다음 질문부터 반영"으로 고친다. 운영 시작이 06:25 이후이면 06:30 daily의 조문 갱신·요약이 모델 없이 실패한다는 주의를 적는다. 예약 재설치 절차(plist 교체: bootout 후 bootstrap)도 적는다.

## 테스트

- 스크립트(가짜 `launchctl`·`uv`, 임시 `.env`): `.env` 값으로 시간 분기, `--hours` 우선, 키 없음·빈 값은 항상 운영, 형식 오류 시 변경 없음과 실패 기록, 상태가 같으면 `launchctl bootstrap`·`bootout`·`check_deploy` 호출 0회와 로그 0줄, 시작+25분 마감. `.env`의 다른 키 값이 출력·로그에 나오지 않음.
- 웹앱: `.env` 수정 시각이 바뀌면 다음 질문부터 새 시간으로 판정, 형식 오류 시 직전 값 유지, 바뀌지 않으면 파일을 다시 파싱하지 않음.
- 대역 E2E: 실행 중인 웹앱의 `.env` 시간을 바꾼 뒤 재시작 없이 안내가 바뀌는지.
- 전체 기본 테스트, 린트, pyright.

## 운영 반영 (승인 받음: 2026-11-28, 06:00–21:00으로 변경)

1. 병합 커밋을 반영하고 웹앱을 재시작한다(운영 시간 안, 21:00 전).
2. 새 plist로 교체한다: `launchctl bootout gui/<uid>/com.lawbot.model-hours` → 템플릿으로 다시 생성 → `bootstrap`.
3. 운영 `.env`를 `LAWBOT_MODEL_HOURS=06:00-21:00`으로 고친다. 로그와 `status`로 반영을 확인한다.
4. 21:00 이후 첫 정지(21:05 점검)와 다음 날 06:00 시작·06:30 daily(06:41 점검)를 확인한다.
5. 버전: 기능 개선이므로 Z 자리(v6.8.1).
