# 수집·캘린더·답변용 법령 범위 통합

2026-11-10 KST · `refactor/law-scope-single-source` · 기준 `5a75f20`

## 목표와 범위

챗봇 v5가 사용하는 노동 법률 7개와 세금·보험 법률 10개, 총 17개를 수집 및 정기 캘린더 import의 공통 기준으로 삼는다. 기존 수집 설정은 13개 법령을 열거하고 국회 제목 필터를 따로 둔다. 공통 범위를 적용하면 부가가치세법은 법령 수집과 정기 캘린더 import에서 빠지고, 남녀고용평등법·기간제법·파견법·임금채권보장법·농어촌특별세법이 추가된다. 기존 법령 분류를 보존하고 추가 법령 5개에 일반 법령 본문 분류(1)를 부여한다. 이미 저장한 모니터 이벤트·캘린더 스냅숏과 수동 이관 경로는 보존한다.

## 설계

- `packages/lawbot-common/src/lawbot_common/law_scope.json`에 정식 법령명(`name`), Legalize KR 폴더명(`folder`), 수집 분류(`category`), 국회 제목 키워드(`keywords`)를 순서대로 기록한다. 패키지 리소스로 읽고 필수 값, 중복과 데이터 형식을 검증한다. 독립 캘린더 환경은 같은 공통 패키지를 로컬 의존성으로 설치한다.
- 기본 monitor 설정은 공통 폴더·분류와 국회 키워드로 법령·국회 수집 범위를 구성한다. 별표·서식과 행정규칙 규칙은 별도 설정으로 유지하고 부가가치세법 시행규칙의 별표·서식 항목을 뺀다.
- 정기 캘린더 sync는 등록된 법령 이벤트의 Legalize KR 경로와 국회 이벤트 제목을 각각 공통 폴더·정규화한 키워드로 검사한다. 등록 검증, 소스별 import, 본문 동기화와 수동 import는 기존 경로를 사용한다.
- 조문 생성기에 `--scope`를 지정하면 그 CSV가 공통 목록의 법령 중 어느 법령을 선택 조문으로 넣을지 정한다. 그 CSV에 없는 등록 법령은 공통 목록 순서대로 법률과 존재하는 하위법령의 전체 조문을 넣고, 선택 조문은 기존 순서 규칙으로 그 뒤에 붙인다. CSV가 직접 지정한 문서는 필요하다. `--scope` 생략 시에는 `data/v5/scope_tax.csv`에 있는 법령을 전체 조문 대상에서 빼고, 나머지 노동 법령 7개만 넣어 기존 v4를 재현한다. 표준 v5 생성과 v5의 CSV·DB 모드 자동 갱신은 `data/v5/scope_tax.csv`를 사용하며 이 CSV에 있는 법령이 공통 목록에 있는지 검증한다. 동일 원문·기준일의 표준 v4/v5 문서와 행 순서를 보존한다.

## 검증 순서

1. Red에서 새 법령이 기본 수집 범위에 들어오는지, 부가가치세법 법령·국회 이벤트가 정기 import에서 걸러지는지, 조문 생성 문서 목록을 공통 설정으로 바꿀 수 있는지 확인한다. 기존 코드가 새 계약을 어기는 실패를 확인한다.
2. 공통 매니페스트와 서비스 연결을 적용한다. 정식명과 폴더명이 다른 법령, 국회 제목의 공백·별칭, 잘못된 매니페스트와 범위 CSV를 다룬다. 정기 sync에서 입력만 걸러지고 기존 DB 행이 보존되는지 임시 monitor home과 캘린더 DB로 확인한다.
3. 명시한 범위 CSV에 따라 법령의 전체·선택 조문 구분이 바뀌는지 검증한다. 공통 설정 도입 전후의 표준 v4/v5 문서, 선택 조문, 순서와 생성 CSV를 비교하고, 기존 소스 등록·재관측 계약과 두 자동 갱신 경로를 회귀 검증한다.
4. 기본 테스트 전체(단위·계약·통합·대역 E2E)와 린트·타입 검사·스키마·프런트엔드 검사·빌드를 실행한다. `e2e_live`, `models`, 품질 평가는 실행 안 함으로 기록한다.

## 운영 반영 시 확인

변경 파일과 서비스 import 경로를 기준으로 독립 캘린더 환경 설치, 서비스 재시작 여부와 다음 정기 수집 확인 절차를 PR에 기록한다. 격리 개발 체크아웃에서 합성 수집 데이터와 로컬 Legalize KR 원천으로 검증한다.

- Legalize KR 수집은 저장 커서가 현재 원천 HEAD와 같거나 그 조상이면 기존 커서부터 새 범위를 적용한다.
- 국회 키워드 변경은 기준점 지문을 바꾼다. 운영 반영은 06:30 KST daily가 정상 종료한 것을 확인하고 06:50 KST 이후 가능한 한 빨리 진행한다. 새 코드에서 `assembly_bill`과 `assembly_notice`에 각각 `bootstrap --only <수집기> --force`를 이어서 실행한다.
- 강제 bootstrap은 기존 항목의 revision을 유지한 채 현재 내용으로 비교 기준을 갱신한다. 마지막 정상 관측과 각 bootstrap 사이에 발생한 변경은 이벤트 없이 기준에 흡수될 수 있다. 마지막 정상 수집의 종료와 각 기준 갱신의 시작·종료 시각을 기록한다. 기존 항목의 기준 갱신 전후 내용을 대조하고, 누락을 확인하면 반영 방법을 정한다.
- 운영 담당자가 PR #107 리뷰에 공유한 읽기 전용 확인에서는 monitor 기본 설정을 사용하고 있었으며 신규 범위의 기존 캘린더 스냅숏은 0건이었다. 반영 시점에 이 상태가 달라졌다면 격리 사본에 해당 입력을 넣어 sync를 먼저 재실행한다. 동일 항목·revision의 ID와 저장 내용, 본문 동기화 결과를 대조한다. 이번 작업의 재현은 개발 환경에 한정한다.
