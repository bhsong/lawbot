# 조문 생성기의 필수 하위법령 검증

2026-11-10 KST · `fix/build-articles-required-decrees` · 기준 `cda1b33`

## 문제와 목표

PR #107은 사용자 범위 CSV를 적용할 때 실제로 존재하지 않는 하위법령도 처리할 수 있게 했다. 전체 포함 법령의 하위법령을 조회하지 못하면 생략하는 규칙은 제목 불일치나 원천 파일 누락에도 적용된다. 이 경우 조문 생성과 자동 갱신이 일부 문서를 빠뜨린 결과를 정상으로 처리할 수 있다. [공통 법령 범위 계획](law-scope-single-source.md)

## 구현

- 공통 `law_scope.json`의 등록 법령마다 `decrees`에 전체 포함 시 필요한 하위법령 종류를 기록한다. 개발 Legalize KR 원천에서 대조한 기준은 시행령 17개와 시행규칙 16개다. 농어촌특별세법은 시행령만 등록한다. 새 하위법령을 전체 포함 범위에 넣을 때 해당 목록을 갱신한다.
- 전체 포함 법령은 본법과 `decrees`에 선언한 문서를 생성 대상으로 삼는다. 범위 CSV가 명시한 문서도 필수다. 생성 대상마다 기준일의 제목이 일치하는 유효 파일을 정확히 하나 찾아야 한다. 파일이 없거나 제목이 달라졌거나 후보가 여러 개면 오류로 중단한다. 실제로 없는 하위법령은 전체 포함 대상 목록에서 생략한다.
- 문서 존재를 판단할 때 기존 기준일 조회와 메타데이터 검증을 사용한다. 필수 문서 목록은 매니페스트에서 읽으므로 별도의 원천 이력 탐색이 필요 없다. 표준 v4/v5의 생성 범위와 순서, 사용자 범위 CSV가 전체·선택 조문을 나누는 규칙을 보존한다.

## 검증 순서

1. 합성 Git 원천에서 이전에 존재한 시행령의 제목 변경 또는 파일 삭제를 재현한다. 기존 코드는 생성 성공으로 처리하고, 수정 후에는 해당 문서를 명시한 오류로 실패해야 한다.
2. 하위법령이 없는 전체 포함 법령은 본법을 생성하고, 범위 CSV가 직접 요구한 문서가 없으면 실패하는지 확인한다. 필수 하위법령을 정상 조회하는 경우와 제목이 같은 후보가 여럿인 경우도 확인한다.
3. 선언한 하위법령이 누락된 합성 원천으로 실제 CSV 모드 `lawbot-articles-update`를 실행한다. 모델 호출 없이 종료 코드 2로 실패하고, 임시 활성 CSV와 매니페스트가 실행 전과 바이트 단위로 같은지 확인한다.
4. 같은 로컬 Legalize KR 커밋·기준일로 표준 v4/v5의 CSV와 임시 DB 릴리스를 변경 전후 비교한다. 파일·조문 순서와 해시가 동일해야 한다.
5. 기본 시험 전체와 린트·타입·스키마·빌드를 확인한 뒤 PR을 연다. `e2e_live`, `models`, 품질 평가는 실행 안 함으로 기록한다.

## 운영 반영 시 확인

PR #107과 이번 수정을 함께 반영할 때 검증한 운영 커밋에 `v5.2.3` (Z, 버그 수정)을 한 번 태그한다. 운영 기준부터 PR까지의 변경 파일과 서비스 import 경로를 기준으로 설치·재시작 여부를 기록한다. 검증은 격리 개발 체크아웃, 합성 Git 원천과 임시 DB에서 진행한다.
