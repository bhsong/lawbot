# 계획 — 시맨틱 캐시·원자 질문 RAG 제거

- 기준 `main` `fe30077` (#155). [상위 계획](reviewed-question-suggestions.md)의 §3 PR A와 §6-1을 구현했다. 추천과 val 라벨 파일 이름 변경은 PR B에서 진행한다.
- 기존 코드에서 시각과 요청 ID를 고정한 웹 응답, SSE, 요청 로그를 캡처한다. 스키마 2와 통과 ZIP 개발 명령의 회귀 테스트를 먼저 추가한다.
- 웹앱 연결과 개발 인덱스·원자 적재 코드, 스키마 3을 걷어낸다. 정확 일치 캐시와 P07 관리·이월 경로는 유지한다.
- 초기 마이그레이션에서 항상 0으로 유지되던 열을 제거했다. 기존 DB는 원본 0001 체크섬과 마이그레이션 이력을 유지한 채 스키마 2로 읽힌다.
- `cache_seed` 개발 명령에서 고정 SHA-256의 통과 ZIP을 읽고 현행 근거 해시, 계산 질문, 보호 분할과 기존 리비전 충돌을 확인한다. 적재와 감사는 한 트랜잭션으로 처리한다. 기존 승인 ID와 보호 지문을 보존하고 첫 적재로 승인할 때만 새 승인 ID를 등록해 일반 `set-mode`를 사용한다.
- ZIP 없이 시작하고 조회·관리하는 런타임 테스트를 유지한다. 기본 pytest, Ruff, Pyright, 챗봇·캘린더 프론트 검사와 빌드를 실행한다. 개발 코퍼스와 캐시 DB 사본에 실제 통과 ZIP을 적재하고 재실행하여 결과를 대조한다. PR에는 집계만 기록한다.
- 운영 파일과 DB를 사용하지 않고 실제 모델 호출 없이 검증한다. 전체 Green 후 작업 브랜치를 푸시하고 `main` 대상 PR을 생성한다.
