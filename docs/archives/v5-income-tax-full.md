# v5 소득세법 전체 조문 추가

상태: 완료 (2026-11-11). 재학습 없이 v5.4.0(`9b3c60f`)으로 운영에 반영했다. [검색 평가](../evals/2026-11-11-v5-income-tax-eval.md) · [운영 반영](../evals/2026-11-11-deploy-v5.2.3-v5.4.0.md)

- 기준 브랜치는 2026-11-10에 원격과 대조한 `main` `0f214d0`이다. 작업 브랜치는 `feat/v5-income-tax-full`이다.
- 모델 재학습 없이 적용하는 경우 앱 버전은 v5.4.0 예정이다. 조문 프로필과 매니페스트의 `dataset_version`·`trained_on.embedding`은 v5를 유지하며, 새 코퍼스는 CSV SHA-256으로 구분한다.
- [기존 v5 계획](../archives/v5-tax-scope.md)은 보관했다. [나머지 법령 계획](../plans/tax-full-scope-remaining-laws.md)은 후속 작업으로 둔다.

## 변경과 검증 순서

1. 합성 Legalize KR 저장소에서 전체 포함 조문 ID를 대조하고, 현재 v5에서 소득세법 계열을 제외한 행의 내용과 상대 순서를 고정하는 시험을 먼저 작성한다. `--scope` 없는 v4 생성도 노동 7개 법령을 유지하는지 확인한다.
2. `data/v5/scope_tax.csv`에서 소득세법 계열을 모두 뺀다. v5는 공통 법령 목록에 선언된 법률·시행령·시행규칙을 전체 포함한다. `--scope` 없는 v4의 범위는 고정 v4 매니페스트의 법령으로 결정해 v5 선택 목록 변경이 v4에 전파되지 않게 한다. 문서의 정렬 규칙은 기존대로 적용한다.
3. 기존 v5와 같은 Legalize KR `bcb7aea7782e81c21fbeb08382c442f7c2041690`과 기준일 2026-11-03으로 재생성한다. 사용자가 제공한 CSV는 조문 ID와 삭제 표시에만 사용한다. 기존 선택 조문과 제공 CSV의 합집합을 비교하고, 생성기 규칙에 따른 삭제 및 부칙 특례와 시행일 차이를 조문별로 기록한다.
4. 두 조문 CSV와 매니페스트를 생성하고 `lawbot-max-seq --counts`로 토큰 수와 v5 기본값을 확인한다. 질문·정답·분할 파일을 고정하고 기본 테스트, 린트, 타입 검사, 빌드가 모두 통과한 뒤 PR을 연다.

## 토큰 상한

법률 최장은 소득세법 제104조 4,251토큰이고 하위법령 최장은 소득세법 시행령 제167조의3 11,863토큰이다. v5 기본값은 법률 4,352, 하위법령 5,120을 유지한다.

emb-v5b는 5,120토큰으로 학습했다. 리랭커의 2,560토큰 상한은 질문과 지시문을 포함한 별도 입력에 적용된다. 아래 비율은 전체 임베딩 문서 토큰 중 5,120을 초과하는 몫이다. 첨부된 조문은 전체 본문을 답변 프롬프트에 제공하므로 긴 조문이 첨부되면 생성 입력도 길어질 수 있다. [임베딩 학습 기록](../evals/2026-11-05-v5-embedding-train.md)

| 조문 | 전체 토큰 | 5,120 초과 토큰 | 잘림 비율 |
| --- | ---: | ---: | ---: |
| 소득세법 시행령 제167조의3 | 11,863 | 6,743 | 56.84% |
| 소득세법 시행령 제155조 | 10,017 | 4,897 | 48.89% |

`lawbot-max-seq --training-max-seq 5120 --counts`는 실제 최장 길이와 조문별 토큰 수를 그대로 기록한다. 권장값은 최장 길이의 256 단위 올림과 학습 상한 중 작은 값이며, 학습 상한을 넘는 모든 비삭제 조문의 잘림을 보고한다. 옵션을 생략하면 기존의 올림 규칙을 적용한다.

## 운영 반영

운영은 DB 코퍼스를 사용한다. 운영에서 PR을 checkout하면 다음 06:30 `law-monitor daily`가 같은 작업 트리의 `lawbot-articles-update --restart`를 호출한다. 절전 중 예약을 놓치면 깨어날 때 실행될 수 있다. 갱신기는 새 `scope_tax.csv`와 그날 원문을 사용해 새 릴리스를 만들고, 임베딩과 변경 조문 자체 검색을 검사한 뒤 활성 릴리스를 바꾸고 정확 일치 캐시를 재판정하고 웹앱을 재시작한다. 자체 검색은 변경 조문이 그 조문 본문으로 상위 10개 안에 드는지 확인한다. 승인된 val 비교 전 checkout하면 평가 전 코퍼스가 활성화되고, 변경된 법률·하위법령 파트 전체 임베딩과 추가·변경 조문별 검사 요청이 06:30에 공유 서버로 몰릴 수 있다. 당일 시행 개정도 함께 들어갈 수 있다.

검색 평가 결과와 운영 반영을 사용자에게 승인받은 뒤 06:20–06:50 밖의 배포 시간을 정한다. monitor 작업이 끝난 것을 확인하고 이전 운영 커밋, 활성 릴리스 ID·해시와 복구용 백업을 확보한다. 명시적인 `LAWBOT_DECREE_MAX_SEQ` 설정이 있으면 5,120을 사용하는지 확인한다. 이때 `law-monitor check`도 갱신을 호출할 수 있으므로 실행 상태는 스케줄러와 작업 로그에서 확인한다. 새 커밋을 checkout한 직후 운영 작업 트리에서 아래 갱신을 한 번 실행한다.

```zsh
uv run lawbot-articles-update --repo services/monitor/data/repos/legalize-kr --report-dir services/monitor/data/articles --restart
```

갱신 완료는 종료 코드 1, 무변경은 0, 오류는 2다. 보고서의 변경 조문·검색 검사·캐시 유지/검토 대기/끔·재시작 결과를 확인하고, `uv run python -m lawbot.check_deploy`와 웹앱에서 활성 릴리스·해시·조문 수·응답을 대조한다. 문제가 생기면 이전 커밋으로 돌아가 다음 예약 실행의 재적용을 막고, 새 릴리스가 활성 상태면 `uv run lawbot-articles-update --rollback --restart`로 이전 릴리스로 복구한다. 재시작 실패는 갱신기가 자동 복구하므로 활성 릴리스를 확인하고 수동 복구 여부를 정한다.

`--restart`를 생략해도 DB는 전환된다. 기존 DB 이관 도구는 비활성 릴리스를 적재할 수 있지만 운영 갱신기의 모델 검사, 캐시 판정, 재시작 절차가 빠져 있다. 위 절차는 현재 갱신기의 전체 경로를 사용한다. 코퍼스 롤백 후에도 이전 전환에서 검토 대기로 이동한 캐시는 재승인이 필요할 수 있으므로 캐시 상태를 별도로 확인한다.

개발 환경의 실제 승인 스냅샷은 없었고 P07 개발 기록의 실제 승인은 0건이었다. 개발 기준·후보 CSV를 넣은 임시 코퍼스 DB와 별도 임시 정확 일치 DB에서 합성 승인 5건으로 활성화·이월·조회 경로를 실행했다. 소득세법·시행령·시행규칙 제1조 근거 답변 3건은 같은 법령 문서의 조문 추가(`related_law_changed`)로 검토 대기 및 검색 전환, 근로기준법과 조세특례제한법 제1조 근거 답변 2건은 유지 및 적중, 끔은 0건이었다. 기존 비삭제 조문의 캐시 비교 필드 변경은 0건이다. 이 집계는 개발 합성 표본이다.

## 승인 후 검색 평가

[Stage 4A](../evals/2026-11-05-v5-stage4a-emb5.md)와 [v5b 결과](../evals/2026-11-07-v5b-evaluation.md)의 명령과 val 문항을 사용한다. 개발 CSV 모드에서 기준과 변경 조문 파일을 환경 변수로 각각 지정한다. 개발 `.env` 파일 편집 없이 셸 변수 `LAWBOT_PROFILE=v5`, `LAWBOT_EMB_MODEL=lawbot-emb-v5b`, `LAWBOT_V5_ARTICLES`, `LAWBOT_V5_DECREE_ARTICLES`, `LAWBOT_DECREE_MAX_SEQ=5120`를 해당 평가 프로세스에만 적용한다. 하위법령 상한은 두 코퍼스에 동일하게 쓰며 기존 최장 5,079토큰도 전부 들어간다. 리랭커·하위법령 첨부를 켜고 평가 시작 전 기존과 같은 설정인지 확인한다. 기준과 변경에 고유 태그를 준다.

```zsh
uv run lawbot-eval-v4 retrieval --split val --dataset v5 --tag <tag>
uv run lawbot-eval-v4 decree-retrieval --split val --dataset v5 --tag <tag>
```

코퍼스당 법률 1,977문항(노동 1,110, 세금·보험 867), 하위법령 1,629문항(노동 444, 세금·보험 1,185)으로 총 3,606문항이다. 법률 임베딩 후보 10개와 리랭킹 3개, 하위법령 후보 10개와 첨부 상한 2개·임계값 0.9를 유지한다. 법률과 하위법령에서 임베딩 R@3·MRR@10, 리랭킹 R@3과 하위법령 첨부율을 비교한다. 승인 후 평가용으로 기존 연산에서 후보 ID와 정답 순위를 저장해 하위 임베딩 지표와 탈락 문항을 계산한다. 빠진 문항마다 정답 순위와 앞선 조문을 기록하고 새 조문이 앞선 경우를 구분한다.

### 기준 결과 재사용 검토

11-07 전체 검색의 기준 CSV 해시(법률 `bd1633defcaf`, 통합 `a379d1193dcf`)와 질문·분할은 이번 비교 기준과 일치한다. 당시 `1b24df1`부터 검색기·평가 도구에 추가된 CSV 로딩과 해시 기록은 순위 계산을 바꾸지 않았다. 기록된 emb-v5b·리랭커 revision은 평가 시작 때 대조한다.
