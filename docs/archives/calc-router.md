`feat/calc-router`는 원격 `main`의 `9b3c60f`에서 시작했다. #112·#114 병합 후 기준을 `57dba43`으로 갱신했다. 앱 버전 구분은 `y`이며 배포 순서상 v5.5.0 예정이다.

기존 계획을 대조했다. #112의 검색 평가와 운영 반영 기록, #114에서 보관한 [소득세법 전체 조문 계획](../archives/v5-income-tax-full.md)을 반영했다. `tax-full-scope-remaining-laws.md`는 후속 범위, `LAW_CALENDAR_PLAN.md`는 실데이터 검증, 모니터 수집기 계획과 원 계획서는 입법예고 수집·리마인드 작업이 남아 현 위치에 둔다. 기존 개발 트리의 미커밋 평가 기록은 별도 복제본으로 격리했다.

1. 의료비 세액공제와 기본 공제 범위의 중도정산 근로소득세를 순수 함수로 계산한다. 적용 연도별 법정 수치와 조문 해시는 v5 기준 데이터에 넣고 활성 CSV 또는 DB 릴리스와 대조한다. 결과가 바뀌는 누락·모호한 입력은 필요한 값과 조문을 안내한다.
2. 합성 val에서 고른 결정적 게이트를 웹앱과 캐시에서 공유한다. 후보만 기존 Pro API에 JSON을 한 번 요청하고 입력의 원문 구간을 검증한다. 캐시 조회·seed·승인에서 후보를 제외하고 기존 항목은 조회 및 관리에서 끈다. 계산기 이름·상태·라우터 사유·지연·사후 검사만 계산 메타데이터로 기록한다.
3. 계산 또는 미지원 계산은 기존 답변 생성 프롬프트에 계산표 또는 안내 지시를 추가한다. SSE로 모델 응답보다 먼저 입력과 단계 표를 보내고 결론의 금액이 다르면 화면에 경고를 표시한다. 게이트를 통과한 조회 질문은 `kind: lookup`으로 분류해 기존 RAG 프롬프트와 화면을 사용한다. 캐시 제외는 공용 게이트 판정을 따르며, 게이트 통과 전후의 프롬프트 바이트와 호출 수를 시험에서 고정한다.
4. 손으로 검산한 계산기별 10건 이상, 원문 구간·숫자 파싱, 프롬프트와 서버 API 계약, 캐시와 코퍼스 전환, 390px·1280px 브라우저 경로를 TDD로 확인한다. 기본 테스트 전체, 린트, 타입 검사, 빌드가 통과한 후 PR을 연다. 실제 모델 E2E, 모델 스모크, 품질 평가는 실행 안 함으로 기록한다.

## 적용 범위

- 법정 수치 파일은 2026년 귀속을 지원한다. 귀속연도가 없으면 서울의 현재 연도를 적용하고 입력 표에 기본값을 표시한다. 지원 데이터에 없는 연도는 안내로 전환한다.
- 의료비는 제59조의4제2항 순서에 따라 총급여 3% 문턱을 적용한다. 일반 부양가족은 문턱 차감 후 700만 원을 한도로 한다. 대상 구분 또는 실손보험금 배분을 달리해도 결과가 같은 경우 계산한다.
- 중도정산에서 건강·장기요양·고용보험료가 입력되면 A(제52조 보험료 공제, 표준세액공제 0원)와 B(보험료 공제 생략, 표준세액공제 13만 원)를 비교한다. 연금보험료공제는 두 경우 모두 적용한다. 결정세액이 낮은 쪽을 선택하며 동률이면 A를 선택한다. 표에 양쪽의 과세표준·산출세액·결정세액과 선택을 표시하고, 지방소득세와 환급·추가납부에는 선택한 세액을 사용한다. [소득세법 제52조제1항](https://www.law.go.kr/LSW/lsLinkCommonInfo.do?chrClsCd=010202&lsJoLnkSeq=1033240143) · [제59조의4제9항](https://www.law.go.kr/lsLinkCommonInfo.do?lsJoLnkSeq=1032011667)
- 건강·장기요양보험료를 합산 금액으로 제시하면 한 항목으로 읽고, 추출에서 빠지면 합산 금액을 안내한다.
- 라우터는 기존 `LAWBOT_MODEL_READ_TIMEOUT`을 따른다. 서버가 대기열 포화로 거부한 경우와 전송 단계별 타임아웃을 구분한다. 라우터 오류에는 일시적인 계산 판정 실패를 표시하고 답변 모델에는 계산에 필요한 정보와 근거 조문 안내를 지시한다. 비스트리밍 API는 읽기 타임아웃 시 서버 대기와 생성 중 어느 단계였는지 알려 주지 않는다.
- 활성 코퍼스와 웹앱이 로드한 조문의 본문을 대조한다. 조문이 누락되거나 해시가 다르면 관련 계산기만 끈다. CSV에서 의료비 시행령을 읽으려면 통합 CSV가 필요하다.

## 평가

합성 val 100문항을 고정했다. 게이트 후보는 계산형 80문항과 조회형 6문항이며 게이트 밖 비계산 대조군은 14문항이다. 게이트만 확인하는 명령은 `uv run python -m lawbot_tools.eval_calc_router`이다.

별도 승인 후 개발 CSV v5 설정으로 아래 명령을 실행한다. 라우터 자체 진단은 비계산 대조군까지 포함한 100회다. 게이트를 통과한 조회 1건을 포함한 표본 8건은 라우터 적용 경로와 기존 RAG 경로를 각각 실행한다. 라우터 8회, 답변 생성 16회, 검색 임베딩·리랭킹 최대 64회, 인덱스 준비 최대 2회까지 추론 요청은 최대 190회다. 준비·모델 목록 조회는 별도다. 예상 시간은 30–75분이며, 동시 요청 1개로 06:20–06:50 KST를 피한다. 라우터 지연 p50·p95와 표본별 첫 토큰·첫 글자 지연 차이를 기록한다.

```sh
uv run python -m lawbot_tools.eval_calc_router --live --output /tmp/lawbot-calc-router-val.json
```

### 2차 실제 모델 평가

1차 실행 커밋은 `ff4f2ac`이다. 실제 답변의 결론 검사와 모호한 입력의 원출력을 재생해 먼저 모델 호출 없이 수정한다. 이어서 미지원 계산과 조회를 구분하는 라우터 system 문장만 한 번 수정한다. 실행 전 리뷰에 따라 기존 미지원 예시인 일반 연말정산과 퇴직소득세를 복원한다. 실행 범위와 시간을 사용자에게 알리고 승인받은 뒤, 로컬 기본 테스트 전체와 린트 및 푸시된 평가 커밋의 CI 통과를 확인한다. [1차 실행 기록](../evals/2026-11-11-calc-router-live.md) · [실행 전 리뷰](https://github.com/bhsong/lawbot/pull/113#issuecomment-6784804010)

같은 합성 val 100문항을 라우터에 직접 보내고, 같은 8문항에서 라우터 적용과 기존 RAG 답변을 번갈아 비교한다. 레포 밖 임시 실행 스크립트에서 추론 POST 최대 190회, 동시 요청 1개, 자동 재시도 없음, 06:20–06:50 KST 제외를 적용한다. 준비 상태와 모델 상주를 먼저 확인하고 시작·종료 구성을 비교한다. 개발 CSV v5를 사용하고 운영 설정·DB는 건드리지 않는다. 1차 23분 6초를 기준으로 20–35분을 예상하며, 실행 전 이 맥의 동시 고부하 작업을 확인해 있으면 기록한다.

1차와 같은 라우터·첫 토큰·첫 모델 글자 지연에 더해 요청 시작부터 `calculation` 이벤트까지의 시간을 기록한다. 계산 답변 표본 5건의 사후 검사 결과도 각각 기록한다. 기대값은 모두 `match`다.

| 판정 항목 | 새 프롬프트 유지 기준 |
| --- | --- |
| 계산 결과 금액 | 출력된 모든 금액이 독립 검산과 일치하고 틀린 금액 0건 |
| 미지원 계산 | 17/20 이상 (1차 14/20) |
| 게이트를 통과한 조회 | 6/6 유지 |
| 의료비 | 19/20 이상 |
| 중도정산 | 18/20 이상 |
| 필수 입력 누락 | 9/10 이상 |
| 모호한 입력·미지원 연도 | 수정 후 재생 기준 10/10 (원출력 6건과 1차 성공 문항의 합성 응답 4건) |

모든 기준을 충족하면 새 프롬프트를 유지한다. 하나라도 미달하면 문항군별 결과를 보고하고, 추가 프롬프트 수정이나 평가 재실행 없이 사용자의 되돌림 결정을 기다린다.

### 2차 평가 후 수정

사용자 결정에 따라 라우터 프롬프트를 유지하고 확인은 원출력 재생과 대역 시험으로 끝낸다. 두 계산기에 공통으로 금액 항목의 동일 원문 문자열 사용 횟수를 기존 금액 경계를 충족하는 등장 횟수와 비교한다. 사용 횟수가 더 많으면 모호한 입력 안내로 보낸다. CR092, 같은 금액을 두 번 적은 의료비 질문, 합계 하나를 두 번 추출한 중도정산 질문으로 확인한다. [사용자 결정](https://github.com/bhsong/lawbot/pull/113#issuecomment-6785592332) · [재생 기록](../evals/2026-11-11-calc-router-live.md#2차-평가-후-수정)

2차에서 미지원 계산 6건(CR041·CR043·CR048·CR050·CR052·CR057)이 조회로 분류됐다. 노동 계산기 PR에서 라우터 프롬프트를 수정하고 실제 모델 평가로 확인한다.

금액 중복 검사는 `700만원`과 `700만`처럼 서로 다른 문자열을 각각 센다. 두 문자열이 같은 금액의 원문을 가리키면 재사용이 남을 수 있다.

## 운영 반영

병합과 운영 반영 승인 후 챗봇 프런트엔드에서 `npm ci && npm run build`를 실행한다. [정확 일치 캐시 절차](../operations.md#p07-정확-일치-캐시)의 `exclude-calculations`로 초안·승인 개수와 ID를 기록하고, DB 백업 후 `--apply`로 기존 활성 플래그를 끈다. 웹앱을 재시작하고 `uv run python -m lawbot.check_deploy`에서 계산기별 조문 해시 상태와 캐시 집계를 확인한다.

개발의 합성 DB에서는 초안 1건과 승인 1건이 제외됐고 활성 플래그 1건을 껐다. 사용자가 PR 리뷰에서 세 namespace의 운영 승인 질문을 대조해 제외 0건을 확인했다. 운영 초안과 반영 시점의 집계는 읽기 전용 명령으로 확인한다. [검증 기록](../evals/2026-11-11-calc-router.md)
