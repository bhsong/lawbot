# 상담 전체 추적 저장 — 대역 검증

[계획 1단계](../archives/consult-trace-clarify.md#1단계-상담-전체-추적-저장-pr-2-2026-11-24-착수-승인). 임시 SQLite DB, 브라우저 Chromium, 임베딩·리랭크 모델 서버 앱의 가짜 모델, 별도 가짜 생성 서버를 사용했다. 공유 추론 서비스에는 요청하지 않았고 운영 트리·운영 DB·개발 DB·환경 파일은 변경하지 않았다.

## 확인 기준

- 서버 ASGI가 받은 요청 바이트와 보낸 응답 바이트를 DB의 호출 순번으로 대조한다. 비스트림 본문은 바이트 단위, 생성 스트림은 수신 조각 단위다. 설정을 끈 기준선과 켠 실행은 요청 본문·공개 답변·조문 카드가 같아야 한다. 대역 리랭커 응답의 매번 다른 `id`는 두 실행 사이에 비교하지 않고 각 실행의 실제 응답과 저장값을 비교한다.
- 일반 경로는 `embedding → rerank → embedding → rerank → writer`, 계산 경로는 앞에 `router_select → router_label`이 붙는다. 시작 시 상태·모델 목록 조회와 인덱스 임베딩은 상담 호출에 들어가지 않아야 한다.
- 오류는 응답 코드·본문과 함께, 중지는 받은 조각까지만 저장해야 한다. 피드백 턴 ID로 요청과 상담을 연결하고 저장 오류가 난 상담은 부분 행을 남기지 않아야 한다. 요청 로그에는 원문·예외 메시지가 없어야 한다.
- 토큰·주소·포트·쿠키 가림, 응답 조각 경계의 가림, 압축 본문, 바이너리 상세의 base64 반환, 명시적 되묻기·재개 경로를 대역에서 확인한다.
- 관리자 로그인 후 목록 → 상세 → 삭제 대상 건수 확인 → 삭제 결과를 브라우저에서 확인한다. 목록 필터와 커서, 대상 변경 시 삭제 거부, 멱등 재실행, 삭제 감사 건수는 임시 DB에서 대조한다. 추적 꺼짐에서는 고지가 없어야 한다.

## 비교에 사용한 합성 화면 답변

기능 검증용 대역 답변으로, 법률 품질 점수는 매기지 않았다.

### 일반

질문: 해고 예고 없이 갑자기 해고되면 어떻게 하나요?

```text
가짜 모델 답변입니다. 근로소득 세금, 4대보험

근거: 소득세법 제95조(양도소득금액과 장기보유 특별공제액)
```

인용: 소득세법 제95조. 화면 판정: `shown`.

### 계산

질문: 월급 300만원으로 3년 일했습니다. 퇴직금은 얼마인가요?

```text
계속근로 1년 이상이고 4주 평균 주 소정근로시간이 15시간 이상이라는 전제에서, 최근 3개월 월급이 일정하고 평균임금을 적용하면 9,000,000원으로 추정됩니다. 월급 전액을 통상임금으로 보고 월 209시간과 1일 8시간을 가정하면 10,334,928원으로 추정됩니다.

근거: 근로자퇴직급여 보장법 제8조
```

인용: 근로자퇴직급여 보장법 제8조. 화면 판정: `shown`.

## 초기 구현 기본 테스트 결과

`uv run --locked pytest`(임시 JUnit 출력): **2,863개 통과**, 실패·skip 0. `models`, `network`, `e2e_live` 선택 제외 10개는 통과로 세지 않았다. 챗봇 대역 E2E는 59개로, 상담 원문 비교·관리 화면, 계산, 캘린더 관리자 흐름을 포함한다.

- 일반 5호출·계산 7호출 모두 송수신 저장값이 대역 서버의 실제 바이트와 일치했다. 생성의 스트림 조각 순서와 오프셋, 개별 호출의 상태·모델 revision·토큰을 대조했다. 켜짐·꺼짐의 송신 바이트·답변·카드가 같았고, 초기 인덱스 임베딩과 준비 조회는 저장에서 제외됐다.
- 브라우저에서 고지·상담 상세·writer 송신 `messages`·수신 원문을 확인했다. 삭제 후 상담 1건·단계 8건·호출 5건이 제거됐고 감사 건수가 일치했다.
- 모델 서버에서 HTTP 503을 받은 상담은 상태·오류 본문을, 중지·로그아웃 상담은 그때까지 수신한 조각을 남겼다. 저장 실패를 일으킨 경우 상담 데이터가 롤백됐고 답변은 완료됐다. 요청 로그에는 원문이나 예외 메시지가 없었다.
- 먼저 스키마 0003·설정·관리자 경로 부재로 Red를 확인했다. 이후 브라우저 worker 문맥 누락과 응답 후 기록에 대한 테스트 동기화, 스키마 버전 픽스처를 수정한 뒤 전체를 다시 실행했다.

## Astra 리뷰 반영 (2026-11-24)

- Red에서 다중 gzip 멤버·헤더·잘린 스트림 보관, JSON 숫자 자리에 가림 삽입, 재로그인 후 미리 보기 영수증 재사용, 요청 ID 충돌을 재현했다.
- 가림: gzip은 모든 멤버의 종료와 헤더를 검사한다. 검증할 수 없는 압축은 `unreadable_encoding` 표식만 보관한다. UTF-8·UTF-16·UTF-32 JSON 문자열은 해석값을 검사하며 무관한 바이트를 유지한다. 포트와 같은 숫자 필드는 보존한다. 승인 범위에 따라 생성 SSE 델타를 이어 붙여 검사하지 않는다.
- 전송: 최종 이벤트를 만든 후 연결이 닫히는 경우와 ASGI 전송 중 끊기는 경우를 나눠 최종 글·판정·피드백 턴을 대조한다. 오류 안내도 보존한다. 연결·쓰기 실패는 응답 여부로 송신 상태를 구분한다. 완료된 writer는 상담 취소를 오류로 기록하지 않는다. 라우터의 `finish_reason` 누락은 해당 호출에 귀속하고, 여러 `data:` 줄의 usage를 완전한 이벤트에서 읽는다.
- 관리자: 미리 보기 집계 중 다른 상담이 저장되는지 확인하고, 확인값을 관리자 세션과 대상 집합에 묶는다. 상세 첫 응답은 메타데이터만 반환한다. 큰 본문은 페이지를 이어 붙여 원문과 대조하고, 브라우저에서는 writer 호출을 펼쳐 송수신 본문을 확인한다.
- 네트워크 대역은 서버 공통 순번으로 모델 호출의 순서를 대조하고, ASGI 송신 조각과 HTTPX 수신 조각은 각자 연결한 바이트를 비교한다. 수신 경계와 시각 오프셋은 transport 대역에서 독립 확인한다.
- 리뷰 반영 뒤 첫 전체 실행에서 브라우저 시험이 송신 첫 페이지에 질문까지 있다고 가정해 실패했다. 송수신 영역을 구분하고, 브라우저에서 송신 페이지를 끝까지 넘겨 합친 글을 대역이 받은 요청 바이트와 대조하도록 고쳤다.

마지막 `LAWBOT_ENV_FILE= uv run --locked pytest -q --tb=short --show-capture=no`는 **2,881개 통과**, 실패·skip 0이었다. `models`, `network`, `e2e_live` 선택 제외 10개는 통과로 세지 않았다. 상담 추적 회귀 25개, 대역 E2E 59개, 웹 인증 통합 6개가 포함된다. Ruff 린트·포맷, `compileall`, Pyright(루트·캘린더·ERP·수집원), ERP·수집원 잠금 파일과 캘린더 스키마 검사도 통과했다. 두 화면의 typecheck·test·build 통과(챗봇 55개, 캘린더 36개).

실제 모델 E2E, 모델 스모크, 품질 평가: **실행 안 함**. [리뷰 반영 계획](../archives/consult-trace-review.md)
