# 운영 v5.1.0 반영 확인 (2026-11-08)

운영 worktree를 태그 `v5.0.0`의 `69a2dd338ec289176046ab343f6f27bb9eb6fd78`에서 태그 `v5.1.0`의 `3aa2002421b679c6ffba4e3adaa861078ada1460`(PR #83–#87)으로 전환했다. 개발 `main`도 같은 커밋이었다. 모든 시각은 KST다. [데이터 DB 운영 절차](../operations.md#데이터-db)

## 반영 범위

- `69a2dd3..3aa2002`의 실행 코드 변경은 `services/chatbot/src`(SQLite 데이터 DB, 피드백 DB 저장, 턴 기록 보강), `services/chatbot/pyproject.toml`(`lawbot-db` 명령)과 `tools/lawbot-tools`다.
- `services/model-server`, 두 프런트엔드, `uv.lock`은 바뀌지 않았다. 모델 서버 재시작과 화면 재빌드는 하지 않았다.

## 절차

1. 운영 `.env`에 `LAWBOT_DB=data/db/lawbot.db`를 추가했다(값 출력 없이 마지막 줄 추가). `LAWBOT_FEEDBACK=1`, `LAWBOT_FEEDBACK_DIR`는 비어 있음을 확인했다. 운영 JSONL 피드백 파일은 0개라 이관할 것이 없었다.
2. `git checkout --detach v5.1.0`. 운영 worktree의 로컬 변경은 기존 `models` 링크뿐이었다.
3. `uv sync --frozen`: `lawbot` 패키지만 다시 설치됐다.
4. `uv run --frozen lawbot-db init --db data/db/lawbot.db` → 스키마 버전 2. `status`도 2. 폴더 권한 700, 파일 권한 600, `git check-ignore` 통과.
5. `uv run --frozen python -m lawbot.check_deploy` 통과: v5 조문·하위법령, 모델 서버 접속·토큰, 필요한 모델 3개(`qwen3.8-27b-4bit`, `lawbot-emb-v5b`, `qwen3-reranker-4b`, 모두 상주).
6. 07:52:33에 `launchctl kickstart -k gui/$(id -u)/com.lawbot.web`. 임베딩 캐시(705·792개)를 써서 조문 인덱스 3.6초. 프로필 v5, 리랭커·하위법령 켜짐.
