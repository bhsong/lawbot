## Red → Green

- 0003을 추가하기 전 신규 캐시 초기화가 0002를 반환했다. `on` 거부와 calibration 없는 `shadow` 거부도 실패했다. 0003 적용 후 0002에서 승인한 기존 exact 답변과 마이그레이션 이력, SQLite FK 무결성을 대조했다.
- 결정적 조건·선택 부모 점수·응답 인덱스 계약 테스트를 먼저 실패시켰다. 정확·시맨틱 분기 연결 전에는 shadow 가상 적중과 미스 사유가 요청 로그에 없었다.
- 전체 실행에서 SQLite import가 런타임에 들어간 계층 검사 실패를 확인했다. 카탈로그 읽기를 `semantic_store.py`로 옮긴 뒤 전체를 다시 실행했다.

## PR #151 리뷰 반영 검증

리뷰 기준은 `f47aed9`다. 로컬 변경과 검증은 P1 → P2 → P3 순으로 진행했다. [리뷰 요약](https://github.com/bhsong/lawbot/pull/151#issuecomment-6887095214)

| 우선순위 | 회귀 검증 |
| --- | --- |
| P1 | SSE 종료 이전 shadow 실행, 종료되지 않는 예산, 긴 페어 하나로 전체 실패, 출처 질문 철회·제외 후 가상 적중을 먼저 재현했다. 수정 후 응답 종료·슬롯 해제 순서, 남은 시간 전달, 페어별 토큰 한도 및 출처 상태를 확인했다. |
| P2 | 실패한 B 호출이 로그에 누락되고, 모델 revision이 바뀌어도 적중하며, 인덱스 파일 오류에 시작 경고가 없는 것을 재현했다. 실패 호출 수, revision 전후 대조, 스키마 0002 경고와 exact 상태 판단을 검증했다. |
| P3 | 임베딩 전 부모 문서 생성이 시작되는 것을 재현했다. 수정 후 자격 있는 Top-K만 생성하고 동점은 인덱스 순으로 선택했다. 기본 `off` 회귀 검사는 SSE 이벤트와 로그 필드를 대조했다. |

개발 리랭커의 로컬 토크나이저로 모델 서버와 같은 prefix·중간 입력·suffix 계약을 대조했다. 7,560바이트의 합성 문서는 중간 입력 2,128토큰으로 통과했고, 32,400바이트의 합성 문서는 9,028토큰으로 제외됐다. 이 대조에는 모델 서버나 모델 추론을 사용하지 않았다.

- 잠긴 의존성에서 기본 pytest 2,049건 통과, 13건 선택 제외, 실패·skip 0건. 단위·계약·통합 7건·대역 E2E 53건을 포함한다.
- `uv lock --check --offline`, Ruff 린트·포맷, Pyright, Python 문법 검사 통과. 챗봇과 캘린더의 타입 검사·Vitest 86건·빌드도 통과했다.
- 실제 모델 E2E·모델 스모크·품질 평가 실행 안 함. 실제 모델 호출 0회.
