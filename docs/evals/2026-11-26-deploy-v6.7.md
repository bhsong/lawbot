# 운영 반영 v6.7.0·v6.7.1: 법령 캘린더 Cloudflare Pages 전환 (2026-11-25~26)

캘린더 공개 화면을 Cloudflare Tunnel + Access(본인만)에서 로그인 없는 Cloudflare Pages 정적 사이트로 옮겼다. 루프백 캘린더 서버는 관리자 프록시와 내보내기용 API만 제공한다. [계획](../archives/calendar-pages-static.md) · [공개 전 확인](2026-11-25-calendar-public-license-check.md) · [PR 1](2026-11-25-calendar-pages-static-pr1.md) · [PR 2](2026-11-25-calendar-pages-static-pr2.md) · [v6.7.1 수정](2026-11-25-calendar-node-admin-group.md)

## 결론

- v6.7.0(`e3615e6`, PR #199·#200)과 v6.7.1(`2a51877`, PR #201)을 반영했다. Pages 첫 게시와 다음 날 06:30 daily 자동 게시가 모두 `ok`였다.
- 공개 캘린더 서브도메인과 `<프로젝트>.pages.dev`가 같은 빌드를 제공한다. 예전 서버 경로(`/api/law-calendar/status`, `/docs`)는 404, 챗봇은 여전히 Access를 요구한다.
- 첫 실제 게시가 `wrangler_unavailable`로 실패했다. Homebrew `Cellar`의 기본 `admin` 그룹 쓰기 권한을 Node 경로 검사가 거부했기 때문이다. 미설정 상태의 게시는 이 검사 전에 `skipped`로 끝나 v6.7.0 반영 때 드러나지 않았다. v6.7.1에서 macOS `wheel`·`admin` 그룹 쓰기만 허용하도록 고쳤다.
