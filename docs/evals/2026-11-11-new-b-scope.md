## 재현과 검증

```zsh
lawbot-build-articles --repo "$pinned_legalize_kr" --asof 2026-11-03 \
  --scope data/v5/scope_tax.csv --version v5 --out-dir data/v5 --check
lawbot-max-seq data/v5/law_articles_v5_decree.csv \
  --tokenizer models/v5/emb_v5b_fp16/tokenizer.json --training-max-seq 5120 --counts "$scratch/doc_tokens_v5.csv"
```

`$pinned_legalize_kr`은 매니페스트 커밋을 HEAD로 지정한 Legalize KR 사본이다. 생성할 때는 임시 출력 디렉터리를 지정하고 `--check`를 생략했다. 기존 매니페스트 두 개를 임시 출력 디렉터리에 복사해 둔 뒤 `lawbot-reindex --no-cache --dataset-version v5 --reference-date 2026-11-03 --collected-date 2026-11-11 --source-ref bcb7aea7782e81c21fbeb08382c442f7c2041690`을 각 생성 CSV에 실행했다.

## CI 브라우저 전송 타이밍 확인

최초 GitHub Actions에서는 390px 캐시 검토 대역 E2E 한 건이 두 번째 질문의 요청 로그를 기다리다가 실패했다. 브라우저 진단에는 첫 캐시 적중 응답과 입력창에 남은 두 번째 질문이 있었다. [최초 CI 실패 로그](https://github.com/bhsong/lawbot/actions/runs/42939699662/job/130258301668)

첫 캐시 응답의 본문을 서버에서 받은 뒤 브라우저 코드에 1.5초 늦게 넘겨 같은 실패를 재현했다. 공통 전송 도우미가 `보내기` 버튼을 확인한 뒤 Enter를 누르도록 수정하자 같은 지연에서 390px·1280px 테스트가 모두 통과했다. 수정 후 기본 테스트 1,290건과 Ruff·Pyright가 통과했다.

## 유효기간 리뷰 반영

조문 전체는 유효기간을 정한 개정과 기준일의 조문 번호·제목이 같을 때 실효 처리한다. 항은 해당 항의 본문을 비교한다. 부칙 제목에 ‘유효기간’이 들어 있으면 모든 항을 읽으며, ‘그 효력을 가진다’도 읽는다. 보험료징수법 제22조의3·제22조의4만 비삭제에서 실효로 바뀌었다. 번호가 재사용된 고용보험법 시행령 제37조의2와 보험료징수법 시행령 제30조의5는 제목이 달라 각각 비삭제로 유지됐다. [PR 리뷰](https://github.com/bhsong/lawbot/pull/116#issuecomment-6787241336)

생성 출력과 조문 점검·갱신 보고서에 ‘유효기간 판정 보류’를 추가했다. 고정 원문에서는 30줄을 기록했다.

| 대상 | 부칙과 만료일 | 판정 보류 사유 |
| --- | --- | --- |
| 고용보험법 시행령 제28조 | 제25022호 부칙 제2조제2항, 2015-12-31 또는 2016-12-31 | 사업장별 날짜를 각 호에 둔 문장 |
| 고용보험법 시행령 제17조제1항제6호 | 제26496호 부칙 제2조, 2018-12-31 | 호에 한정된 유효기간 |
| 고용보험법 제107조제1항 단서 | 제8429호 부칙 제3조, 2009-12-31 | 항 안의 단서에 한정된 유효기간 |

하위법령 검색 평가가 `emb_rank`를 CSV에 저장하도록 평가 스크립트를 변경했다. 가짜 검색 결과로 임베딩 순위와 리랭킹 순위가 각각 기록되는지 확인했다. 3단계는 실행 안 함이다.

회귀 테스트에서 기존 동작의 실패 6건을 확인했다. 수정 후 기본 테스트 1,296건과 Ruff·Pyright가 통과했다. 고정 원문으로 `lawbot-build-articles --check`를 실행해 v5 조문 CSV 두 개의 바이트 일치를 확인했고, 토큰 CSV도 다시 생성해 `cmp`로 확인했다.
