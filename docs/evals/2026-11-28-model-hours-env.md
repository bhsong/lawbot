| 명령 | 결과 |
| --- | --- |
| `uv run pytest` | 3,031개 통과, 10개 기본 실행 대상 제외 (224.75초). 단위·계약·통합·대역 E2E 포함 |
| `uv run ruff check` | 통과 |
| `uv run ruff format --check` | 634개 파일 통과 |
| `uv run pyright` | 오류 0, 경고 0 |

Red에서는 스크립트·웹앱·대역 E2E 대상 10개가 실패했다(6개 통과). 첫 전체 실행은 3,030개 통과했다. 준비 검사 중 다음 주기를 놓치는 경우를 별도 Red 1개로 재현했다. 이를 고치는 과정에서 자동 마감과 `--deadline` 값이 섞여 미설정·빈 값 두 건이 실패했고, 두 값을 분리한 뒤 최종 전체 실행은 모두 통과했다.

## 확인한 동작

- 스크립트: PATH의 가짜 `launchctl`·`uv`와 임시 `.env`만 사용했다. `.env`의 시간 분기, `--hours` 우선, 누락·빈 값일 때 항상 운영, 형식 오류 시 등록 상태 불변, 다른 키의 명령 미실행과 값 미노출을 확인했다.
- 예약: `RunAtLoad`와 `StartInterval=300`, 같은 상태일 때 bootstrap·bootout·준비 확인·로그 0건을 확인했다. 시작 시각 + 25분 마감, 자정 넘김, `--deadline` 우선, 늦은·수동 시작의 단일 확인을 검증했다. 준비 확인 중 다음 주기에 `.env`가 바뀌어 현재 시각이 범위를 벗어나면 확인을 중단하고 두 서비스를 내렸다.
- 웹앱: 다음 질문에서 새 운영 시간으로 판정·표시했다. 수정 시각이 그대로면 재파싱하지 않았고, 잘못된 값은 직전 시간으로 판정하며 해당 수정에 경고를 한 번만 남겼다. 다른 설정 줄은 파싱하지 않았다.

## 대역 E2E 질문·응답

같은 웹앱 프로세스와 로그인 세션에서 첫 질문에 답한 뒤 임시 `.env` 한 줄을 바꾸고 두 번째 질문을 보냈다. 다음은 최종 실행의 상담 기록 원문이다.

1. 질문: `해고 예고 없이 갑자기 해고되면 어떻게 하나요?`

   ```text
   가짜 모델 답변입니다. 근로소득 세금, 4대보험

   근거: 소득세법 제95조(양도소득금액과 장기보유 특별공제액)
   ```

   대역 응답의 인용: 소득세법 제95조. 품질 점수는 산정하지 않았다.
2. 질문: `주 40시간 일하면 주휴수당은 얼마인가요?`

   ```text
   답변 서비스 운영 시간은 13:00–14:00입니다. 운영 시간에 다시 질문해 주세요.
   ```

   화면과 상담 기록이 일치했다. `error_type=off_hours`, `delivery_status=sent`, 피드백 버튼 없음, 모델 호출 0건. 조문 인용·품질 점수 해당 없음.

운영 트리·실제 launchd·운영/개발 `.env` 미접근. 운영 반영, 실제 모델 E2E, 모델 스모크, 품질 평가: 실행 안 함.
