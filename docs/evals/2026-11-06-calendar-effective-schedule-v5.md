# v5 법령 캘린더의 시행일과 저장 원문 검증

PR #74 병합 커밋 `1a2de67` 위에서 캘린더의 시행일 판정과 원문 분리를 검증했다. 입력은 개발 `calendar-v5-preview.db`에 저장된 개정 20건이다. 원천 DB를 읽기 전용으로 열어 SQLite 사본을 만들고 보관된 이벤트 JSON과 신·구 원문을 일반 import 경로에 다시 넣었다. 원천 DB의 전후 SHA-256이 일치했다.

- 첫 실행은 갱신 20건, 실패 0건이었다. 동일 입력 재실행은 무변경 20건이었다.
- 공개 31건을 날짜와 저장 원문까지 유지했고 29건을 추가했다. 최종 60건 중 57건이 미리보기 기준일 뒤의 일정이다. 시행 예정 범위로 가져온 원천에서는 부칙 판정 결과에 원천의 기준일을 적용했다. 공개된 후보의 날짜는 저장된 v5 후보 날짜와 전부 일치했다.
- API와 Chromium에서 아래 8개 날짜의 목록과 상세를 전수 확인했다. 60건의 Before/After가 저장 신·구 원문의 해당 부분과 일치했다. 공개 상세는 시행 전후 효력 미검증 상태를 유지했고, 원문 한쪽이 없는 경우 이를 표시했다.
- API와 Chromium의 보류 5건, 항목별 사유와 공개 상세에서 제외되는 것을 확인했다. 첫 브라우저 점검의 보류 행 선택 범위와 새 회귀 테스트의 상세창 표시 대기를 수정한 뒤 다시 실행했다.

소득세법과 시행령의 16개 일정은 2027-01-01 15개와 2028-01-01 1개다. 제17조제3항의 배당가산율 변경, 제37조의 서로 다른 두 개정과 시행령 제207조 제11항을 개정별로 확인했다. 노동법은 근로기준법 제43조의6, 최저임금법 제26조·제28조·제31조 및 보험료징수법 특례가 붙은 개정 등도 확인했다.

| 보류 범위 | 이유 |
| --- | --- |
| 소득세법 제21조, 제119조(2023-07-18 개정) | 다른 법률의 부칙을 통해 이전 개정법률을 바꾼 사례. 시행일 단서와 대상 개정의 연결 확인 필요 |

## 실행

- `PYTHONPATH="$PWD/services/law-calendar/src" .venv/bin/python -m pytest -q`로 단위·계약·통합·대역 E2E를 실행했다. 기본 885개 통과, 기본 제외 13개.
- 두 프런트엔드의 `npm run typecheck`, `npm test`, `npm run build` 통과. Vitest는 캘린더 18개, 챗봇 19개 통과.
- Ruff 검사·포맷, 루트와 캘린더 Pyright, 캘린더 API 스키마, Python 문법 검사, 두 uv 잠금 파일 검사, `git diff --check` 통과.
- 실제 모델 E2E·모델 스모크·품질 평가는 실행 안 함. 개발 검증 사본은 `services/law-calendar/data/calendar-v5-verified.db`에 두었다.
