## 2차 평가 후 수정

사용자는 2차의 라우터 system(SHA-256 `5a7fcd20723b106b7642e74051bf910104d0f02293886a14aab1f12783f97094`)을 유지하고 검증을 재생과 대역 시험으로 마치기로 결정했다. 세 프롬프트 문자열이 모두 평가 커밋과 일치함을 확인했다. 실제 모델 실행은 `ff4f2ac`(1차)와 `f20f993`(2차)다. 이후에는 결정적 코드·시험과 문서만 바꿨다. [2차 검토](https://github.com/bhsong/lawbot/pull/113#issuecomment-6785560293) · [사용자 결정](https://github.com/bhsong/lawbot/pull/113#issuecomment-6785592332)

CR092의 2차 원출력은 질문에서 한 번 나온 `700만원`을 일반 의료비와 난임시술비에 각각 넣어 2,925,000원을 계산했다. 두 계산기 모두 동일한 금액 문자열의 사용 횟수가 질문에서 `complete_amount_span` 경계를 충족하는 등장 횟수를 초과하면 기존 `guidance/ambiguous_input` 안내로 전환한다. CR092와 중도정산의 합산 보험료 중복은 안내로 바뀌었다. 일반 의료비와 난임시술비에 각각 `300만원`이 적힌 질문은 1,125,000원을 계산했다.

2차 실행의 임시 원출력 파일은 기록 작성 후 정리했다. 아래 점수는 문서에 보존된 2차 원출력 10건의 재생 결과다. 2차 전체 실측은 직접 호출 90/100, 모호한 입력 9/10이었다.

| 보존 원출력 | 수정 전 | 수정 후 |
| --- | ---: | ---: |
| 의료비 계산형 CR008 | 1/1 | 1/1 |
| 미지원 계산 CR043·CR047 | 1/2 | 1/2 |
| 모호한 입력 CR091·CR092·CR093·CR094·CR096·CR097·CR100 | 6/7 | 7/7 |
| 보존 원출력 전체 | 8/10 | 9/10 |
| 계산 결과 금액 검산 | 1/2 | 1/1 |

재생에서 바뀐 판정은 CR092 하나다. 수정 후 계산이 나온 CR008의 1,035,000원은 독립 검산과 일치했다. 계산형 40건(의료비 20건, 중도정산 20건)과 필수 입력 누락 10건은 고정 val 질문의 원문 구간으로 합성 응답을 만들어 비교했다. 50건 모두 수정 전후의 상태, 사유와 응답 데이터가 일치했고, 계산형은 40건 모두 계산, 필수 입력 누락형은 10건 모두 안내였다.

2차의 미지원 계산 6건(CR041·CR043·CR048·CR050·CR052·CR057)은 조회로 분류됐다. 노동 계산기 PR에서 라우터 프롬프트를 수정하고 실제 모델 평가로 확인한다. 이번 중복 검사는 정확히 같은 문자열을 센다. CR092에서 `700만원`과 `700만`으로 달리 추출한 합성 응답은 두 문자열로 집계되어 2,925,000원을 계산했다.
