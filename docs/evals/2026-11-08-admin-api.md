# 관리자 API 검증 (2026-11-08)

임시 SQLite, 가짜 자격 증명과 가짜 모델로 PR 7을 검증했다. [계획서](../plans/sqlite-admin-pipeline.md#pr-7--관리자-api-featadmin-feedback-api)

Red 단계에서 미등록 라우트의 404, 양쪽 분할을 보호하지 않던 기존 검수 도구, 시작 시 이관 검사의 부재를 재현했다. 별도 회귀 테스트에서 거부된 검수 키가 다른 본문으로 재사용되는 경우와 과거 피드백의 조문 식별 필드 누락을 재현했다.

- 관리자 인증, Origin, 관리자 전용 415, 본문 64 KiB 상한과 세션당 분당 30회 제한을 확인했다. 실제 웹앱 프로세스에서 관리자 로그인, 목록 조회, 검수 저장, 좋아요 승격, `promoted` 목록 조회를 이어서 실행했다.
- QA 세트 8종을 임시 DB에 이관한 뒤 CSV 검수 도구와 DB의 보호 문항 다중집합이 같음을 확인했다. `sllm` val을 합치며 v4 444건, v5 855건, 하위법령 181건을 보호 대상에 추가했다. 원 질문과 교정 질문의 일치·유사도를 확인했고 train 겹침은 승격을 허용했다.
- 활성 승격 동시 요청은 한 건만 성공했다. 승격 쓰기 실패 시 QA·검수·감사·멱등 응답이 함께 롤백됐다. 배치 중간에 쓰기를 실패시킨 뒤 같은 키로 재시도해 이미 성공한 결과와 남은 결과를 모두 받았다. 거부된 검수도 같은 요청은 그대로 재생하고 다른 본문은 409를 반환했다.
- `-r1` 취소 후 기존 train 배정은 보존됐고 상세에서 겹침을 확인했다. `-r2`는 두 목적 모두 `unassigned`로 시작했다. 피드백 원문은 관리자 응답에서만 조회했고 감사에는 ID와 상태를 기록했다.
- 가짜 캘린더 응답으로 GET 허용 경로, 쿼리와 상태 전달, 자격 증명 미전달 및 502·503·504를 확인했다.
