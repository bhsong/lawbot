## 구현 후 기록 절차

1. 검증일 KST, 개발 HEAD, 설정의 `AGE`·키워드 수, 페이지 크기와 실행 예산, 테스트 명령·종료 코드를 적는다. 임시 `LAW_MONITOR_HOME`과 임시 캘린더 DB를 사용한다. 대역 데이터는 합성 응답과 공개 원문 구조로 만들고, 운영 DB를 이용한 사전 검증은 승인된 백업 사본에서만 수행한다.
2. 기본 실행에서 네트워크 없이 파싱·재시도·키 가림·상태와 이벤트 원자성을 확인한다. 대역 Monitor의 등록 이벤트를 임시 캘린더 DB에 sync하고 API와 Chromium에서 승인 전후, 정정, 누락 날짜, 원문 링크, 장애 복구를 확인한다. 기존 법령 소스의 자동 시행일 등록·보류·승인 결과를 함께 대조한다.
3. 실제 API 연결 테스트는 구현 후 `uv run pytest -m network services/monitor/tests/test_mon_assembly_network.py`로 분리한다. 세 API의 두 페이지씩과 공식 원문 상세 두 건을 읽는 최대 8회 테스트를 기본안으로 잡는다. 배치 수집 시간 측정은 별도 실행으로 남긴다. 요청은 HTTPS 공식 호스트만 사용하고 테스트 출력에는 서비스 코드, 결과 코드, 건수·시간만 기록한다. 키를 포함한 URL, 응답 덤프, 실제 환경 설정은 남기지 않는다.
4. 검증 결과는 `docs/evals/YYYY-MM-DD-assembly-law-calendar.md`에 아래 표로 기록하고 README에 한 줄 추가한다. 측정하지 않은 값은 ‘실행 안 함’으로 적는다. 일정·공개 검토·신선도에 오류가 있으면 검증을 완료 처리하기 전에 재현 방법과 실패 출처를 기록한다.
