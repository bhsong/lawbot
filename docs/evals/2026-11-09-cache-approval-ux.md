# 정확 일치 캐시 관리자 승인 개선 검증

2026-11-09 KST · 기준 `8bbd69b` · `feat/cache-approval-ux` · 개발 트리에서 임시 SQLite와 대역 모델로 실행했다. [계획서](../archives/cache-approval-ux.md)

| 계약 | 확인 결과 |
| --- | --- |
| A | `off`, `shadow`, `on`의 모든 전환 방향과 승인 ID 누락·불일치 거부, 보호 지문 불일치 409를 확인했다. `shadow`에서는 `would_hit`가 기록된다. |
| B | `on`·`shadow`에서 초안을 승인했다. `on`에서 신규 초안 승인 직후 다음 채팅 요청이 캐시에 적중했다. 기존 carry-forward, 검토 대기 재승인, 철회 테스트도 통과했다. |
| C | 미입력·공백 승인 사유에 `표시본 확인 승인`을, 사용자 입력에는 입력한 사유를 저장했다. 모드·답변 철회·질문 철회는 공백 사유에 400 `reason_required`를 반환했다. |
| D | 두 답변을 한 번의 POST로 승인했다. 답변별 감사에 같은 승인 ID가 남고 generation은 1 증가했다. 해시 변경, 답변·질문 철회, 보호 분할 위반에서 실패 답변 ID와 원인이 반환됐다. 승인 중 릴리스가 바뀌는 경우도 제어 행·답변·질문·감사가 롤백됐다. 오래된 generation 409, 멱등 재응답, Origin 403, POST 속도 제한 429를 확인했다. |
| E | 390px·1280px Chromium에서 상세 조회 전 선택 차단, 사유 없는 단건·일괄 승인, `on` 경고, 비활성 버튼의 흐린 스타일·기본 커서, 사유 안내, 상세 하단 사유 입력, 409의 `role="alert"`를 확인했다. |

## Chromium 캐시 요청 기록

두 화면 폭에서 모두 아래 합성 질문의 `response_source`가 `exact_cache`였다. 요청별 임베딩·검색·리랭킹·생성 호출은 각각 0회였다. 캐시 동작을 확인하는 사례이며 점수 산정은 실행 안 함이다.

**합성 질문인가요?** · 일괄 승인 후 `off → on`으로 전환했다. 인용 조문은 근로기준법 제27조다.

```text
【결론】
합성 결론입니다.
【근거 조문】
근로기준법 제27조
【설명】
합성 설명
【참고】
합성 참고
```

**활성 캐시에서 승인할 합성 질문인가요?** · `on` 상태에서 상세의 단건 승인으로 추가했다. 인용 조문은 근로기준법 제26조다.

```text
【결론】
합성 결론입니다.
【근거 조문】
근로기준법 제26조
【설명】
합성 설명
【참고】
합성 참고
```
