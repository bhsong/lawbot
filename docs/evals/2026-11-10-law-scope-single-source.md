# 공통 법령 범위 통합 검증 (2026-11-10)

개발 기준 `5a75f20`에서 합성 Git 저장소·임시 DB와 대역 API로 수집 및 캘린더 흐름을 확인했다. 조문 생성 동등성은 로컬 Legalize KR 원천으로 검증했다. [계획서](../archives/law-scope-single-source.md)

## 수집 범위와 캘린더

- Red에서 기존 monitor의 기본 범위는 부가가치세법 1개를 더 포함하고 v5 대상 5개가 빠져 일치 시험 1개가 실패했다. Green에서 전체 조문을 사용하는 노동 법령 7개와 선택 조문을 사용하는 세금·보험 법령 10개, 국회 제목 키워드 22개를 확인했다.
- 합성 Legalize KR에서 저장 커서 유지와 `legalize_law`만 강제 bootstrap하는 두 경로를 검증했다. 두 경로 모두 새로 추적하는 5개 법령의 과거 이력을 발행하지 않았고, 반영 이후 임금채권보장법 개정 1건이 캘린더에 들어갔다.
- 두 국회 수집기는 키워드 변경 뒤 기존 기준점으로 수집을 거부했다. 각각 강제 bootstrap하면 기존 항목의 revision 1을 보존하고 새 항목을 revision 0으로 등록했다. 첫 정상 수집에서 신규 범위의 진행 중 입법예고를 revision 1로 발행했다.
- 정기 sync가 범위 밖의 등록 법령·법률안·입법예고를 가져오지 않는지 확인했다.

### 과거 스냅숏 충돌 리허설

아래 결과는 합성 스냅숏을 넣은 격리 DB에서 확인했다.

- 사전 이관 행이 없으면 신규 예고를 저장했다. 같은 revision 1의 저장 내용이 같으면 기존 행을 보존하고 `unchanged`로 집계했다. 내용이 다르면 같은 소스에서 앞서 처리한 신규 예고까지 롤백하고 본문 단계는 실행하지 않았다.
- 캘린더에 revision 2가 이미 있으면 먼저 들어온 monitor revision 1은 과거 스냅숏으로 저장하고 기존 현재 행을 유지했다. 다음 수집의 revision 2에서 내용 충돌이 발생해 입법예고 소스가 실패했으며, 같은 실행의 법률안은 정상 반영됐다.

## 초기 PR의 조문 생성과 DB 릴리스 동등성

같은 로컬 Legalize KR 커밋 `bcb7aea7782e81c21fbeb08382c442f7c2041690`과 기준일 2026-11-27로 변경 전후의 DB 모드 `lawbot-articles-update`를 실행했다. 임시 DB에서 같은 초기 코퍼스를 사용했고 v4·v5 각각 조문 변경 7건을 감지해 `v4-live-2026-11-27`과 `v5-live-2026-11-27`을 활성화했다. 검색 검증은 대역으로 실행했으며 재시작 없이 확인했다.

## 리뷰 반영 검증

- 별도 CSV에서 근로기준법이 중복되고 소득세법이 누락되는 문제를 재현했다. 수정 후 해당 CSV가 전체·부분 포함을 결정하며, 누락된 하위법령은 전체 포함에서 생략하고 CSV가 지정한 문서는 계속 필수로 검사한다.
- 로컬 Legalize KR에서 농어촌특별세법을 선택 조문 목록에서 뺐을 때 법률과 시행령이 전체 포함 대상으로 조회됐다. 조문 관련 시험 95개와 국회 기준점 관련 시험 7개가 통과했다.
- 최종 코드로 같은 원천·기준일에 v4·v5 임시 DB 릴리스를 다시 활성화했다. 복원한 CSV 4개와 릴리스 DB 및 매니페스트의 SHA-256이 위 기준값과 일치했다. 표준 v5의 2026-11-03 CSV 2개도 다시 바이트 단위로 일치했다.
- 최종 기본 테스트 1,243개 통과, 13개 제외. 문법·Ruff·Pyright·캘린더 스키마와 두 프런트엔드의 타입 검사·단위 시험·빌드도 통과했다. `e2e_live`, `models`, 품질 평가는 각각 실행 안 함.

## 운영 반영 전 대조

운영 담당자가 PR #107 리뷰에 공유한 읽기 전용 확인에서는 monitor 기본 설정을 사용하고 있었으며, 신규 범위의 기존 캘린더 스냅숏은 0건이었다. 위 격리 DB의 충돌 리허설은 기존 이관 행이 생겼을 때 적용할 확인 절차를 검증한다. [운영 담당자 리뷰](https://github.com/bhsong/lawbot/pull/107#pullrequestreview-5834060489)

합성 입법예고 시험에서는 마지막 수집 뒤 바뀐 종료일이 강제 bootstrap에서 같은 revision의 비교 기준으로 저장됐고, 다음 수집에서 해당 변경 이벤트는 발행되지 않았다. 운영 반영 시 06:30 KST daily 정상 종료를 확인하고 06:50 KST 이후 가능한 한 빨리 반영과 두 국회 기준 갱신을 이어서 진행한다. 마지막 정상 수집 종료와 기준 갱신 시각을 기록하고, 이 사이에 알려진 변경을 원천과 대조해 누락이 확인되면 반영 방법을 정한다.
