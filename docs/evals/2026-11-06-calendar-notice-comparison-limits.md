# 입법예고 대비표 처리 한도 검증

- 151쪽 PDF와 PNG 한 장의 크기 한도 초과를 각각 재현했다. 한도 초과 사유를 `pdfLimits`와 DB에 기록하고, 날짜와 주요내용이 확인된 예고에는 공식 PDF 링크를 제공했다. 재수집 중 한도에 걸려도 기존 PNG는 보존했다.
- 신규 한도 초과 예고는 자동 공개하되 정기 PDF 재시도 대상에서 제외했다. 수동 재수집에 성공하면 한도 상태와 이전 이미지를 갱신했다. 일시적인 PDF 조회 오류는 다음 수집의 재시도 대상으로 남고, 재시도에서 기존 페이지 번호를 같은 번호의 새 이미지로 교체했다.
- Chromium 390px·1280px에서 공식 PDF 안내와 링크, 이전에 저장한 신·구조문대비표 제목 및 보존된 이미지를 확인했다.
- 개발 DB의 읽기 전용 사본을 v6에서 v7로 올렸다. 주요내용 112건, 대비표 539쪽의 바이트, 일정·검토 이력·보류가 원본과 일치했고 SQLite 무결성 검사와 이전 스키마의 공개 API 조회도 통과했다.

| 검증 | 결과 |
|---|---|
| 단위·계약·통합·대역 E2E (`PYTHONPATH="$PWD/services/law-calendar/src" .venv/bin/python -m pytest -q`) | 913개 통과, 기본 선택에서 제외 13개 |
| 캘린더·챗봇 프런트엔드 타입·Vitest·빌드 | 통과, Vitest 각각 19개 |
| Ruff, 포맷, 두 Pyright 범위, API 스키마, Python 문법, 두 uv 잠금 파일 | 통과 |
| 실제 모델 E2E·모델 스모크·품질 평가 | 실행 안 함 |
