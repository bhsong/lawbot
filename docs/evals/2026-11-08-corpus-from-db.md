# DB 코퍼스 검색 동등성 검증 (2026-11-08)

개발 트리의 v5 원본 조문을 `tmp_path`의 SQLite DB에 이관하고 가짜 모델 서버로 CSV·DB 모드를 대조했다. [PR 11 계획](../archives/sqlite-admin-pipeline.md#pr-11--웹앱-코퍼스를-db-활성-릴리스에서-읽기-featcorpus-from-db)

| 하위법령 첨부 | 선택한 CSV | 검색 인덱스 | CSV와 같은 캐시 키 | DB 시작 시 가짜 인코더 호출 |
|---|---|---|---|---|
| 꺼짐 | `articles_v5.csv` | 법률 705개 | `e98b86afa4b21794361264674cd69393` | 법률 확인용 1개 |
| 켜짐 | `law_articles_v5_decree.csv` | 법률 705개와 하위법령 792개 | 법률 `e98b86afa4b21794361264674cd69393`, 하위법령 `2bba800231b93bf32aeb35c93e39c027` | 각 인덱스 확인용 1개 |

두 모드에서 문서 문자열, ID, 법령명, 종류, 제목, 순서, 임베딩 배열, 합성 질문의 검색 결과와 점수가 같았다. CSV 모드에서 만든 캐시에서 `meta`를 뺀 뒤 DB 모드로 재사용해 파일 내용과 캐시 키를 확인했다. 새 캐시에는 실제 배열 차원과 모델 revision이 기록됐고, revision이 달라져도 확인용 벡터가 같으면 캐시를 재사용했다.

- 초기 Red 14건은 DB 모드, 검증, 메타데이터 또는 내보내기 계약이 구현되기 전 실패했다. 추가 Red에서 평가 도구의 CSV 고정, 화면 기준일의 릴리스 고정, 빈 코퍼스 설정 거부를 확인한 뒤 수정했다.
- 활성 릴리스 없음, DB 없음, 낮은 스키마, 조문 내용 변조로 인한 복원 해시 불일치에서 모델 클라이언트를 만들기 전에 시작을 거부했다. 임베딩 메타데이터 쓰기 실패는 롤백하고 경고를 남겼으며 검색은 계속 동작했다.
- 활성 릴리스를 바꾸면 재시작한 앱에서 새 조문과 버전을 읽었다. 이전 앱의 검색, 화면 기준일, 피드백 버전·해시·릴리스 ID와 요청 로그의 릴리스 ID는 시작 시점의 코퍼스와 일치했다. 관리자 조문 인덱스도 같은 검색기에서 만들어졌다.
- `check_deploy`의 CSV 출력은 기준 커밋 `425f796`과 하위법령 꺼짐 20줄·켜짐 23줄이 일치했다. DB 모드에서는 릴리스 ID·데이터 버전·해시·조문 수와 조문·하위법령·매니페스트 검사 결과를 확인했다. `export-release`는 파일 네 개의 바이트 일치, 동일 파일 건너뛰기, 다른 내용의 보호, 명시적 교체와 이전·새 해시 출력을 확인했다.
- 새 대역 E2E에서 존재하지 않는 CSV 경로를 설정하고 로그인한 뒤 질문을 전송했다. 가짜 답변과 법률 카드 3개가 표시됐고, 요청 로그에서 활성 릴리스 ID를 확인했다.
- 리뷰 반영 Red는 활성 릴리스 누락과 복원 해시 불일치에서 배포 점검이 중단되는 경우 두 건, revision 조회에 일치하는 항목이 없을 때 `StopIteration`이 발생하는 경우 한 건에서 실패했다. 수정 후 배포 점검은 코퍼스 오류를 남기고 system·모델·리랭커·하위법령 설정·포트·가짜 모델 서버 점검을 계속했다. 일치하는 revision이 없는 경우에는 메타데이터에 `null`을 기록했다. CSV 모드의 점검 출력도 다시 대조했다.
