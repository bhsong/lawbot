SQLite 트랜잭션에서 이미지 행을 지우고 `secure_delete`, WAL 체크포인트, `VACUUM`, 재체크포인트를 적용했다. 이미지 테이블을 제외한 모든 테이블의 행 수와 해시가 작업 전후에 일치했다. `quick_check`는 정상이고 외래 키 오류는 0건이다.

개발의 이미지 포함 복구본 1개와 SQLite 보조 파일 2개는 앞선 정리에서 제거했다. 두 레포의 캘린더 DB와 백업·복구 파일·WAL·SHM을 다시 검사해 대비표 이미지 행과 PNG 헤더가 0건임을 확인했다. 정리한 운영 원본으로 `calendar.db.clean-20261113.backup`을 만들었다. 파일 권한은 `600`이고, 원본과 백업의 보존 데이터 및 무결성이 일치한다. 작업용 사본과 임시 스크립트를 정리했다.

운영 로컬 입법예고 상세가 HTTP 200을 반환하고 공식 원문·PDF 링크가 표시됐다. 이전 이미지 조회는 HTTP 404였다. 운영 코드·스케줄·서비스는 변경하지 않았다. 다음 정기 수집에서 이미지 생성이 중단되는 상태는 PR #130 운영 반영 후 확인한다.
