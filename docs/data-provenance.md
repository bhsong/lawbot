# 조문 데이터의 출처·시점 추적

Lawbot이 근거로 쓰는 근로기준법 조문 데이터에서 무엇을 확인할 수 있고 무엇을 확인할 수 없는지, 그리고 검색 결과와 답변에 출처를 어떻게 연결하는지 정리합니다. 이 기능은 답변의 법적 정확성이나 최신성을 보장하지 않습니다. 데이터의 출처와 시점을 드러내고, 확인할 수 없는 부분을 확인된 것처럼 보이지 않게 하는 것이 목적입니다.

## 1. 현재 데이터

| 항목 | 상태 | 근거 |
| --- | --- | --- |
| 데이터 파일 | `data/labor_articles_20261001.csv` (132행, 색인 130개) | 저장소 |
| 열 | `article_id, title, chapter, deleted, starter, text` | 파일 |
| 법령명 | 근로기준법 | README, 파일 내용 |
| 기준일 | 2026-10-01 | 파일 이름과 README에만 기록. 이 날짜에 원본에서 받았다는 기록은 없음 |
| 저장소에 추가된 날 | 2026-10-18 (커밋 `18e956b`) | Git 기록 |
| 원 출처·수집 방법 | **기록 없음** | 수집·가공 스크립트가 저장소에 없음 |
| 법률 번호, 공포일, 시행일 | **기록 없음** | 데이터에 해당 열이 없음 |
| 개정 이력(과거 버전 본문) | **없음** | 기준일 한 시점의 본문만 있음 |
| 항별 개정 표시 | 있음: `<개정 …>`, `<신설 …>`, `삭제 <…>` 날짜 179개 (최근 2026.2.19) | 조문 본문 |
| 실효 표시 | 있음: `[실효: …]` 3개 | 조문 본문 |

주의할 점:

- 본문의 `<개정 2018.3.20>` 같은 날짜는 그 항을 바꾼 개정의 표시일입니다(국가법령정보센터 표기에서는 보통 개정 법률의 공포일). **시행일이 아니며**, 이 데이터로는 각 개정의 시행일을 알 수 없습니다.
- **제53조 ③·⑥**(30명 미만 사업장의 8시간 추가 연장근로)에는 `[실효: … 2022.12.31.까지 유효]` 표시가 있지만 조문 전체가 색인되어 검색·프롬프트에 그대로 들어갑니다. 프롬프트는 학습 형식과 같아야 해서(`test_prompt_matches_training_format`) 본문을 바꾸지 않고, 근거 패널에서 실효 표시를 알립니다.
- `deleted=1`인 2개 중 제35조는 삭제, **제16조는 실효**(2007.6.30.까지 유효)입니다. 둘 다 색인에서 빠지므로 동작은 같지만 `deleted` 열이 삭제와 실효를 구별하지 않습니다.

## 2. 메타데이터 파일

조문 CSV 옆에 `<CSV 이름>.meta.json`을 둡니다(`data/labor_articles_20261001.meta.json`). 저장소에서 확인한 값만 적고, 모르는 값은 `null`로 둡니다.

| 키 | 값 | 설명 |
| --- | --- | --- |
| `law_name` | `"근로기준법"` | |
| `sha256` | CSV 파일의 SHA-256 | 메타데이터가 이 파일을 설명한다는 확인용 |
| `as_of` | `"2026-10-01"` | 기준일 (`as_of_basis`에 근거) |
| `source` | `null` | 원 출처. 확인되면 채움 |
| `law_number`, `promulgated`, `effective` | `null` | 이 스냅샷이 반영한 법령 버전의 법률 번호·공포일·시행일 |
| `amendment_history` | `null` | 개정 이력은 확보하지 않음 |

`lawbot.lawdata.load_articles`가 CSV를 읽을 때:

- **데이터 검증**: 필수 열, `deleted` 값(0/1), 조문 번호 형식(`제N조`, `제N조의M`)과 중복, 색인 대상 조문의 빈 제목·본문을 검사하고, 문제가 있으면 모델을 불러오기 전에 `DataError`로 멈춥니다.
- **메타데이터 확인**: 메타데이터가 없거나, 읽을 수 없거나, `sha256`이 실제 파일과 다르면 기록 값(기준일·법령명 등)을 **쓰지 않고** `Snapshot.issues`에 사유를 남깁니다. 날짜 형식이 틀린 필드도 버립니다. 메타데이터 문제로 앱이 멈추지는 않지만, 시작 로그와 근거 패널에 "출처·기준일 확인 불가"로 표시됩니다.

## 3. 검색 결과와 답변의 연결

- **검색 결과**: `Retriever.search`의 각 결과에 `meta`가 붙습니다. 법령명, 조문 번호·제목, 데이터 파일과 해시, 기준일, 출처, 조문 본문 해시(`content_sha256`, 16자리), 항별 개정 표시(`marks`)와 최근 표시일(`last_marked`), 실효 표시(`expiry_notes`)입니다. `(law_name, article_id, content_sha256)`이 조문 버전을 구별합니다. 조문 본문이 바뀐 새 데이터로 바꾸면 같은 조문 번호라도 해시가 달라집니다.
- **색인 기록**: 색인은 실행할 때마다 메모리에 새로 만듭니다. `Retriever.index_info`에 데이터 파일·해시·조문 수·임베딩 모델·생성 시각을 남기고, 앱 시작 로그에 한 줄로 출력합니다.
- **답변 인용 대조**: 생성이 끝나면 답변 【근거 조문】의 조문 번호(`refusal.cited_articles`)를 검색 결과와 비교합니다(`service.trace_citations`). 근거 패널 맨 위에 인용한 조문을 표시하고, 검색 결과에 없는 조문(지어낸 번호, 다른 법 조문 등)을 인용하면 "검색 결과에 없는 조문 인용"으로 알립니다. 거절 답변(`해당 없음 …`)은 인용으로 보지 않습니다.

## 4. 최신성·시점 안내

근거 패널 첫 줄에 출처(법령명, 데이터 파일, 기준일, 원 출처 미기록)를 한 줄로 표시합니다. 그 밖의 안내는 아래 경우에만 붙입니다(`lawdata.time_notes`). 답변 본문과 프롬프트는 바꾸지 않습니다.

| 상황 | 안내 |
| --- | --- |
| 메타데이터 없음·해시 불일치 | 출처·기준일을 확인할 수 없다는 안내와 사유 |
| 기준일이 기록되지 않음 | 기준일 미기록 |
| 기준일이 `STALE_DAYS`(180일)보다 오래됨 | 그 뒤 개정 여부를 확인하지 않았다는 안내 |
| 질문에 연도(`2019년`)나 `개정 전` 표현이 있음 | 기준일 한 시점의 조문뿐이라 그 시점에 적용되는 조문인지 확인할 수 없다는 안내. 검색 조문에 그 해 이후 개정 표시가 있으면 조문별로 알림 |
| 검색 조문 본문에 실효 표시가 있음 | 실효 표시 내용을 그대로 인용 |

평가 650문항에는 연도·개정 전 표현이 없어 정답 조문을 줄 때 안내가 붙는 경우는 실효 표시가 있는 제53조뿐입니다(`tests/test_lawdata.py`).

## 5. 데이터를 갱신할 때

자동 수집·갱신 기능은 없습니다. 조문 데이터를 바꿀 때는 다음 순서를 따릅니다.

1. 새 CSV를 `data/labor_articles_<기준일>.csv`로 추가합니다(기존 파일은 평가 기준이므로 덮어쓰지 않음).
2. 같은 이름의 `.meta.json`을 만들고 출처·기준일, 확인한 경우 법률 번호·공포일·시행일을 적습니다. 확인하지 못한 값은 `null`로 둡니다.
3. `uv run python -m lawbot.lawdata data/labor_articles_<기준일>.csv`로 검증합니다. 해시를 출력하므로 메타데이터의 `sha256`에 넣고 다시 실행해 종료 코드 0을 확인합니다.
4. `paths.ARTICLES`를 바꾸고 평가를 다시 돌립니다. 학습·평가 데이터(`labor_eval_keywords.csv`의 `oracle_prompt` 등)는 기존 본문 기준이므로 테스트가 차이를 알려 줍니다.

## 6. 남은 한계

- 원 출처, 법률 번호, 공포일, 시행일을 모릅니다. 근거 패널은 이를 "미기록"으로 표시할 뿐 채우지 않습니다.
- 기준일 한 시점의 본문만 있어 과거·미래 시점 질문에 맞는 조문을 고를 수 없습니다. 안내만 합니다.
- 기준일 이후 개정 여부를 확인하지 않습니다. 외부 법령 서비스와 대조하는 기능은 없습니다.
- 질문의 시점 감지는 `YYYY년`과 `개정 전/이전`만 봅니다. "작년", "예전에" 같은 표현은 감지하지 않습니다.
- 인용 대조는 조문 번호만 봅니다. 다른 법의 같은 번호(예: 근로자퇴직급여 보장법 제34조)는 검색 결과의 근로기준법 제34조와 구별하지 못합니다. 인용이 맞더라도 답변 내용이 조문과 일치하는지는 확인하지 않습니다.
- 평가 결과 파일(`results/`)과 `metrics.csv`에는 어떤 데이터 해시로 평가했는지 기록하지 않습니다.
